## 1. 架构结论

采用**粗粒度微服务**：

```text
Client → Nginx（TLS / 静态资源 / auth_request）
           ↓
Java 业务（M1/M2/M3/M4/M5/M6/M7，模块化单体；M4 评测记录 / 状态在 Java，执行在 Python）
  ├─ PostgreSQL（业务系统记录）
  ├─ 对象存储（录像 / 关键帧）
  ├─ MQ（M4 评测任务）
  └─ Python AI 服务（LLM / OCR / ASR / Vision，无状态）
        └─ Python 评测 worker（M4，无状态）
```

- **Java 是业务状态与系统记录的唯一持有者**：账号、组织、课程、题库、课堂 session、任务、提交件、录制元数据、训练、教师评分、最终分、统计。
- **Python 是 AI 能力层**：LLM、OCR、ASR、视觉、音频特征、关键帧、M4 评测流水线；不持有业务状态、不写 Java 业务表、不算最终分。
- Java 业务先做一个模块化单体，不按 M1—M7 拆成独立服务；后续需要时再按边界拆。
- Python 一套代码，两个进程：同步 AI API + 异步评测 worker；两个进程都无状态。

### 3.3 云模型选型

| 能力 | 选型 | 用途 / 约束 |
|---|---|---|
| 文本 LLM | DeepSeek `deepseek-flash`（V4.1 Flash） | 虚拟学生问答、教师话语分类；课堂关闭 thinking，分类用 JSON 输出 |
| 实时 ASR | 阿里云 `paraformer-realtime-v2`（WebSocket） | 教师语音转写；16 kHz 单声道 PCM |
| 批量 ASR | 阿里云 `paraformer-v2` | M4 对录像做批量转写 |
| OCR | 阿里云 `qwen3.5-ocr`，回退 `qwen-vl-ocr` | 共享窗口截图；返回文字、框、置信度 |
| 视觉 | DeepSeek `deepseek-flash` 原生图片输入 | 关键帧 / 图表页；M3 只做 OCR，M4 使用视觉 |
| TTS | 不做 | 虚拟学生只用文字 |

- 组合 A：DeepSeek + 阿里云；LLM / 视觉一个 key，ASR / OCR 一个 key。
- 所有厂商通过 Python `providers/` 适配；超时、限流、降级和 `model_version` 由能力层统一封装。
- 云 API 不可用时：ASR / OCR 标记 partial，LLM 使用兜底文本或 Mock；不阻断录制。

## 4. Python 无状态规则

1. **不持有业务数据库**：不写 Java 的业务表；可以使用只读配置 / prompt 文件。
2. **不持有 session 状态**：课堂 session、WebSocket 连接、任务状态都在 Java。
3. **请求自带上下文**：每个请求 / 任务携带 `request_id` / `job_id`、输入 URL、配置快照、必要文本。
4. **结果通过响应或回调返回**：同步接口直接返回 JSON；异步任务通过 HTTP 回调交给 Java，不使用结果队列。
5. **流式 ASR / LLM 只有连接级临时状态**：连接关闭即释放，不持久化；控制 WS 断线进入 30 秒 grace，感知 WS 断线只影响 ASR / OCR，录制继续。
6. **派生文件写对象存储**：转写、OCR 帧、关键帧可写对象存储，返回 URL；业务元数据由 Java 记录。
7. **幂等**：Java 用 `evaluation_id` / `submission_id` 去重；Python 只记录请求 ID，不保存结果缓存。
8. **配置外置**：模型名、prompt 版本、限流、超时从环境变量 / 配置文件读取；响应返回 `model_version` / `prompt_version`。
9. **日志脱敏**：业务表保存课堂文本流；日志不落录音 / 转写全文。
10. **可水平扩展**：任意实例可处理任意请求，不做 sticky session。

## 5. 关键流程

### 5.1 M3 虚拟学生内容（同步）

1. Java 课堂状态机触发“学生提问”或“学生回答”。
2. Java 调 Python `/v1/classroom/question` 或 `/v1/classroom/answer`，带上近期转写、OCR 文本、学生参数、课题。
3. Python 调 DeepSeek，返回文本 / 质量档标签。
4. Java 写入事件日志、推送 WebSocket、更新课堂状态。

### 5.2 M3 实时 ASR / OCR

1. Java 持有课堂 session 与 WebSocket。
2. 音频流 / 屏幕帧由 Java 或前端送到 Python；Python 做流式 ASR / OCR。
3. Python 返回中间 / 最终转写、OCR 文本与置信度；Java 写入事件 / 统一文本流 / OCR 表。
4. 控制 WS 断线：30 秒 grace 内允许重连；超时或页面刷新 / 录制器丢失则 session 失败。感知 WS 断线只影响 ASR / OCR，录制继续，M4 标记受影响维度 partial。

### 5.3 M4 异步评测

1. Java 创建评测任务，状态 `pending`，写 `evaluations` + `evaluation_jobs` + `input_snapshots`，只把 ID 与引用投递 MQ。
2. Java 投递 MQ。
3. Python worker 消费任务，通过内部 manifest / 分页接口拉取 M3 已落库的 final 文本、OCR 帧、事件与录像 URL；计算音频特征、关键帧视觉 / LLM；不重跑实时 ASR。
4. Python 回调 Java `/internal/evaluations/{evaluation_id}/start`、`/result` / `/fail`，带 `job_id + attempt` 幂等键。
5. Java 持久化维度分 / 问题 / 建议，按维度权重计算 AI 总分，更新 `completed / partial / failed` 与 `evaluation_jobs`。
6. M7 通过 `EvaluationTerminalEvent` 读取 Java 的 AI 结果 + 教师评分，计算最终分。

### 5.4 M7 教师评测

- 全部在 Java：任务 / 提交件、AI 结果、教师评分、权重、最终分、统计、排行榜、CSV 导出。
- 不调用 Python。

## 7. 接口与协议

- **Gateway**：对外只暴露 Java 业务 API；`/api/**` 路由到 Java；WebSocket 也由 Java 持有。
- **Java → Python 同步**：REST / JSON；用于 M3 内容生成、教师话语分类、单张 OCR、ASR 短请求。
- **Java → Python 流式**：WebSocket / SSE；用于实时 ASR、流式 LLM。
- **Java → Python 异步**：MQ 投递任务；Python 通过 HTTP 回调 Java，不使用结果队列。
- **认证**：Nginx `auth_request` 预校验；Java 使用 Spring Security 7.1 + OAuth2 Resource Server 再次验 JWT，并在自定义 `AuthorizationManager` 中按 `api_permissions` 做 URL 级权限；service 层做资源级权限；Python 只接受内部服务 token / mTLS，不直接暴露给前端。
- **幂等**：`evaluation_id` / `submission_id` / `request_id`。
- **错误**：统一错误码、超时、重试、熔断；Python 返回结构化错误，Java 决定任务状态。

### 7.1 服务发现、配置与服务调用

课程演示采用固定拓扑，不需要 Eureka / Nacos / Consul / Apollo / Istio。

| 能力 | 本轮方案 | 何时再引入 |
|---|---|---|
| 服务发现 | Docker Compose 服务名 DNS + Nginx upstream | 多节点动态扩缩容 / K8s |
| 配置中心 | `.env` + Spring `application-*.yml` + Python pydantic-settings | 多环境动态配置 / 多团队 |
| 服务注册 | 不需要 | 实例动态上下线 |
| 服务调用 | REST / JSON（Java RestClient / WebClient，Python httpx）；M4 用 Redis Streams；流式用 WebSocket | gRPC 仅在性能需要时 |
| 网关 | Nginx | 已确认 |
| 熔断 / 重试 | Resilience4j + httpx 重试 | 服务数量增多 |
| 链路追踪 | trace id / OpenTelemetry（P1） | 多服务排障 |
| 服务网格 | 不需要 | 大规模 K8s / 多团队 |

- Docker Compose 的服务名就是静态服务发现：`java-app`、`python-ai-api`、`python-ai-worker`、`redis`、`minio`；Nginx upstream 使用 `java-app:8080`。
- Nginx upstream 就是 Java 的负载均衡；3 个课堂单实例足够。
- 健康检查：Java Actuator `/actuator/health`、Python `/health`、Docker `healthcheck`。
- 配置通过环境变量注入：`DATABASE_URL`、`JAVA_BASE_URL`、`PYTHON_AI_BASE_URL`、`REDIS_URL`、`MINIO_ENDPOINT` 等。
- 服务调用：同步用 REST / JSON；异步用 Redis Streams；流式用 WebSocket；不需要 Dubbo。

## 8. 部署

Docker Compose 起步：

```text
nginx
java-app
python-ai-api
python-ai-worker
postgres
redis
minio
```

- Nginx 负责 TLS、Vue 静态资源、`/api` 与 `/ws` 路由，并通过 `auth_request` 调 Java `/internal/auth/verify`。
- Redis 同时承载 M4 评测 Stream 与少量缓存。
- MinIO 负责录像、关键帧和派生文件，浏览器使用预签名 URL 直传，避免 Java 代理大文件；材料 / 屏幕截图走 Java multipart，Nginx 按路由设置 `client_max_body_size`（材料 25 MB、截图 5 MB）；MinIO 使用 HTTPS 子域，避免混合内容。
- Java 迁移用 Flyway / Liquibase；Python 无业务数据库迁移。
- 环境变量统一：`DATABASE_URL`、`JWT_SECRET`、`DEEPSEEK_API_KEY`、`OCR_*`、`ASR_*`、`REDIS_URL`、`MINIO_ENDPOINT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`。
- 健康检查 / 就绪检查；日志带 trace id。

### 8.1 演示容量目标：3 个并发虚拟课堂

- 目标：3 个课堂同时进行，每课堂默认 3 名虚拟学生；若配置到 30 名，需限制提问 / 回答频率或使用内容池。
- 每个课堂 2 条 WebSocket（控制 + 感知）、3 路录制（摄像头 / 屏幕 / 麦克风）；服务器不做实时转码，浏览器编码、MinIO 存储。
- Nginx：3 条 WebSocket + API 请求，`auth_request` 开销可忽略；WebSocket 超时调大。
- Java：3 个 session、事件写入与录制元数据，单实例足够；预留 1 GB 堆。
- Python：3 路流式 ASR、低频 OCR、按需 LLM 调用；建议使用云 ASR / OCR，避免单机 CPU 峰值。
- Redis Streams：3 个评测任务，consumer group + ack + pending 重试即可。
- MinIO：单机；按每课堂 3 路、20 分钟估算约 0.5—1 GB / 课堂，3 个课堂约 1.5—3 GB。
- 建议演示机：4 vCPU / 8 GB 起步，16 GB 更稳；录像放本地 SSD。
- 目标延迟（待实测）：ASR 中间结果 < 1 s，LLM 首 token < 2 s，单帧 OCR < 2 s，WebSocket 事件 < 200 ms，M4 单份评测 < 90 s。
- 验收：3 个课堂同时运行 20 分钟，无 WebSocket 掉线、录制上传完整、M4 评测全部完成。

## 10. 风险

1. **两套运行时**：部署、日志、链路、联调成本增加；需要契约与健康检查。
2. **M3 有状态**：WebSocket、session、录制留在 Java；Python 只做能力调用，避免状态分裂。
3. **M4 异步**：消息丢失、重复消费、回调失败；需要幂等、重试、死信。
4. **模型 / 供应商不稳定**：DeepSeek、OCR、ASR 的超时、限流、成本；Python 侧做适配与降级。
5. **数据一致性**：Java 是唯一系统记录；Python 不直接写业务表，避免双写。
6. **演示资源**：容器多、启动慢；课程演示优先减少组件。
7. **视觉能力**：`deepseek-flash` 已支持原生图片输入；M3 OCR 仍优先 Qwen-OCR，M4 关键帧理解可用 DeepSeek flash，但需校验结构化输出并保留降级。

## 11. 演示路径

1. 学生登录 → 选课 → 试讲 → 提交 → AI 报告。
2. 教师登录 → 创建任务 / 选题 → 查看提交 → 教师评分 → 统计 / 导出。
3. 微服务演示点：
   - 同步：Java 调 Python 生成虚拟学生提问。
   - 异步：Java 投递 M4 评测 → Python worker → 回调 Java。
   - 跨服务数据：M7 读取 Java 的 M3/M4 结果，不直接查 Python。
