## 1. 结论

- 需求文档已经具备启动系统设计的业务输入：角色、权限、FR、业务规则、异常与验收点齐全，M1—M7 的模块边界基本清晰。
- 但还不能直接写一份完整的系统设计：跨模块数据模型、API / WebSocket 协议、异步任务、录制与存储、非功能需求、部署与测试策略尚未形成统一设计输入。
- 建议顺序：先写总体设计、数据模型、API 与实时协议，再按模块写设计文档；M3（课堂与录制）和 M4（AI 评测）是风险最高的设计对象。
- 旧设计文档（`docs/superpowers/specs/2026-09-14-*`、`2026-09-15-*`）基于早期 MVP，范围与当前需求不一致，只作历史参考，不作为当前设计依据。

### 1.1 已确认架构（2026-11-02）

```text
Client → Nginx（TLS / 静态资源 / auth_request）
           ↓
Java 业务（M1/M2/M3/M5/M6/M7）
  ├─ PostgreSQL（业务系统记录）
  ├─ MinIO（录像 / 关键帧）
  ├─ Redis Streams（M4 评测任务）
  └─ Python AI 服务（LLM / OCR / ASR / Vision，无状态）
        └─ Python 评测 worker（M4，无状态）
```

- Java 是业务状态与系统记录的唯一持有者。
- Python 不持有业务状态、不写 Java 业务表、不计算最终分。
- 这是粗粒度服务化：网关 + Java 业务 + Python AI / 评测；暂不按 M1—M7 拆成独立微服务。

## 3. 必须先定的设计决策

| 编号 | 决策 | 当前建议 | 影响 |
|---|---|---|---|
| D1 | 架构形态 | 已确认：Nginx + `auth_request` 网关 + Java 业务（M1/M2/M3/M5/M6/M7，模块化单体）+ Python AI / 评测（无状态）；Java 持有业务状态，Python 只做 AI 与媒体处理 | 部署、事务、联调成本 |
| D2 | 异步任务 | Redis Streams + consumer group + Python worker；Java 记录任务状态，Python 无状态执行 | M4 重试、M3 分析、可靠性 |
| D3 | 录制与存储 | Java 负责录制生命周期、元数据与保留期；MinIO 预签名上传 / 下载；Python 只读处理，不持有业务状态 | 三路录制、回放、保留期 |
| D4 | 实时协议 | WebSocket 由 Java 持有；Python 只提供流式 ASR / LLM 的临时连接；控制 WS 断线 30 秒 grace + 重连快照；页面刷新 / 录制器丢失 / Java 重启不恢复 | 课堂状态机与评测时间基准 |
| D5 | AI / OCR / ASR | 统一适配层；DeepSeek `deepseek-flash` 负责文本与关键帧视觉；阿里云 Paraformer 实时 ASR + Qwen-OCR；OCR / ASR 云服务可替换；限流、重试、成本上限 | M3 实时分析、M4 评测 |
| D6 | 多租户 | 所有业务表带 `school_id`；管理员与学校一对一；跨校一律拒绝 | 数据隔离与索引 |
| D7 | 身份认证 | JWT / JWS（HS256、2 小时、Bearer）；密码 / 邮箱验证码 / 微信扫码登录；Java Spring Security 7.1 + OAuth2 Resource Server；URL 级 `AuthorizationManager` + 资源级权限；WebSocket 握手用 ticket；不做 refresh | M1、M3、M7 |
| D8 | 非功能目标 | 已确认演示目标：3 个并发课堂、20 分钟；ASR < 1 s、LLM 首 token < 2 s、OCR < 2 s、M4 < 90 s；4 vCPU / 8 GB 起 | 容量、成本、部署 |
| D9 | 前端技术栈 | Vue 3 + Vite + Pinia + Vue Router；Element Plus + ECharts | 页面、录制、回放、图表 |
| D10 | 部署形态 | Docker Compose：Nginx + Java 业务 + Python AI（API / worker）+ PostgreSQL + Redis + MinIO；生产环境再评估 K8s | 启动、演示、运维 |

## 5. 模块设计模板

每份模块设计至少包含：

0. 模块状态：Owner、G1—G8 完成度、测试层级状态、最后更新与证据链接；口径见 [进度看板](../team/02-进度看板.md)。
1. 范围与 FR 映射：本设计覆盖哪些 `FR-Mx-yy`，哪些不做。
2. 依赖与边界：上游 / 下游模块、只读 / 写入关系。
3. 数据模型：表、字段、主外键、索引、状态枚举、软删除与迁移。
4. 接口：REST 端点、请求 / 响应 DTO、错误码、幂等键；WebSocket 消息与时序。
5. 状态机与时序：正常流程、异常流程、重试、超时、降级。
6. 权限与安全：角色、学校范围、课程老师组、资源级校验。
7. 非功能：性能、容量、并发、可观测性、成本。
8. 测试与验收：单元 / 集成 / 端到端；引用 FR 编号。
9. 开放问题：需要产品或架构确认的事项。
