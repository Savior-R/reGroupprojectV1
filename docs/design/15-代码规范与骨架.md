## 2. Java 代码规范

> 版本基线：Java 21 LTS、Spring Boot 4.1.x（基线 4.1.2）、Spring Security 7.1、Hibernate 7.4、Jackson 3、Jakarta EE 11。Boot 4 的 Security DSL、Jackson 3、Jakarta 包名与 `@MockitoBean` 等差异按本节执行。

### 2.1 命名

| 对象 | 规范 | 示例 |
|---|---|---|
| 包 | 小写 | `m3classroom.application` |
| 类 | PascalCase | `TaskPublishService` |
| 接口 | 名词 / 能力 | `TaskRepository`、`ObjectStoragePort` |
| 方法 | 动词 | `publishTask`、`recomputeFinalScore` |
| 常量 | UPPER_SNAKE | `MAX_VIRTUAL_STUDENTS` |
| DTO | `XxxCommand` / `XxxQuery` / `XxxView` | `CreateTaskCommand` |
| Controller | `XxxController` | `TaskController` |
| Application | `XxxApplicationService` | `TaskApplicationService` |
| Domain | 领域名，无后缀 | `Task`、`Evaluation` |
| Repository | `XxxRepository` | `TaskRepository` |
| Port | `XxxPort` | `ObjectStoragePort` |
| Adapter | `XxxAdapter` | `MinioObjectStorageAdapter` |
| 事件 | 过去式 + `Event` | `TaskPublishedEvent` |

### 2.2 依赖方向

```text
api → application → domain ← infrastructure
```

- `domain` 不 import Spring / JPA / HTTP / Jackson。
- `application` 不 import Controller DTO。
- `infrastructure` 实现 `domain` / `application` 的端口。
- 跨模块只调用 application 接口或订阅集成事件；禁止注入对方 Repository。
- ArchUnit 测试必须校验以上规则。

### 2.3 类设计

- 优先 `record` 表示命令、查询、DTO、值对象。
- 不用 Lombok；手写构造函数 / record / getter，避免隐式行为。
- 构造器注入，不用字段注入。
- Domain 类不暴露 setter；状态变化通过方法。
- 聚合不持有另一个聚合实体，只持有 ID / 快照。
- Application service 方法是一个用例；不要做“万能 Service”。
- 查询服务返回 Query DTO；不返回聚合。

### 2.4 方法

- 方法只做一件事；超过约 40 行考虑拆分。
- 参数不超过 4 个；超过用 Command / Query 对象。
- 返回值显式；不返回 `null` 集合，用空集合。
- 不用 `Optional` 作为字段 / 参数；可用于 Repository 查询返回。
- 受检异常不用；业务异常用 `DomainException`。
- Controller 方法不写 try/catch；全局异常处理。

### 2.5 事务

- `@Transactional` 只放 application service。
- 事务内不做 HTTP / MQ / 文件上传；after-commit 再做。
- 事务边界与 14 的“事务边界”表一致。
- 乐观锁：`version` 条件更新；冲突 409。
- 悲观锁：发布 / 配置 / 清空按任务行 `FOR UPDATE`。

### 2.6 异常与错误码

```java
public class DomainException extends RuntimeException {
    private final ErrorCode code;
    private final Map<String, Object> details;
}
```

- 错误码来自 02，不新造字符串。
- Controller 不捕获异常；`GlobalExceptionHandler` 统一映射。
- 日志只记录 `code` / `trace_id` / 关键 ID；不记录密码、JWT、全文。

### 2.7 DTO / JSON

- Jackson 全局 `SNAKE_CASE`；Java 字段 camelCase，JSON 输出 snake_case。
- 请求 DTO 用 `record` + Jakarta Validation。
- 响应用 `View` record；不返回 JPA entity。
- 时间统一 `Instant`，JSON ISO-8601 UTC。
- 分数字段用 `BigDecimal` / `Score`，不用 `double`。

### 2.8 安全

- Spring Security 7.1；`/api/**` stateless JWT；`/internal/**` service token。
- 不在 Controller 写 `@PreAuthorize`；URL 权限由 `AuthorizationManager`。
- 资源级权限在 application service。
- `CurrentUser` 从 `Jwt` 解析；不读全局静态。
- 管理员不能访问 M3/M4/M6/M7 业务；训练 owner-only。

### 2.9 持久化

- 核心聚合：domain + JPA entity + mapper。
- 简单 CRUD：JPA entity 可直接在 infrastructure 使用。
- 读模型：JdbcTemplate + Query DTO。
- JSONB 用 `JsonNode` / 专用 record；不把大对象放大字段。
- 不写数据库触发器 / 存储过程。

### 2.10 事件

- 领域事件：模块内；集成事件：跨模块。
- `ApplicationEventPublisher` + `@TransactionalEventListener(AFTER_COMMIT)`。
- 事件只带 ID / 状态 / 时间；不带聚合 / 大文本。
- 监听器幂等；reconciler 兜底。
- 事件名过去式；payload record。

### 2.11 日志与可观测

- SLF4J；参数化日志；不字符串拼接。
- 关键日志字段：`trace_id`、`account_id`、`session_id`、`evaluation_id`、`job_id`。
- 不打印密码、token、预签名 URL、转写全文。
- 指标：Micrometer；关键计数 / 延迟。

### 2.12 测试

- 单元：JUnit 5 + AssertJ；domain 规则 / 计算。
- 集成：Spring Boot Test + Testcontainers PostgreSQL。
- Web：MockMvc；安全用例。
- ArchUnit：模块边界。
- 不 mock 领域对象；mock 端口 / 外部服务。

## 4. Python 规范与骨架

### 4.1 规范

- Python 3.12；Ruff + mypy / pyright；行宽 100。
- 所有函数类型注解；禁止裸 `except`、`import *`。
- Pydantic 做请求 / 响应 / 评测结果 schema。
- Provider / capabilities / worker 分层；provider 不依赖业务。
- 不连业务库；只读预签名 URL / Java 内部输入。
- 外部调用必须有 timeout / retry / 结构化错误。
- 日志脱敏：不打印密钥、全文、预签名 URL。

### 4.2 骨架

```text
ai/
├─ app/
│  ├─ main.py
│  ├─ config.py
│  ├─ api/ (llm, ocr, asr, vision, classroom, evaluation)
│  ├─ providers/ (base, deepseek, ocr_cloud, asr_cloud, mock)
│  ├─ capabilities/ (llm_gateway, ocr_gateway, asr_gateway, vision_gateway,
│  │                  classroom_content, evaluation, media)
│  ├─ prompts/
│  ├─ schemas/
│  ├─ worker/ (main, consumer, input_client, callback)
│  └─ observability/
└─ tests/
```

- 新增厂商只改 `providers/`。
- 新增评测维度只改 `capabilities/evaluation/` + prompt + Java registry。
- worker 不写 DB；只拉输入、跑 prompt、回调。

## 5. 前端规范与骨架

- Vue 3 + TypeScript + Vite + Pinia + Vue Router + Element Plus + ECharts。
- MVVM 分层：`views` / `viewmodels` / `models` / `services` / `stores`。
- 页面 ViewModel 用 composable；Pinia 只放 auth / ui。
- 组件不直接 fetch；不计算总分 / 权重 / 最终分。
- API DTO 与 02 `snake_case` 对齐；ViewModel 用 camelCase；mapper 显式转换。
- WS 事件运行时校验；未知事件忽略并记录。
- 录制 / 回放只在 Chromium E2E。

## 6. 代码生成规则

1. 一次只生成一个模块或一个垂直切片。
2. 先生成接口 / record / 空实现，编译通过后再填逻辑。
3. 不跨模块 import `domain` / `infrastructure`；只 import application 接口。
4. 不修改 02 / 12 / 14 的字段名 / 方法签名；需要改先回写文档。
5. 每个 public 方法有明确 Command / Query / View；不用 `Map` 当 DTO。
6. 每个模块至少：
   - 一个 domain 单测；
   - 一个 application 集成测试；
   - 一个权限用例；
   - 一个契约 fixture；
   - 一个对应 E2E 场景（见 [10](10-测试与验收.md) 7.7）。
7. 生成后必须跑：`./gradlew test`、lint、ArchUnit；本环境没有 JDK / Gradle，需在开发机验证。

## 7. 完成定义

- 代码编译通过；单元 / 集成 / 契约 / E2E 测试按 [10 测试与验收](10-测试与验收.md) 分层通过。
- 模块依赖符合 ArchUnit。
- API 响应符合 02；错误码一致。
- 数据库迁移可重复执行；Flyway validate 通过。
- 权限 / 资源级校验有测试。
- 日志无敏感信息。
- 文档中的类 / 方法签名与代码一致；如需偏离，先改设计。
