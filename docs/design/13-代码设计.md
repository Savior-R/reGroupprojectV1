## 1. 结论与取舍

### 1.1 三个问题的结论

| 问题 | 结论 |
|---|---|
| Java 是否使用 DDD | **可以，但采用“DDD-lite + 模块化单体”**：按 M1—M7 划分 bounded context，核心域用聚合 / 值对象 / 领域服务；M1/M2/M5 的 CRUD 不强行战术 DDD；不做全量事件溯源。代码演示不是重点，采用 DDD-lite 的目的是**可扩展、可拆分、可讲清边界**，不是为了展示 DDD 纯度 |
| 前端是否使用 MVVM | **可以，但采用“MVVM 分层 + 单向数据流”**：View（Vue SFC）/ ViewModel（composable）/ Model（DTO + 领域类型）；Pinia 只放跨页面状态；不把 `v-model` 绑到全局 store |
| Python 负责范围 | **厂商适配层 + 高级能力封装 + 无状态评测 worker**：LLM / OCR / ASR / Vision、音频特征、关键帧、M4 维度评测编排；不持有业务状态、不写业务库、不算最终分 |

### 1.2 为什么不是“全量 DDD / 经典 MVVM / Python 全包”

- 全量 DDD（每表聚合、领域与持久化完全分离、事件溯源）对课程项目过重，代码量和调试成本会压过收益；但完全不分层又会让 M3/M4/M7 的规则散在 Controller / SQL 里，后续扩展困难。DDD-lite 是折中。
- 经典 MVVM 的双向绑定容易让状态来源不清；Vue 3 更适合“ViewModel composable + 显式 action + 单向数据流”。
- Python 若只做厂商适配，M4 的 prompt 编排、音频 / 关键帧处理会被迫塞回 Java，反而更重；让 Python 做“无状态能力层 + worker”，Java 保留业务状态，是边界最清晰的方案。

### 1.3 核心原则

1. **Java 是业务状态权威**：任务、session、评测状态、权重、最终分、权限都在 Java。
2. **Python 是能力层**：输入上下文 / 媒体，输出结构化结果；不持久化业务状态。
3. **前端是展示与交互层**：不计算分数、不推断课堂状态、不保存答案要点。
4. **跨模块只通过 application 接口 / 集成事件**：不跨模块直接访问 Repository。
5. **契约优先**：02 / 06 / 12 的 DTO、错误码、表结构是代码边界；实现不得私自定义字段。
6. **扩展点只放在易变轴**：模式、评测维度、AI 厂商、评分模式、训练档位、存储；不为“以后可能变”给每个类加抽象。

### 1.4 运行版本基线

- Java 21 LTS；Spring Boot 4.1.x（基线 4.1.2）；Spring Framework 7；Spring Security 7.1；Hibernate 7.4；Jackson 3；Jakarta EE 11。
- 新项目不使用已结束 OSS 支持的 Spring Boot 3.5；Boot 4 的 Security DSL、Jackson 3、Jakarta 包名和测试注解差异按 15 的规范处理。

## 2. Java：DDD-lite 模块化单体

### 2.1 适用性判断

| 模块 | 领域复杂度 | 采用程度 |
|---|---|---|
| M1 账号 / 组织 | 中低，规则多但流程 CRUD | 轻量领域模型 + application service |
| M2 课程 | 中，状态矩阵 / 成员关系 | 领域服务 + 聚合 |
| M3 课堂 / 录制 | 高，状态机 / 实时 / 媒体 | 完整战术 DDD + Actor |
| M4 评测 | 高，异步 / 部分成功 / 可复现 | 聚合 + 领域服务 + 端口 |
| M5 题库 | 低，CRUD + 种子 | 轻量领域模型 |
| M6 训练 | 中，模板 / 记录 / 隐私 | 聚合 + 策略 |
| M7 评分 / 统计 | 高，最终分 / 并发 / 统计 | 聚合 + 计算服务 + 读模型 |

- **核心域**：M3、M4、M7 用完整聚合、值对象、领域服务、领域事件。
- **支撑域**：M1、M2、M5、M6 用“领域模型 + application service”，不强行 repository 接口 / 领域事件全套。
- **读模型**：统计、名单、排行榜、报告查询用 `JdbcTemplate` / SQL 查询服务，不经过聚合。

### 2.2 Bounded Context

```text
com.shijiangtai
├─ shared/                 # 共享内核：ID、Score、Clock、错误、分页、当前用户
├─ m1auth/                 # 账号、学校、组织、权限
├─ m2course/               # 课程、老师组、学生成员
├─ m3classroom/            # 任务、session、课堂、录制、回放
├─ m4eval/                 # 评测记录、维度、问题、异步 job
├─ m5question/             # 题库
├─ m6training/             # 训练模板、训练记录
├─ m7teacher/              # 评分、最终分、统计、导出
└─ integration/            # 跨模块事件订阅 / 发布适配
```

依赖方向：

```text
api → application → domain ← infrastructure
```

- `domain` 不依赖 Spring / JPA / HTTP / Redis。
- `application` 编排用例、事务、权限、事件；可以依赖 `domain` 和端口接口。
- `infrastructure` 实现端口（JPA、MinIO、Redis、Python HTTP、邮件等）。
- `api` 只做 DTO / 参数校验 / 调用 application；不写业务规则。
- 跨模块只能调用对方的 `application` 接口或订阅集成事件；不能注入对方 Repository。

### 2.3 分层职责

| 层 | 内容 | 禁止 |
|---|---|---|
| `api` | Controller、WebSocket Handler、DTO、参数校验、错误映射 | 业务规则、事务、直接 Repository |
| `application` | Use case、事务边界、权限、编排、事件发布 | 复杂领域计算、SQL |
| `domain` | 聚合、实体、值对象、领域服务、领域事件、Repository 接口 | Spring / JPA / HTTP 注解 |
| `infrastructure` | JPA Repository、JdbcTemplate 查询、MinIO、Redis、Python Client | 业务决策 |

### 2.4 聚合与值对象

| Context | 聚合根 | 聚合内 | 说明 |
|---|---|---|---|
| M1 | `Account` | 账号类型、学校、角色档案 | 账号类型不可变 |
| M1 | `School` | 专业、班级 | 组织维护；导入是 application 流程 |
| M2 | `Course` | 课程专业、老师组、学生成员 | 成员量大时作为独立聚合 / 查询模型 |
| M3 | `Task` | 虚拟学生配置、题目快照、权重 | 发布后不可变 |
| M3 | `SessionActor` | 课堂状态、虚拟学生运行时、对话 | 内存 Actor，不是 JPA 实体 |
| M3 | `Submission` | 提交件、班级快照 | 一次提交 |
| M3 | `Recording` | 三路 stream 状态 | 上传生命周期 |
| M4 | `Evaluation` | 维度分、问题、输入快照 | 状态 / 总分 / partial |
| M4 | `EvaluationJob` | 队列状态、attempt | 与 Evaluation 同事务更新 |
| M5 | `QuestionBank` / `Question` | 类别、题目 | 题库按学校 |
| M6 | `TrainingTemplate` | 模板快照 | 发布 / 下架 |
| M6 | `TrainingRecord` | 选中记录、到期 | 每模板最多 3 条 |
| M7 | `GradingConfig` | 权重、模式、锁定 | 每任务一条 |
| M7 | `TeacherScore` | 维度分 / 总分 / 评语 / version | 乐观锁 |
| M7 | `FinalScore` | 最终分 / 状态 / 快照 | 派生结果 |

值对象（示例）：

- `AccountId`、`SchoolId`、`CourseId`、`TaskId`、`SessionId`、`EvaluationId`
- `Score`（0—100，一位小数）、`Weight`（0—100）、`Confidence`（0—1）
- `DurationMs`、`DurationSeconds`
- `RubricWeights`（校验和 100）
- `ClassSnapshot`、`QuestionSnapshot`、`VirtualStudentConfig`
- `EvaluationStatus`、`FinalScoreStatus`

聚合规则：

- 聚合内强一致；跨聚合最终一致（事件 / 事务边界）。
- 聚合不直接持有另一个聚合的实体，只持有 ID / 快照。
- 聚合方法负责状态转移；application 不直接改字段。
- 读模型不经过聚合，避免为查询加载大对象。

### 2.5 领域服务

| 服务 | 职责 |
|---|---|
| `TaskPublishPolicy` | 模式、权重、材料、M5 题目、学生名单校验 |
| `TaskSnapshotFactory` | 生成不可变 `config_snapshot` |
| `SessionStateMachine` | session 生命周期与非法命令 |
| `ClassroomStateMachine` | lecturing / qa / ended，qa_phase |
| `VirtualStudentEngine` | 注意力、纪律、举手、回答、对话 |
| `InterviewStateMachine` | 题目展示、下一题、结束、超时 |
| `RecordingPolicy` | required_streams、retry、failed、cleanup |
| `EvaluationPolicy` | warnings / partial、适用维度、状态 |
| `EvaluationResultValidator` | 回调维度 / 分数 / 问题校验 |
| `FinalScoreCalculator` | AI / 教师权重、最终维度、状态优先级 |
| `TrainingRecordPolicy` | 3 条上限、到期、模板下架 |
| `GradingConfigPolicy` | 锁定、清空、版本冲突 |

- 领域服务无状态，输入领域对象 / 值对象，输出结果或领域事件。
- 不注入 Repository；需要读取时由 application 传入数据。

### 2.6 Application Service 与事务

| 用例 | 事务边界 |
|---|---|
| 建校 | `schools` + `school_admins` 同事务；提交后 `SchoolCreatedEvent` |
| 发布任务 | 锁任务行 → 校验 → 快照 → assignments → published |
| 提交试讲 | 同步 flush 上下文 → 校验 required streams → submission / session / event 同事务 → 提交后 M4/M7 |
| 开始 / 结束 session | 锁 session 行 / actor mailbox；状态转移 + 事件 |
| 评测回调 | evaluation + dimension_scores + issues + job 同事务 |
| 教师评分 | teacher_score 条件更新 + final_score 重算 |
| 配置修改 / 清空 | 任务级锁 + config / teacher_scores / final_scores |
| 训练选中 | record 创建 + session selected + 3 条上限 + M4 触发 |

- `@Transactional` 放在 application service，不放在 Controller / Repository。
- 领域事件用 `ApplicationEventPublisher`；跨模块用 `@TransactionalEventListener(AFTER_COMMIT)`。
- 事务内不发 HTTP / MQ；after-commit 再投递；失败由 reconciler 兜底。
- 乐观锁：`teacher_scores.version`、`config_version`；冲突映射 409。
- 悲观锁：发布 / 配置 / 清空按任务行 `SELECT ... FOR UPDATE`。

### 2.7 领域事件 vs 集成事件

| 类型 | 范围 | 例子 |
|---|---|---|
| 领域事件 | 模块内 | `TaskPublished`、`SessionEnded`、`SubmissionCreated` |
| 集成事件 | 跨模块 | `SchoolCreatedEvent`、`SubmissionCreatedEvent`、`EvaluationTerminalEvent`、`TrainingRecordSelectedEvent`、`CourseArchivedEvent`、`CourseTeacherRemovedEvent` |

- 集成事件放 `integration/events`，payload 用 record / DTO；不直接传聚合。
- after-commit 发布；监听器幂等；事件丢失由 reconciler 兜底。
- 本轮不引入 outbox；若后续可靠性要求提高，再加 outbox 表。

### 2.8 持久化策略

- **核心聚合**（Task、Evaluation、TeacherScore、FinalScore、TrainingRecord）：domain 模型 + infrastructure JPA entity + mapper；domain 不依赖 JPA。
- **简单 CRUD**（M1/M2/M5）：允许 infrastructure JPA entity 直接作为持久化模型，application 做 DTO 映射；不强行双模型。
- **读模型 / 统计**：`JdbcTemplate` + 专用 Query DTO；不加载聚合。
- **SessionActor**：内存领域对象，不映射 JPA；事件 / 文本 / 帧通过 `ContextPersistenceWriter` 落库。
- **批量重算**：M7 用一条 SQL / 批量 SQL，不逐条加载聚合。
- **JSONB**：快照、事件、配置用 JSONB；Java 用 Jackson `JsonNode` / 专用 record 映射。

Repository 规则：

- 核心聚合的 Repository 接口放 `domain`，实现放 `infrastructure`。
- 简单 CRUD 可直接用 Spring Data JPA Repository，但只在 application 内使用。
- 禁止 Controller 直接调用 Repository。
- 禁止跨模块 Repository。

### 2.9 M3 的 Actor 模型

- 每个 session 一个 `SessionActor` + 单线程 mailbox；命令串行。
- `SessionActor` 持有 `SessionContext`：事件、文本、帧、课堂状态、虚拟学生运行时。
- 领域服务：`ClassroomStateMachine`、`VirtualStudentEngine`、`InterviewStateMachine`。
- 事件先入有序持久化队列再推送；关键事件同步 flush。
- 控制 WS 断线 30 秒 grace；actor 存活期间可重连；Java 重启不恢复。
- Actor 不直接写 DB；通过 `ContextPersistenceWriter` / `SessionRepository` 端口。
- 录制 / 上传由 `RecordingApplicationService` 编排，不放进 Actor。

### 2.10 安全与权限

- Spring Security 7.1 + OAuth2 Resource Server；`/api/**` stateless JWT；`/internal/**` service token。
- URL 级 `AuthorizationManager` 查 `api_permissions`；最具体路径优先。
- 资源级权限在 application service：学校、课程老师组、学生本人、训练 owner-only。
- 不在 Controller 写 `@PreAuthorize`；权限码是唯一来源。
- `CurrentUser` 从 SecurityContext 读取；application 显式传入，不读全局静态。

### 2.12 反模式

- Controller 直接写 SQL / Repository。
- 跨模块注入对方 Repository。
- 聚合内调用 HTTP / MQ / 文件系统。
- 用 `@Transactional` 包住远程调用。
- 把 session 运行时状态写回 `sessions` / `virtual_students`。
- 用领域事件替代所有同步调用，导致调试困难。
- 为每个表建一个“聚合”，实际没有一致性边界。

### 2.13 扩展点设计

| 易变轴 | 扩展点 | 新增时改什么 |
|---|---|---|
| 课堂模式 | `TaskMode` + `ModePolicy` / `SessionModeHandler` | 新增枚举 + handler；不改 session 核心 |
| 评测维度 | Java `EvaluationDimensionRegistry` + Python `DimensionEvaluator` registry | 新增维度 key、权重、prompt、capability |
| AI 厂商 | `LLMProvider` / `OCRProvider` / `ASRProvider` / `VisionProvider` | 新增 adapter + 配置；不改 capabilities |
| 评分模式 | `FinalScorePolicy`（`dimension` / `total`） | 新增 policy；不改 M7 主流程 |
| 训练档位 | `TrainingLevelPolicy` | 新增档位策略 + 默认时长 / 权重 |
| 存储 | `ObjectStoragePort`（MinIO 适配） | 替换 adapter；不改录制 / 回放 |
| 账号类型 | DB 权限表 + `account_type` | 新增权限行 / 角色策略；不改认证链 |
| 事件消费 | 集成事件 + `@TransactionalEventListener` | 新增 listener；不改发布方 |
| 前端页面 | 路由 meta + ViewModel composable | 新增页面模块；不改 shell |

- 只为这些轴建接口；不要做通用插件系统 / 工作流引擎。
- 扩展点必须有默认实现和测试；新增实现不修改既有分支。
- 如果某个“扩展”需要改 3 个以上核心类，说明边界选错了。

## 3. 前端：MVVM 分层 + 单向数据流

### 3.1 适用性判断

Vue 3 的响应式 + 模板天然接近 MVVM，但“经典 MVVM”容易变成双向绑定到处飞。建议：

- View：页面 / 组件，只渲染与派发事件。
- ViewModel：composable，持有页面状态、校验、API / WS 调用、派生数据。
- Model：API DTO、领域类型、mapper。
- 全局只放 auth / ui；页面状态放 ViewModel。
- `v-model` 只用于表单控件的本地状态；不直接绑定 Pinia store 对象。
- 服务端状态单向流入 ViewModel，再流向 View。

### 3.2 分层

| 层 | 目录 | 职责 |
|---|---|---|
| View | `views/`、`components/` | 渲染、交互、无障碍；不 fetch、不计算业务 |
| ViewModel | `viewmodels/` | 页面状态、action、校验、轮询、WS reducer |
| Model | `models/` | DTO、领域类型、mapper、状态枚举 |
| Service | `services/` | API client、WS client、media/recorder、storage |
| Store | `stores/` | auth、ui；不承载页面业务 |

### 3.4 ViewModel 契约

```ts
export function useInterviewRoom(sessionId: string) {
  const state = reactive<InterviewRoomState>({...})
  const currentQuestion = computed(() => state.interview?.question ?? null)
  const remainingSeconds = computed(() => Math.ceil(state.remainingMs / 1000))

  async function start() { ... }
  function nextQuestion() { ... }
  function endInterview() { ... }
  function onWsEvent(event: WsEvent) { ... }

  return { state, currentQuestion, remainingSeconds, start, nextQuestion, endInterview }
}
```

规则：

- ViewModel 返回 `ref` / `reactive` / `computed` + 显式 action。
- ViewModel 不操作 DOM、不直接 `window` 媒体 API（通过 service）。
- 页面级 ViewModel 可以组合子 ViewModel（如 `useVirtualStudentEditor`）。
- 表单校验在 ViewModel；服务端 422 映射到字段。
- 轮询 / 定时器在 ViewModel 内，`onUnmounted` 清理。
- WS 事件 reducer 在 ViewModel；组件只消费状态。

### 3.5 状态归属

| 状态 | 归属 |
|---|---|
| token、me、permissions | `stores/auth` |
| 全局 toast / 抽屉 / loading | `stores/ui` |
| 任务草稿、自动保存 | `useTaskDraft` |
| 评分表格、批量保存 | `useTaskGrading` |
| 面试房间、倒计时、WS | `useInterviewRoom` |
| 回放同步 | `useReplayController` |
| 报告轮询、雷达数据 | `useEvaluationReport` |
| 训练记录 | `useTrainingRecords` |

- 不把页面数据塞 Pinia；避免“全局 store 变成第二个数据库”。
- 跨页面共享的只读字典（账号类型、状态文案）放 `models/constants`。

### 3.6 Model / DTO 映射

- API DTO 与 02 的 `snake_case` 对齐；不手写两套字段名。
- ViewModel 使用 camelCase 领域类型；`models/mappers` 显式转换。
- 金额 / 分数用 `number`，但前端不重新计算总分；展示 Java 返回值。
- 状态枚举集中 `models/domain/status.ts`；与后端字符串一致。
- WS 事件做运行时类型守卫；未知事件忽略并记录。

### 3.7 录制 / WS / 回放 ViewModel

| ViewModel | 职责 |
|---|---|
| `useDeviceCheck` | 摄像头 / 麦克风 / 屏幕共享权限、设备状态 |
| `useSessionRecorder` | 三路 MediaRecorder、5s timeslice、5MB part、上传状态 |
| `useInterviewRoom` | WS 连接、snapshot、题目、倒计时、下一题 / 结束、30s grace |
| `useReplayController` | 音频主时钟、三路同步、seek、漂移校正、事件跳转 |
| `useGradingTable` | 名单、筛选、行编辑、批量保存、版本冲突 |
| `useEvaluationReport` | 报告轮询、雷达 / 维度 / 建议、partial / failed 状态 |

### 3.8 组件规则

- `views` 页面只组合组件与 ViewModel。
- `components` 展示组件不 fetch、不读 store；props 进、emit 出。
- 表单组件 `v-model` 绑定本地 `ref`，不直接绑 store。
- 状态 badge / 文案用共享常量，不各页面重复。
- 空态 / 错误态 / 加载态由页面 ViewModel 统一提供。
- 页面级权限只做显示；最终以服务端 403 为准。

### 3.9 测试

- ViewModel 用 Vitest 单测：API mock、WS event fixture、计时器 fake。
- 展示组件用 Vue Test Utils：props / emit / 状态。
- 页面 E2E 用 Playwright：主流程 + 权限 + 空 / 错 / 加载。
- 录制 / 回放 E2E 只跑 Chromium；用 fake media / 固定 WebM。
- 不把业务计算放进组件测试；计算应在 Java。

### 3.10 反模式

- 组件直接 `axios.get`。
- `v-model` 直接绑 Pinia store。
- ViewModel 里操作 DOM / `document.querySelector`。
- 页面自行推断 session 状态 / 倒计时。
- 前端计算总分 / 权重 / 最终分。
- 把答案要点、参考材料放进 localStorage。

## 4. Python：适配层 + 能力层 + 无状态 worker

### 4.1 范围判断

| 能力 | Python 负责 | 理由 |
|---|---|---|
| LLM 厂商适配 | ✅ | DeepSeek / OpenAI 兼容 / 未来厂商 |
| LLM 高级封装 | ✅ | 重试、超时、限流、JSON schema、token、prompt 版本 |
| OCR 厂商适配 | ✅ | 云 OCR / PaddleOCR / mock |
| ASR 厂商适配 | ✅ | 流式 / 批量、音频格式、时间戳归一化 |
| 视觉 LLM 适配 | ✅ | 关键帧分析 |
| 音频特征 | ✅ | 解码、重采样、VAD、音量 / 停顿 / 语速 |
| 关键帧选择 / 预处理 | ✅ | 帧去重、缩放、编码 |
| M3 内容生成 / 分类 | ✅ | 虚拟学生问题 / 回答、教师话语分类 |
| M4 维度评测编排 | ✅ | prompt 链、并行维度、问题 / 建议生成；无状态 |
| M4 worker | ✅ | Redis Streams 消费、拉输入、回调 Java |
| Mock provider | ✅ | CI / demo 固定结果 |
| 业务状态 / DB | ❌ | Java 持有 |
| 任务 / session 状态 | ❌ | Java / SessionActor |
| 评测状态 / 权重 / 总分 | ❌ | Java |
| 最终分 / 统计 / 排行榜 | ❌ | M7 Java |
| 权限 / 资源校验 | ❌ | Java |
| 录像上传 / 回放 | ❌ | M3 Java + 浏览器 |
| 文档解析（PDF / DOCX） | ❌ | Java（PDFBox / POI） |
| M5 / M6 / M7 业务 | ❌ | Java |

**判断**：Python 的合理边界是“把外部模型 / 媒体处理封装成稳定能力”，以及“把一次评测的 prompt 编排做完”；它不拥有业务状态，也不做最终决策。

### 4.2 分层

```text
providers/      厂商适配：请求 / 响应 / 鉴权 / 流式 / 错误归一化
capabilities/   高级能力：重试、超时、JSON schema、prompt、并行、聚合
api/            FastAPI 同步 / 流式端点
worker/         Redis Streams 消费、拉输入、回调 Java
schemas/        Pydantic 请求 / 响应 / 评测结果
prompts/        版本化 prompt 模板
observability/  trace / token / 延迟 / 错误
```

依赖方向：

```text
api / worker → capabilities → providers
```

- `providers` 不知道业务；只做厂商协议。
- `capabilities` 不知道业务状态；输入上下文 / 媒体，输出结构化结果。
- `api` / `worker` 不写业务库；只调用 capabilities + HTTP 回调。
- `prompts` 只被 capabilities 读取；版本写入响应。

### 4.3 Provider 接口

```python
class LLMProvider(Protocol):
    async def chat(self, messages, model, timeout_s, **kwargs) -> LLMResponse: ...
    async def stream(self, messages, model, timeout_s, **kwargs) -> AsyncIterator[LLMChunk]: ...

class OCRProvider(Protocol):
    async def recognize(self, image_url: str, **kwargs) -> OCRResult: ...

class ASRProvider(Protocol):
    async def stream(self, audio: AsyncIterator[bytes], config: ASRConfig) -> AsyncIterator[ASRChunk]: ...
    async def transcribe(self, audio_url: str, config: ASRConfig) -> ASRResult: ...

class VisionProvider(Protocol):
    async def analyze(self, image_urls: list[str], prompt: str, **kwargs) -> VisionResult: ...
```

- `ProviderRegistry` 按配置选择实现；`MockProvider` 用于 CI / demo。
- 所有 provider 返回统一的 `model_version`、`usage`、`latency_ms`、`raw_error`。
- 不把厂商 SDK 类型泄漏到 capabilities。

### 4.4 Capability 层

| Capability | 输入 | 输出 |
|---|---|---|
| `LLMGateway` | messages / schema / model / prompt_version | JSON / text / usage / model_version |
| `OCRGateway` | image URL / bytes | text / boxes / confidence |
| `ASRGateway` | PCM stream / audio URL | partial / final / timestamps |
| `VisionGateway` | keyframe URLs + prompt | observations / confidence |
| `ClassroomContentCapability` | 上下文窗口 + 学生设定 | 问题 / 回答 / 分类 |
| `EvaluationCapability` | EvaluationContext + 维度 | 维度分 / 子项 / 问题 / 建议 |
| `MediaCapability` | 音频 / 帧 | 声学特征 / 关键帧 |

高级封装规则：

- 超时：LLM 30s、OCR 15s、ASR 连接级、视觉 30s。
- 重试：429 / 5xx / 超时最多 2 次；JSON 非法修复 1 次。
- 限流：全局 semaphore + provider 级 QPS。
- JSON：Pydantic / JSON Schema 校验；失败带错误信息修复。
- Token：记录 prompt / completion / 总成本；不把全文写日志。
- 版本：`model_version` / `prompt_version` / `rubric_version` 随响应返回。
- 降级：provider 不可用 → 结构化错误；不返回伪造分数。

### 4.5 M4 worker

```text
XREADGROUP evaluation:jobs
  → POST /internal/evaluations/{id}/start
  → GET input manifest / paged texts / frames / events
  → 构建 EvaluationContext
  → 并行调用适用维度 capabilities
  → 生成 3—5 条建议
  → POST /internal/evaluations/{id}/result（或 /fail）
  → XACK
```

- worker 无状态；临时文件 `/tmp/eval-{evaluation_id}`；结束删除。
- 不写业务库；不做最终状态判定；Java 校验 / 计算总分。
- 单 worker 并发 3；全局 LLM 并发 8；整份 90s。
- 失败：结果带已完成维度 + `partial_reasons`；Java 决定 `partial / failed`。
- 回调失败不 XACK；由 pending / 调度器重试。
- `idempotency`: 结果带 `job_id + attempt`；Java 幂等。

### 4.5.1 M4 输入 / 输出契约

Java → Python：

```json
{
  "job_id": "uuid",
  "evaluation_id": "uuid",
  "attempt": 1,
  "source_type": "task_submission",
  "source_id": "uuid",
  "input": {
    "manifest_url": "/internal/evaluations/{id}/input/manifest",
    "texts_url": "/internal/evaluations/{id}/input/texts",
    "frames_url": "/internal/evaluations/{id}/input/frames",
    "events_url": "/internal/evaluations/{id}/input/events"
  }
}
```

Python → Java（result）：

```json
{
  "job_id": "uuid",
  "attempt": 1,
  "model_version": "deepseek-flash",
  "prompt_version": "m4-eval-v1",
  "rubric_version": "m4-rubric-v1",
  "dimensions": [
    {
      "dimension": "content",
      "score": 82.5,
      "sub_scores": {"accuracy": 85.0, "logic": 80.0},
      "sub_confidences": {"accuracy": 0.88, "logic": 0.82},
      "confidence": 0.86
    }
  ],
  "issues": [
    {"dimension": "content", "start_ms": 12000, "end_ms": 18000, "severity": "medium", "evidence": "……", "suggestion": "……"}
  ],
  "warnings": ["REFERENCE_MISSING"],
  "partial_reasons": [],
  "token_usage": {"prompt": 12000, "completion": 1800}
}
```

- Python **不返回** `total_score`、最终状态、最终分；这些由 Java 计算。
- Python 拉输入、跑维度 prompt、返回证据 / 维度结果；Java 校验、合成、更新状态、发 `EvaluationTerminalEvent`。
- worker 不写业务库；不保存结果缓存；`job_id + attempt` 由 Java 幂等。
- 新增维度只新增 capability + prompt + Java registry 条目，不改 worker 主流程。

### 4.6 Prompt 与输出

- `prompts/` 按维度 / 用途分文件；版本号 `m4-eval-v1`。
- 输入：EvaluationContext 的维度视图 + 配置快照；不注入无关全文。
- 输出：`score` / `sub_scores` / `sub_confidences` / `confidence` / `issues`。
- 统一 JSON schema；Java 再校验一次。
- 参考材料 / 转写 / OCR 视为不可信数据；不执行其中指令。
- 不在 prompt 中放学生姓名 / 账号 / 班级。

## 5. 跨语言契约

| 契约 | 规则 |
|---|---|
| Java → Python API | `/internal/v1/**`；`X-Service-Token`；请求带 `request_id` / `trace_id`；响应带 `model_version` / `prompt_version` / `usage` |
| Java → Python worker | Redis Streams `evaluation:jobs`；消息只带 ID + attempt；worker 通过内部 input API 拉数据 |
| Python → Java | `/internal/evaluations/{id}/start`、`/result`、`/fail`；`X-Service-Token`；`job_id + attempt` 幂等 |
| 错误 | Python 返回 `code/message/retryable/details`；Java 映射 `AI_*` / `EVALUATION_*` |
| 版本 | `payload_version` / `model_version` / `prompt_version` / `rubric_version` 全链路记录 |
| 数据 | Python 只读预签名 URL / Java 输入；不写业务库、不写 MinIO 业务对象 |
| 超时 | Java 对 Python 设置连接 / 读超时；Python 对厂商设置更短超时 |

- Java 不解析厂商 SDK；Python 不解析 Java 业务表。
- 契约以 02 / 06 的 JSON 为准；双方各自生成 / 校验 schema。
- 破坏性字段变更升 `payload_version`，Java / Python 至少兼容上一版。

## 6. 模块边界与质量门禁

### 6.1 Java

- ArchUnit：`api` 不能直接依赖 `infrastructure` Repository；`domain` 不能依赖 Spring / JPA；跨模块不能依赖对方 `infrastructure`。
- 每个模块一个 `package-info.java` 说明边界。
- 领域服务单测覆盖状态机 / 计算 / 校验；application 集成测试用 Testcontainers。
- 禁止 `@Transactional` 在 Controller；禁止跨模块事务。
- 统一异常：`DomainException` → API 错误码；不把内部异常透出。

### 6.2 前端

- ESLint + vue-tsc；禁止 `any` 在 API 边界。
- ViewModel 单测；组件 emit / props 测试。
- 路由 meta 权限覆盖率检查。
- 不直接 fetch；统一 `apiClient`。
- 录制 / 回放只在 Chromium E2E。

### 6.3 Python

- Ruff + mypy / pyright；Pydantic schema；`pytest`。
- Provider / capability 分层用 import-linter 或目录约定检查。
- 禁止 `app.providers` 导入 `app.worker`；禁止 capabilities 访问 DB。
- 所有外部调用有 timeout / retry / 结构化错误。
- 日志脱敏：不打印全文 / 密钥 / 预签名 URL。
