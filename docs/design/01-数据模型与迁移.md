# 01 数据模型与迁移

> 上位文档：[需求规格说明书](../requirements/需求规格说明书.md)、[00 总体设计](00-总体设计.md)
> 详细 DDL：[12 数据库设计](12-数据库设计.md)
> 版本：V1.1（讨论稿）　状态：待评审　更新日期：2026-11-03
> 范围：M1—M7；M8 暂缓
> 数据库：PostgreSQL 16；单库 + 按模块分 schema；Java 是唯一业务写入方，Python 无业务数据库

## 1. 设计原则

1. **单库 + 按模块分 schema**：`m1_auth`、`m2_course`、`m3_classroom`、`m4_eval`、`m5_question`、`m6_training`、`m7_teacher`。
2. **UUID 主键**：优先 UUIDv7（`uuid-creator` 应用生成；不可用时回退 `UUID.randomUUID()`），Postgres 类型 `uuid`；API 对外使用 UUID 字符串。
3. **审计字段**：核心表统一 `created_at`、`updated_at`；需要归属的表加 `created_by`、`updated_by`；时间统一 `timestamptz`，UTC。
4. **状态字段**：`varchar + check`，不使用 Postgres enum，便于后续迁移。
5. **软删除**：用 `status`；活跃关系用部分唯一索引保证唯一。
6. **JSONB 边界**：快照、事件、配置、评估子项用 JSONB；课程、任务、提交件、评分等核心关系用普通表。
7. **跨 schema 外键**：本轮保留，保证单体阶段的数据完整性；未来拆服务时改为 ID / 事件引用。
8. **Java 写入**：Java 业务是唯一写入方；Python 只读对象存储、返回 AI 结果，不写业务表。
9. **迁移**：Flyway，forward-only；迁移脚本按模块拆分；演示数据独立 profile。

## 3. M1 账号与组织

### 3.1 表结构

| 表 | 关键字段 | 约束 / 索引 | 说明 |
|---|---|---|---|
| `schools` | `id`、`name`、`created_at`、`updated_at` | `UNIQUE(name)` | 学校；不冗余管理员字段 |
| `account_types` | `id`、`code`、`name`、`status`、`created_at`、`updated_at` | `UNIQUE(code)`；seed：student / teacher / admin | 账号类型 |
| `accounts` | `id`、`username`、`password_hash`、`account_type_id`、`school_id`、`created_at`、`updated_at` | `UNIQUE(username)`；索引 `(school_id, account_type_id)`；`account_type_id` FK | 账号；学生 / 教师用 `school_id`，管理员学校归属看 `school_admins` |
| `school_admins` | `id`、`school_id`、`account_id`、`is_owner`、`status`、`joined_at`、`created_at`、`updated_at` | `UNIQUE(account_id) WHERE status='active'`；`UNIQUE(school_id) WHERE status='active'`（MVP 一校一管理员）；索引 `school_id` | 管理员与学校多对一预留；后期去掉 `school_id` 唯一约束即可支持多管理员 |
| `majors` | `id`、`school_id`、`name`、`status`、`created_at`、`updated_at` | `UNIQUE(school_id, name)`；索引 `(school_id, status)` | 专业；停用不删除 |
| `classes` | `id`、`school_id`、`major_id`、`grade`、`name`、`status`、`created_at`、`updated_at` | `UNIQUE(major_id, grade, name)`；索引 `(school_id, major_id, status)` | 班级；停用不删除 |
| `student_profiles` | `account_id`、`class_id`、`created_at`、`updated_at` | PK `account_id`；索引 `class_id` | 学生档案；班级带出年级 / 专业 |
| `teacher_profiles` | `account_id`、`created_at`、`updated_at` | PK `account_id` | 教师档案；学校在 `accounts.school_id` |
| `teacher_majors` | `id`、`account_id`、`major_id`、`status`、`effective_from`、`effective_to`、`created_at`、`updated_at` | 部分唯一 `(account_id, major_id) WHERE status='active'`；索引 `account_id`、`major_id` | 教师专业范围；变更保留历史 |
| `api_permissions` | `id`、`code`、`name`、`module`、`protocol`、`method`、`path_pattern`、`description`、`status`、`created_at`、`updated_at` | `UNIQUE(code)`；`UNIQUE(protocol, method, path_pattern)`；索引 `(module, status)` | 接口权限目录；seed 只读 |
| `account_type_permissions` | `account_type_id`、`permission_id`、`created_at` | PK `(account_type_id, permission_id)`；索引 `permission_id` | 账号类型 → 接口权限 |

### 3.2 关键约束

- 管理员首任建校：插入 `school_admins`，`is_owner=true`；MVP 的 `school_id` 部分唯一索引保证一校一管理员。
- 后期多对一：删除 `UNIQUE(school_id) WHERE status='active'`，新增邀请码 / 添加管理员流程；`accounts` 不需要改。
- 学生、教师必须绑定学校；管理员可以是未绑定状态（`accounts.school_id` 为空，且没有 active 的 `school_admins` 行）。
- 管理员学校范围从 `school_admins` 解析；JWT 里的 `school_id` 由登录 / 建校响应时的关系计算。
- 教师专业范围变更：旧行 `status='inactive'`，写 `effective_to`；新行 active。
- `api_permissions` / `account_type_permissions` 由迁移 seed，运行时不提供管理界面；默认拒绝，公开接口白名单。
- 资源级权限不靠这两张表，仍在 service 层校验。

- 课程名称自由文本；年级 / 类型由名称约定，不结构化拆字段。
- 老师组至少一名有效教师由 service 保证；数据库不做跨行约束。

## 5. M3 课堂与录制

| 表 | 关键字段 | 约束 / 索引 | 说明 |
|---|---|---|---|
| `tasks` | `id`、`course_id`、`mode`、`topic`、`textbook_version`、`reference_material`、`scenario_config`、`duration_recommended_seconds`、`duration_max_seconds`、`rubric_weights`、`question_config`、`config_snapshot`、`config_version`、`status`、`created_by`、`published_at`、`closed_at`、`created_at`、`updated_at` | 索引 `(course_id, status)`、`created_by`；`mode` free / scenario / interview；`status` draft / published / closed | 试讲任务；发布时写配置快照 |

| `virtual_students` | `id`、`task_id`、`name`、`avatar`、`personality_text`、`activity`、`question_rate`、`ability`、`attention_baseline`、`discipline_probability`、`seat_no`、`sort_order`、`created_at` | 索引 `task_id`；五个参数 check 0—1 | 任务虚拟学生**静态配置**；发布后锁定；`attention / hand_raise_energy / cooldown / state` 等运行时状态只在 `SessionActor` 内存 |
| `sessions` | `id`、`session_type`、`task_id`、`course_id`、`student_account_id`、`mode`、`status`、`attempt_no`、`started_at`、`ended_at`、`duration_ms`、`stream_offsets`、`created_at`、`updated_at` | 索引 `(student_account_id, status)`、`task_id`、`course_id`、`session_type`；`session_type` task / training；`mode` free / scenario / interview | 任务 / 训练共用；训练 `task_id` 为空；运行时课堂 / 虚拟学生动态状态只在内存，不落本表 |
| `submissions` | `id`、`task_id`、`student_account_id`、`session_id`、`class_id_snapshot`、`submitted_at`、`status` | `UNIQUE(task_id, student_account_id)`；`UNIQUE(session_id)`；索引 `task_id`、`student_account_id` | 每个学生每任务一条提交；班级快照供 M7 |
| `recordings` | `id`、`session_id`、`duration_ms`、`status`、`created_at`、`updated_at` | `UNIQUE(session_id)`；索引 `status`；`status` recording / uploading / uploaded / failed / deleted | 一次录制的汇总 |
| `recording_streams` | `id`、`recording_id`、`stream_type`、`upload_id`、`object_key`、`part_size`、`parts_uploaded`、`bytes_uploaded`、`duration_ms`、`offset_ms`、`mime`、`status`、`created_at`、`updated_at` | `UNIQUE(recording_id, stream_type)`；索引 `recording_id`、`status`；`stream_type` camera / screen / audio；`status` uploading / uploaded / failed / deleted | 三路流独立 multipart 上传、状态、偏移 |
| `session_texts` | `id`、`session_id`、`speaker_type`、`speaker_ref`、`source`、`kind`、`text`、`start_ms`、`end_ms`、`at_ms`、`confidence`、`model_version`、`prompt_version`、`status`、`created_at` | 索引 `(session_id, at_ms)`、`(session_id, speaker_type)`、`(session_id, kind)`；`speaker_type` teacher / student / examiner / candidate；`source` asr / llm / manual；`kind` utterance / question / answer / follow_up | 统一文本流：教师 ASR、学生 LLM、结构化面试考官 / 考生 |
| `frames` | `id`、`session_id`、`timestamp_ms`、`text`、`bounding_boxes`、`confidence`、`change_score`、`frame_type`、`object_key`、`content_hash`、`status`、`error_message`、`created_at`、`updated_at` | 索引 `(session_id, timestamp_ms)`、`(session_id, frame_type)`、`(session_id, status)`；`frame_type` normal / slide_change / final / low_confidence / chart；`status` pending / processed / failed | 屏幕变化流；OCR pending → processed / failed；提交前必须完成或失败 |
| `events` | `id`、`session_id`、`seq`、`type`、`timestamp_ms`、`actor`、`target`、`payload`、`created_at` | `UNIQUE(session_id, seq)`；索引 `(session_id, timestamp_ms)`、`(session_id, type)` | 课堂事件唯一桥梁；payload JSONB |

- `sessions.status`：`preparing` / `in_progress` / `ended` / `reviewing` / `submitted` / `selected` / `evaluated` / `cancelled` / `failed`；任务与训练按 M3 / M6 规则使用。
- `sessions` 部分唯一索引：`UNIQUE(task_id, student_account_id) WHERE status IN ('preparing','in_progress')`；同一学生同一任务同时只有一个活跃 session；训练 `task_id` 为空，不受影响。
- `sessions` 训练部分唯一索引：`UNIQUE(student_account_id) WHERE session_type='training' AND status IN ('preparing','in_progress')`；同一学生同时只有一个活跃训练 session。
- **运行时状态不落库**：课堂宏观状态、`qa_phase`、面试当前题 / `answer_id`、虚拟学生 `attention / hand_raise_energy / cooldown / state` 都在 `SessionActor` 内存；30 秒 grace 依赖 actor 存活，Java 重启则不恢复。`sessions` 只存生命周期、时间、`stream_offsets` 与业务状态。
- `tasks.reference_material` JSONB：`{material_id, filename, object_key, mime, size, parsed_text, char_count, parse_status}`；自由 / 情景发布时复制进 `config_snapshot`。
- `tasks.question_config` JSONB：`{question_ids, total_duration_seconds}`；草稿只存 ID、顺序与时长，发布时读取 M5 生成题目快照。
- `tasks.config_snapshot` 发布后不可变；`config_version` 草稿为 0、发布为 1。
- 任务配置时长（`duration_recommended_seconds` / `duration_max_seconds` / `total_duration_seconds`）由教师按分钟输入，保留秒；session 时间线、录制 `offset_ms` / `duration_ms`、事件 / 文本 / M4 / M7 时间点统一毫秒。对外 DTO 使用 `duration_ms`。
- `task_assignments.status`：`assigned` / `submitted`；学生提交时更新。
- 录制对象键：任务 `recordings/{school_id}/task/{task_id}/{session_id}/{stream_type}.webm`；训练 `recordings/{school_id}/training/{session_id}/{stream_type}.webm`。MinIO bucket 按环境区分。材料对象键：`materials/{school_id}/{course_id}/{task_id}/{material_id}.{ext}`；训练材料 `training-materials/{school_id}/{student_account_id}/{material_id}.{ext}`。
- 教师 ASR 按语义段一行；学生 LLM 按一条问题 / 回答 / 追问一行；不按字或 token 拆。
- `session_texts.speaker_ref`：课堂学生为 `virtual_student_id`；结构化面试考官为 `question_id`、考生为 `answer_id`；教师行为空。
- 事件通过 `text_id` 引用文本，不重复存全文；结构化面试考官 / 考生也使用同一张表。`student.question / answer / follow_up` 只带 `text_id`，不内嵌全文；如需 UI 预览，用短 `text_preview` 且不作为权威数据。
- `frames` 是课堂上下文的屏幕变化流；只保存变化帧 / 关键帧，不保存每秒所有帧；`content_hash` 用于去重。
- `sessions` 不存训练字段；M6 的模板、档位、有效配置放 `m6.training_session_meta`。
- 面试 `answer_id` 是事件派生键：`interview.question_shown` / `answer_started` / `answer_ended` + `session_texts.speaker_ref` 构成题目 / 回答映射，本轮不建独立题目 / 回答表；M4 按 `answer_id` 聚合文本。

## 6. M4 AI 评测

| 表 | 关键字段 | 约束 / 索引 | 说明 |
|---|---|---|---|
| `evaluations` | `id`、`source_type`、`source_id`、`submission_id`、`training_record_id`、`session_id`、`task_id`、`course_id`、`student_account_id`、`mode`、`status`、`total_score`、`weights`、`task_config_version`、`training_config_version`、`model_version`、`prompt_version`、`rubric_version`、`attempt_count`、`warnings`、`partial_reasons`、`error_code`、`error_message`、`token_usage`、`started_at`、`created_at`、`completed_at`、`updated_at` | `UNIQUE(source_type, source_id)`；索引 `(student_account_id, status)`、`submission_id`、`training_record_id`；`status` pending / running / completed / failed / partial；CHECK：`source_type` 与 `submission_id` / `training_record_id` 恰好一个匹配 | 一次评测；重试更新同一条；总分由 Java 写入；`warnings` 与 `partial_reasons` 分离 |
| `dimension_scores` | `id`、`evaluation_id`、`dimension`、`score`、`sub_scores`、`sub_confidences`、`confidence`、`created_at` | `UNIQUE(evaluation_id, dimension)` | 维度分；`sub_scores` / `sub_confidences` JSONB |
| `issues` | `id`、`evaluation_id`、`dimension`、`start_ms`、`end_ms`、`severity`、`evidence`、`suggestion`、`is_suggestion`、`suggestion_rank`、`sort_order`、`created_at` | 索引 `(evaluation_id, dimension)`、`(evaluation_id, start_ms)`、`(evaluation_id, is_suggestion, suggestion_rank)`；`severity` high / medium / low | 问题定位与建议；`is_suggestion` 标记报告 3—5 条建议，`suggestion_rank` 排序 |
| `input_snapshots` | `evaluation_id`、`source_type`、`source_id`、`submission_id`、`training_record_id`、`recording_ids`、`text_ids`、`frame_ids`、`event_ids`、`config_version`、`task_config_version`、`training_config_version`、`flags`、`created_at` | PK `evaluation_id` | 输入快照，保证可复现；`text_ids` 指向统一文本流；`flags` JSONB 记录完整性；快照不可变 |
| `evaluation_jobs` | `id`、`evaluation_id`、`status`、`attempts`、`last_error`、`next_retry_at`、`created_at`、`updated_at` | `UNIQUE(evaluation_id)`；索引 `(status, next_retry_at)`；`status` queued / running / completed / failed / partial | Java 侧任务状态；Redis Streams 只做消息通道 |

- `source_type`：`task_submission` / `training_record`；`source_id` 分别指向 submission / training_record。
- `total_score` 是 AI 总分，只在 `completed` 时有值；最终分在 M7 计算。
- `weights` 是 AI 维度权重；`model_version` / `prompt_version` / `rubric_version` 记录可复现信息。
- `warnings` 是 JSONB 数组，如 `["REFERENCE_MISSING","CONTEXT_TRUNCATED"]`，只降低置信度，不改变 `completed`；`partial_reasons` 只放缺失适用维度 / 必需输入，如 `["FRAMES_MISSING","DIMENSION_TIMEOUT"]`。
- `error_code` / `error_message` 记录失败原因；`token_usage` 记录 prompt / completion token。
- `input_snapshots.flags` 记录文本 / 音频 / 帧 / 事件 / 参考材料 / 答案要点完整性，以及 `context_truncated`；运行期警告写 `evaluations.warnings`，不回写快照。
- `evaluation_jobs` 的重试策略：Java 扫描 `queued` / `next_retry_at`，重新投递 Redis Streams；Python worker 消费后回调 Java；result 事务内同步更新 job 状态。

## 7. M5 题库

| 表 | 关键字段 | 约束 / 索引 | 说明 |
|---|---|---|---|
| `libraries` | `id`、`school_id`、`seed_version`、`created_at`、`updated_at` | `UNIQUE(school_id)` | 每校一个题库 |
| `categories` | `id`、`school_id`、`name`、`sort_order`、`status`、`created_by`、`updated_by`、`created_at`、`updated_at` | `UNIQUE(school_id, name)`；索引 `(school_id, status, sort_order)` | 类别；停用不删除 |

- 内置种子题库放 `backend/src/main/resources/seed/question-bank.json`，由 Java 建校时复制；不写死在 SQL 迁移里。

## 8. M6 训练

| 表 | 关键字段 | 约束 / 索引 | 说明 |
|---|---|---|---|
| `training_templates` | `id`、`source_task_id`、`source_task_config_version`、`course_id`、`training_level`、`classroom_mode`、`config_snapshot`、`created_by`、`status`、`published_at`、`unpublished_at`、`created_at`、`updated_at` | `UNIQUE(source_task_id, course_id, training_level) WHERE status='published'`；索引 `(course_id, status)`、`source_task_id`；`training_level` progressive / mock_exam；`status` published / unpublished | 教师训练模板；来自已发布 / 已关闭自由试讲任务；同源任务 + 课程 + 档位只允许一个已发布模板 |
| `training_session_meta` | `session_id`、`template_id`、`training_level`、`effective_config_snapshot`、`created_at` | PK `session_id`；索引 `template_id` | 复用 M3 session 的训练元数据 |
| `training_records` | `id`、`training_session_id`、`student_account_id`、`template_id`、`selected_at`、`expires_at`、`status`、`deleted_at`、`created_at`、`updated_at` | `UNIQUE(training_session_id)`；索引 `(student_account_id, template_id, expires_at)`、`(expires_at, status)`；`status` selected / evaluated / deleted / expired | 学生选中的训练记录；每模板最多 3 条由 service 保证；评测通过 `evaluations.training_record_id` 查询，不双写 `evaluation_id` |

- 训练 session 在 `m3.sessions` 中 `session_type='training'`、`task_id=null`；目标课程可空。
- `sessions` 部分唯一索引：`UNIQUE(student_account_id) WHERE session_type='training' AND status IN ('preparing','in_progress')`；同一学生同时只有一个活跃训练 session。
- 未选中的训练录像沿用 M3 临时录像清理规则；TrainingRecord 自 `selected_at` 起保留 1 个月。
- 自由训练 `template_id=null`，按 `(student_account_id, template_id=null)` 分组限制 3 条。

- 自由训练材料对象键：`training-materials/{school_id}/{student_account_id}/{material_id}.{ext}`；未使用 24 小时清理，使用后随 session / record 清理。
- 训练评测以 `m4.evaluations.training_record_id` 为权威外键；`training_records` 不存 `evaluation_id`，API 通过评测表查询。
- `training_materials.created_by` 不适用；M5 种子的 `categories/questions.created_by/updated_by` 允许 NULL，前端显示“系统”。

## 9. M7 教师评测

| 表 | 关键字段 | 约束 / 索引 | 说明 |
|---|---|---|---|
| `task_grading_configs` | `id`、`task_id`、`course_id`、`ai_weight`、`teacher_weight`、`scoring_mode`、`config_version`、`locked_at`、`updated_by`、`created_at`、`updated_at` | `UNIQUE(task_id)`；check 两项 0—100 且和为 100；`scoring_mode` dimension / total | 每任务一条有效配置；首次教师评分后锁定 |
| `teacher_scores` | `id`、`submission_id`、`task_id`、`course_id`、`student_account_id`、`class_id_snapshot`、`scoring_mode`、`dimension_scores`、`teacher_total`、`comment`、`version`、`graded_by`、`graded_at`、`updated_at` | `UNIQUE(submission_id)`；索引 `(task_id, student_account_id)`、`course_id`；`version` 乐观锁 | 每提交件一条教师评分；老师组共享 |
| `final_scores` | `submission_id`、`task_id`、`course_id`、`student_account_id`、`ai_evaluation_id`、`teacher_score_id`、`ai_total`、`teacher_total`、`final_total`、`final_dimensions`、`status`、`class_id_snapshot`、`config_version`、`error_code`、`error_message`、`computed_at` | PK `submission_id`；索引 `(task_id, status)`、`(course_id, status)`、`(class_id_snapshot, status)`；`status` pending_ai / pending_teacher / completed / ai_partial / ai_failed | 最终分物化；配置 / AI / 教师分变化时重算 |

- 最终分由 Java 计算；Python 不参与。
- `final_scores` 只统计 `completed`；`final_total` / `final_dimensions` 仅 `completed` 非空；其他状态单独计数。
- `final_scores.status` 优先级：AI partial → AI failed / 数据异常 → AI pending / 缺失 → 教师缺失 → completed；权重为 0 的项不参与判定。
- 教师评分变更递增 `version`；保存时校验版本，冲突返回 409。
- `task_grading_configs` 首次教师评分后写 `locked_at`；清空该任务教师评分才解锁。
- `final_scores.error_code` / `error_message` 记录数据异常或计算失败；不伪造分数。
- `final_scores.class_id_snapshot` 优先取提交时快照，缺失时回退教师评分 / 最终分快照 / 当前班级；历史统计不随转班变化。
- `final_scores.teacher_score_id → teacher_scores.id ON DELETE SET NULL`；`ai_evaluation_id → evaluations.id ON DELETE SET NULL`；清空教师评分时同步置空并重算。
- `task_assignments` 增加发布时 `class_id_snapshot`，供未提交 / 进行中学生的班级筛选与名单展示。

## 12. 保留与清理

| 数据 | 保留期 | 清理方式 |
|---|---|---|
| M3 录像 / 文本 / 帧 / 事件 | 任务：课程结束 + 1 年；训练：1 个月；未设置 `end_at` 用归档时间 | 任务按 submission 根清理；训练按 TrainingRecord 根清理；先 MinIO 后 DB |
| M4 评测 / 维度分 / 问题 | 与 submission / training_record 同期 | 随 submission / training_record 级联 |
| M7 教师评分 / 最终分 | 与 submission 同期 | 随 submission 级联 |
| M6 TrainingRecord | 选中后 1 个月 | 到期删除记录、session、录像、评测 |
| M5 题库 | 随学校长期保留 | 停用不删除；学校删除时清理 |
| M1 / M2 | 长期保留 | 只归档 / 停用，不物理删除 |

- 清理任务由 Java 定时执行；先删 MinIO 对象，再删 DB 行，失败重试并记录日志。
- 直接物理删除前，保留期内的数据只做软删除 / 只读。
- `ON DELETE CASCADE` 只用于同一业务对象的从属表；跨模块业务对象由清理任务按顺序删除。
- **任务清理根**：`submission_id`。顺序：删除录像 / 关键帧 / 材料 MinIO 对象 → 删除 `submissions`（级联 M4 评测、M7 教师评分 / 最终分）→ 删除 `sessions`（级联录像、文本、帧、事件）→ 删除任务材料对象。`submissions.session_id` 不对 session 做级联删除，先删 submission 再删 session。
- **训练清理根**：`training_record_id`。顺序：删除录像 / 材料 MinIO 对象 → 删除 `training_records` → 删除对应 `evaluations`（`training_record_id`）→ 删除 `sessions`（级联录像、文本、帧、事件）。
- **临时未提交 attempt**：按 `ended_at + 24h` 或任务关闭后 24 小时（取较晚）清理；同时最多 5 个 attempt，超出按最旧清理；不依赖 submission 根。
- 清理任务不依赖“删 session 一把梭”；每一步可重试，失败记录 `ops.cleanup_jobs`（见 [12 数据库设计](12-数据库设计.md)）。
