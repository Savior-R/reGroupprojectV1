## 3. M1 系统设计

### 3.1 注册

#### 流程

1. 前端加载注册选项：学校、专业、年级、班级（公开接口）。
2. 用户先选择账号类型：学生 / 教师 / 管理员。
3. 按类型展示表单：
   - 学生：用户名、密码、学校、年级、专业 → 选择班级；
   - 教师：用户名、密码、学校、一个或多个专业；
   - 管理员：用户名、密码。
4. 提交前二次确认账号类型；提交后类型不可变更。
5. 注册成功：自动登录，返回 JWT；管理员未建校时 `school_id` 为空，前端跳建校页。（已确认）

#### 校验

- 账号类型必填、合法；`account_type_id` 写入后不再更新。
- 用户名平台唯一；即真实姓名；重名由用户自行加后缀。
- 密码 8—64 位；BCrypt 加密存储。
- 学生：班级必须属于所选学校 / 专业 / 年级；无匹配班级返回 `CLASS_NOT_MATCHED`；多个班级由前端选择。
- 教师：至少一个本校启用专业；专业已停用返回 `MAJOR_DISABLED`。
- 管理员：不绑定学校；注册后进入建校流程。
- 注册接口重复提交：用户名唯一约束兜底；前端按钮幂等。

#### 注册与登录

- 注册成功直接签发 JWT，减少一次登录；如产品要求回到登录页，可改为返回成功状态。
- 账号类型不可变更：不提供更新接口、不提供管理入口；选错类型只能重新注册。

### 3.2 登录与 JWT

- 用户名 + 密码登录（BCrypt）、邮箱验证码登录、微信扫码登录；三种方式成功都签发同一 JWT / JWS。
- 成功签发 JWT / JWS：
  - HS256；密钥来自环境变量；
  - Claims：`sub`（account_id）、`account_type`、`school_id`（可空）、`exp`、`iat`、`jti`；
  - 有效期 2 小时；无 refresh token；登出由客户端丢弃 token。
- 错误统一 `用户名或密码错误`，不暴露账号是否存在。
- 管理员未建校：`school_id` 为空，仅可访问建校相关接口。
- 建校成功：返回新 token，`school_id` 已写入；客户端替换旧 token，不要求重新登录。
- 登录 / 注册启用 Nginx `limit_req`（默认 5 次 / 分钟，burst 5）；失败统一提示，不区分账号是否存在。

### 3.2.1 邮箱验证码登录

- `accounts.email` 可空、平台内唯一（`lower(email)` 唯一索引）；写入前统一 `trim` + 小写；`email_verified_at` 为空不可用于登录。
- 发送：`POST /api/v1/auth/email/code`，统一 202；生成 6 位数字，HMAC-SHA256 后写入 `email_login_codes`，5 分钟有效，发送新码使旧码失效。
- 校验：`POST /api/v1/auth/login/email`；按邮箱查已绑定账号，校验哈希、过期、`consumed_at`、尝试次数；成功后标记 consumed 并签发 JWT。
- 限流：60 秒重发、邮箱 5 次 / 小时、IP 20 次 / 小时；错误统一 `UNAUTHORIZED`。
- 绑定 / 换绑 / 解绑：需登录 + 当前密码 + 邮箱验证码；换绑需验证新邮箱；解绑后不能再用邮箱登录。
- 邮件发送通过 `MailSender` 端口；dev / test 使用 Mock，不真实发信；发送失败返回 503，不改变账号。

### 3.2.2 微信开放平台扫码登录

```text
GET  /api/v1/auth/oauth/wechat/qr
  → {state, authorize_url, expires_at}
GET  /api/v1/auth/oauth/wechat/callback?code&state   # 微信回调，服务端处理
GET  /api/v1/auth/oauth/wechat/status?state
  → {status, ticket?}
POST /api/v1/auth/oauth/wechat/exchange {ticket} → JWT
```

- state 5 分钟、一次性；微信回调校验 state 后用 code 换 `openid` / `unionid`，token 不落库。
- 已绑定 `oauth_identities(provider='wechat', provider_user_id)` → 生成 `login_ticket`，前端 exchange 换 JWT。
- 未绑定 → 生成 `registration_ticket`，前端进入 `/register/oauth?ticket=...`。
- 微信返回昵称 / 头像只用于展示；不把微信 openid 直接当账号 ID。
- 回调 URL 必须在微信开放平台白名单；provider secret 只在服务端配置。

### 3.2.3 OAuth 引导注册与账号绑定

- 引导注册复用 FR-M1-01 的校验：账号类型、学校、专业 / 班级、用户名、密码；可同时设置邮箱。
- `POST /api/v1/auth/oauth/wechat/register {ticket, account_type, ...}`：在同一事务内创建账号、学生 / 教师 / 管理员档案（按现有注册流程）与 `oauth_identities`；失败整体回滚，ticket 不消耗。
- 绑定 / 解绑接口需登录；绑定微信需重新扫码拿 ticket，绑定邮箱需验证码；解绑需当前密码。
- 同一 `(provider, provider_user_id)` 只能绑定一个账号；一个账号同一 provider 只保留一条有效身份。
- 解绑最后一个登录方式：本轮账号必有密码（不支持清空），该场景不可达；若后续支持清空密码须拒绝。审计写入 `auth_login_events`（`event_type=unbind`）。
- 不做“按 OAuth 邮箱自动合并账号”；邮箱匹配只作为提示，必须用户登录后显式绑定。

### 3.3 Spring Security 集成

#### 依赖

```text
spring-boot-starter-security
spring-boot-starter-oauth2-resource-server
spring-security-oauth2-jose
spring-security-test
```

#### Filter Chain

1. `/internal/**`：
   - 单独 `SecurityFilterChain`，要求 `X-Internal-Token`；
   - 不经过 `api_permissions` 权限管理器；
   - `/internal/auth/verify` 由 Nginx 调用，控制器用 `JwtDecoder` 验证用户 JWT，返回身份头；
   - 其他内部接口（如 M4 回调）使用 service token。
2. `/api/**`：
   - `SessionCreationPolicy.STATELESS`；
   - `oauth2ResourceServer(jwt)` 校验 Bearer token；
   - 公开接口 `permitAll`：注册、密码 / 邮箱验证码登录、邮箱验证码发送、微信二维码 / 回调 / 状态 / exchange / 引导注册、注册选项、健康检查；邮箱 / 微信绑定、解绑不公开；
   - 其余请求交给自定义 `AuthorizationManager`。
3. 默认链路：`denyAll`；不启用 formLogin、httpBasic、CSRF。

#### 认证

- 登录 `/api/v1/auth/login` 使用 `AuthenticationManager` + `UserDetailsService`；
- `DaoAuthenticationProvider` + `BCryptPasswordEncoder(12)`；
- 登录成功由 `TokenService` 签发 JWT；注册成功也走同一签发逻辑；
- 邮箱验证码 / 微信 ticket 登录由 `EmailCodeService` / `OAuthLoginService` 校验后直接调用 `TokenService`；不走 `DaoAuthenticationProvider`；
- 认证失败统一 `BadCredentialsException` / `UNAUTHORIZED`，不暴露账号是否存在。

#### JWT

- HS256；`NimbusJwtDecoder.withSecretKey(...)`；`NimbusJwtEncoder` 签发；
- Claims：`sub`（account_id）、`roles`（授权角色数组）、`account_type`（主身份）、`school_id`（可空）、`exp`、`iat`、`jti`；
- `JwtAuthenticationConverter` 将 `roles` 每个值映射为 `ROLE_*`（教师兼管理员同时有 `ROLE_TEACHER` + `ROLE_ADMIN`）；旧 token 无 `roles` 时退回 `account_type` 单值；
- 权限管理器从 JWT 的 `roles` 读取角色集合，**取权限并集**，不把权限列表塞进 token；
- 2 小时有效，无 refresh；登出客户端丢 token。角色变更（V14 授予 / 撤销）需重新登录才对当前 token 生效。

#### URL 级权限管理器

- 启动时 `PermissionRegistry` 加载：
  - `api_permissions`：`method + path_pattern` → permission code；
  - `account_type_permissions`：account_type → permission codes。
- 自定义 `AuthorizationManager<RequestAuthorizationContext>`：
  - 公开接口由 Nginx 直接绕过 `auth_request`；Spring 侧仍 `permitAll` 兜底；
  - 用 Spring `PathPattern` 匹配请求路径；
  - 多个 pattern 命中时按“最具体路径优先”：字面量段 > 变量段 > 通配；同一优先级出现歧义时 CI 失败；
  - **角色集合中任一角色拥有该权限码即放行**（多角色并集）；
  - 没有匹配 / 没有授权：`AuthorizationDecision(false)`；
  - 默认拒绝；缺失权限行启动时记录 `ERROR`，不阻止启动；
  - CI 必须通过“路由 → 权限行”覆盖率与歧义检查。
- 不在 Controller 上写 `@PreAuthorize`；`api_permissions` 是接口权限唯一来源。
- 权限表 seed 只读；本轮不做运行时刷新，变更后重启生效。

#### 资源级权限

- service 层仍做：
  - 学生只能操作本人、本校本专业课程；
  - 教师只能操作本课程老师组；
  - 管理员只能操作本校数据；
  - 跨校一律 403。
- 管理员未建校：除建校接口外，service 检查 `school_id` 为空并拒绝。
- 管理员权限边界：可管理学校、组织、教师专业、课程元数据；不能创建课程，不能访问 M3 / M4 / M7。

#### 异常与响应

- `AuthenticationEntryPoint` → 401 JSON `UNAUTHORIZED`；
- `AccessDeniedHandler` → 403 JSON `FORBIDDEN`；
- `@RestControllerAdvice` 处理参数校验、业务异常；
- 不返回 Spring Security 默认 HTML 登录页。

#### 测试

- `spring-security-test` + MockMvc；
- 覆盖公开接口、无 token、过期 token、角色越权、跨校、未建校管理员；
- 权限矩阵测试覆盖学生 / 教师 / 管理员的允许与拒绝；
- CI 路由覆盖率与 JWT 签发 / 解析测试。

### 3.4 管理员建校与 school_admins

- 未绑定管理员调用 `POST /api/v1/admin/schools`，请求 `{name}`。
- 事务：
  1. 校验该账号没有 active 的 `school_admins` 行；
  2. 插入 `schools`；
  3. 插入 `school_admins(school_id, account_id, is_owner=true, status='active')`；
  4. 生成新 token（`school_id` 从 `school_admins` 解析）。
- 事务提交后发布 `SchoolCreatedEvent {school_id}`；M5 `@TransactionalEventListener(AFTER_COMMIT)` 复制种子题库；复制失败不阻塞建校，M5 懒初始化兜底。
- `accounts.school_id` 对管理员保持空；学校归属以 `school_admins` 为准。
- MVP 部分唯一索引 `UNIQUE(school_id) WHERE status='active'` 保证一校一管理员。
- 后期多对一：删除该唯一索引，增加学校邀请码 / 加入流程；不需要改 `accounts`。
- 并发建校：学校名唯一、`school_admins` 唯一约束兜底；失败返回 409。

### 3.5 学校 / 专业 / 班级维护

- 学校名称平台唯一；管理员可编辑本校名称。
- 专业：新增、编辑、停用；学校内名称唯一；停用不删除。停用前检查是否为某教师最后一个有效专业；若是则拒绝并返回受影响教师，要求先改专业。
- 班级：按专业 + 年级 + 班名维护；学校内自然键唯一；停用不删除。
- 已有学生的班级不能修改专业 / 年级；空班级可以修改。
- 停用专业 / 班级不再出现在注册选项、新建课程、批量加人选项中；已有关系保留。
- 学生注册班级匹配：
  - 前端按学校 / 专业 / 年级查询**启用**班级；
  - 恰好一个自动选中；多个学生选择；没有则不能提交；
  - 后端再次校验班级归属且 `classes.status='active'`；停用班级返回 `CLASS_DISABLED`。

### 3.6 组织导入

- 支持 CSV / Excel（xlsx）；Java 使用 EasyExcel（xlsx）+ commons-csv（CSV）。
- 两个类型化导入：专业、班级；不导入教师 / 学生账号。
- 单文件最多 500 行、5 MB；提供模板下载：`GET /api/v1/admin/imports/templates/{type}`，`type=major|class`。
- 专业列：`name`；自然键 `school_id + name`。
- 班级列：`major_name`、`grade`、`name`、`status`（可选，默认 active）；自然键 `major_id + grade + name`。
- 导入为整批事务：任一行失败则整批回滚；返回 `{total, created, updated, errors[]}`，`errors` 含行号 / 列 / 原因；不生成服务器错误报告文件。
- 校验：空值、重复、专业不存在 / 已停用、班级引用跨校、已有学生班级修改专业 / 年级、班级自然键冲突。
- 导入操作记 `admin:org`；跨校数据拒绝。

### 3.7 教师专业范围

- 管理员调用 `PUT /api/v1/admin/teachers/{account_id}/majors`，请求 `{major_ids}`。
- 校验：教师属于本校；专业属于本校且启用；至少一个；不能为空。
- 事务：
  1. 锁定教师账号 / 专业关系；
  2. 旧 active 行标记 `inactive`，写 `effective_to`；
  3. 新行 active，写 `effective_from`；
  4. 唯一约束 `(account_id, major_id) WHERE status='active'` 兜底。
- 已有课程老师组关系保留；新建课程、加入老师组按新专业范围校验。
- 教师本人不能修改；跨校 403。
- 历史专业只读展示，不提供删除。

### 3.7.1 教师附加角色（多角色，V14）

- 数据模型：`accounts.account_type_id` 是**主身份**（注册时确认、决定档案类型、不可变）；`account_roles(account_id, role_code)` 是**授权角色集合**，一人可多行。
- 管理员调用 `PUT /api/v1/admin/teachers/{account_id}/roles`，请求 `{"admin": true | false}`。
- 校验：
  - 目标必须是本校教师（`account_type = teacher` 且 `school_id` 相同），否则 400 / 403；
  - 不能操作自己（防自助提权与自锁），400；
  - 只允许叠加 / 撤销 `admin`，不接受任意角色码。
- 授予只写 `account_roles`，**不改** `accounts.account_type_id`，也不创建 `school_admins` 记录；教师档案与专业归属保持不变。
- 效果：该教师重新登录后 JWT `roles = ["teacher","admin"]`，同时具备教师与管理端权限；撤销后 `roles = ["teacher"]`。
- 生效时机：角色随 token 下发，**需重新登录**；未重新登录期间旧 token 权限不变（最长 2 小时）。
- 账号创建时仓储层自动写入主身份角色（`on conflict do nothing`），保证「账号存在 ⇒ 至少一个角色」，不依赖各服务各自记得写。

### 3.8 账号信息

- `GET /api/v1/auth/me` 返回本人账号、类型、学校与角色档案。
- 学生：学校、年级、专业、班级；教师：学校、有效专业列表；管理员：学校或未绑定状态。
- 账号类型只读，标注“注册后不可变更”。
- 个人资料 / 修改密码本轮不做；不提供更新接口。
- 退出登录只清除客户端 token；无服务端吊销。

### 3.10 登录扩展配置与安全

- 配置：`M1_WECHAT_APP_ID`、`M1_WECHAT_APP_SECRET`、`M1_WECHAT_REDIRECT_URI`、`M1_MAIL_*`（SMTP）、`M1_EMAIL_CODE_SECRET`；secret 只从环境变量 / Secret 读取。**本轮 `M1_WECHAT_APP_ID` 留空即走 Mock provider（验收基线），不接真实开放平台。**
- 存储：OAuth state / ticket 使用 Redis（测试 profile 用内存实现），TTL 5 分钟、一次性；验证码哈希落库，明文只存在发送请求内存中。
- 限流：邮箱验证码按邮箱 + IP；微信二维码按 IP；登录失败按账号 / IP；Nginx 与 service 双层限流。
- 审计：`auth_login_events` 记录 `event_type`（`login` / `bind` / `unbind`）、方式、provider、成功 / 失败、IP、UA；不记录 token、验证码、微信 access token。
- 安全：state 防重放、回调白名单、微信 userinfo 只信任服务端换取结果；绑定 / 解绑需重新验证；不在 URL / 日志中放 JWT。
- 测试：`MailSender` / `OAuthProvider` 均有 Mock；真实微信 / SMTP 只在手工 smoke 使用，不进入 CI。

## 4. M2 系统设计

### 4.1 课程状态矩阵

| 操作 | 启用且未到 `end_at` | 已到 `end_at`、未归档 | 已归档 |
|---|---|---|---|
| 学生课程列表可见 | 是 | 是，标“已结束” | 否（已有报告可直链） |
| 学生加入 | 可 | 不可 | 不可 |
| 学生退出 | 可 | 不可 | 不可 |
| 老师组增 / 删 | 可 | 不可 | 不可 |
| 学生名单增 / 删 | 可 | 不可 | 不可 |
| 新建任务 | 可 | 不可 | 不可 |
| 编辑草稿任务 | 可 | 可编辑，不能发布 | 不可 |
| 发布已有草稿任务 | 可 | 不可 | 不可 |
| 关闭任务 | 可 | 可 | 不可 |
| 已有提交的教师评分 / 统计 | 可 | 可 | 只读 |
| 编辑课程名称 / `end_at` | 可 | 不可 | 不可，只能恢复 |
| 归档 / 恢复 | 管理员可归档 | 管理员可归档 | 管理员可恢复 |

- `courses.end_at` 使用 `timestamptz`（UTC）；`now >= end_at` 即视为已结束；为空时只有归档触发只读。
- `end_at` 作为教学结束：停止加入、加人、老师组变更、新建任务、发布草稿任务；已有 session 可结束 / 提交，已有提交可评分。
- 归档作为管理结束：全部只读；学生列表隐藏；本组教师可通过已有链接只读查看统计 / 导出；管理员可恢复。

### 4.2 创建课程

- 教师调用 `POST /api/v1/courses`，请求 `{name, major_ids, end_at?}`。
- 校验：
  - 当前账号为教师；
  - 学校从 token 获取；
  - 至少一个专业；专业均在本校且启用；
  - 专业全部在教师本人有效专业范围内；
  - 课程名称非空，且在本校唯一；重复返回 `COURSE_NAME_TAKEN`；
  - `end_at` 可选；若提供，必须晚于当前时间；创建已结束课程返回 `INVALID_END_AT`。
- 事务：
  1. 插入 `courses`；
  2. 插入 `course_majors`；
  3. 插入 `course_teachers`，创建者 active；
  4. 返回课程详情。
- 课程所属学校、课程专业范围创建后不可修改。
- 课程名称校内唯一；同一门课下一届加年份 / 后缀新建课程，不复用原名称。
- 管理员调用 `POST /courses` 返回 403。

### 4.3 课程可见性与列表

- 学生：
  - 本校、启用、专业在 `course_majors` 内的课程；
  - 已结束课程可见并标“已结束”，不可加入；
  - 已归档课程在课程列表隐藏；已有报告可直链查看。
- 教师：
  - 可检索本校启用 / 已结束课程（只读）；默认显示“我的课程”，可切换“全校课程”；
  - `course_teachers` 中 active 的课程可管理、查看任务 / 名单 / 统计；
  - 非本组课程只读，不显示任务 / 名单 / 统计入口；
  - 已结束课程按状态矩阵只读；已归档课程不在列表展示，但本组教师可通过已有链接只读查看统计 / 导出。
- 管理员：
  - 本校全部课程，含已归档；
  - 状态筛选：全部 / 启用 / 已结束 / 已归档。
- 搜索：课程名称、教师姓名；分页 `page/size`。
- 列表形态：
  - 学生：卡片（名称、老师组、专业、学生数、状态、加入 / 进入）；
  - 教师 / 管理员：表格（课程、专业、老师组、学生数、结束日期、状态、操作）。

### 4.4 老师组

- 添加教师：`POST /courses/{id}/teachers`，请求 `{account_id}`。
  - 同校、`account_type=teacher`；本轮不设 `accounts.status`，不要求账号 active；
  - 教师有效专业与课程专业范围至少一个交集；
  - 未在 active 组内；
  - 任何 active 组内教师或管理员可添加。
- 移出教师：`DELETE /courses/{id}/teachers/{account_id}`。
  - 任何 active 组内教师或管理员可移出；
  - 至少保留一名 active 教师；
  - 软删除，写 `left_at`，保留历史；
  - 事务提交后发布 `CourseTeacherRemovedEvent {course_id, account_id}`，M6 自动下架该教师在该课程发布的训练模板。
- 组内平权：创建者无特权；不设主教师。
- 并发：修改老师组时对课程行加锁（`SELECT ... FOR UPDATE`），检查 active 教师数；防止两人同时移出最后两名教师。
- 教师专业范围被管理员修改后：已有老师组关系保留；新加入按新范围校验。

### 4.5 学生成员

- 学生自主加入：`POST /courses/{id}/join`。
  - 同校、学生角色、专业在课程范围内；
  - 课程 active 且未到 `end_at`；
  - 无 active 关系；重复加入 409 `ALREADY_JOINED`；
  - `join_method='self'`。
- 学生自主退出：`POST /courses/{id}/leave`。
  - 仅 active 且未到 `end_at`；
  - 软删除，状态 `left`，保留历史；
  - 重新加入生成新行。
- 教师 / 管理员按班级批量加入：`POST /courses/{id}/students/class`，请求 `{class_id}`。
  - 班级 active、同校、专业在课程范围内；
  - 班级内学生批量加入；已存在跳过；
  - 返回 `{total, success, skipped, errors[]}`；允许部分成功；
  - `join_method` 为 `class` 或 `admin`。
- 按账号 ID 加入：`POST /courses/{id}/students/account`，请求 `{student_account_id}`。
  - 学生存在、同校、专业在范围内；
  - 已存在 409 / 跳过；`join_method='account'` 或 `admin`。
- 查看老师组 / 学生名单：`GET /courses/{id}/teachers`、`GET /courses/{id}/students`，权限 `course:members:read`；仅本组教师 / 本校管理员，学生不可读；`include_history=true` 可含已退出 / 移出成员。
- 移出学生：`DELETE /courses/{id}/students/{account_id}`。
  - 老师组 / 管理员；
  - 仅 active 且未到 `end_at`；
  - 软删除，状态 `removed`；
  - 管理员移出不限制专业；添加仍受专业范围约束。
- 批量加入允许部分成功；与 M1 组织导入的整批回滚不同。

### 4.6 归档与恢复

- 管理员调用 `POST /courses/{id}/archive`。
  - 设置 `status='archived'`、`archived_at`；
  - 不删除老师组、学生、任务、录像、报告；
  - 学生课程列表隐藏；不可加入 / 退出；
  - M3 / M4 / M6 / M7 转为只读；M6 该课程训练模板自动下架；
  - 事务提交后发布 `CourseArchivedEvent {course_id}`；
  - 二次确认。
- 恢复：`POST /courses/{id}/restore`。
  - 设置 `status='active'`；
  - 不修改 `end_at`；若 `end_at` 已过，课程仍显示“已结束”，按状态矩阵只读；
  - 如需重新开课，本轮需新建课程（Q2 已确认）。
- 归档课程在管理端可见，学生端隐藏；已有报告可直链。

### 4.7 M2 页面与路由

| 路由 | 页面 | 角色 | 主要接口 |
|---|---|---|---|
| `/courses` | 课程列表 / 发现 | 学生、教师、管理员 | `GET /courses`、join / leave |
| `/courses/{id}` | 课程详情 | 学生、教师、管理员 | 课程详情、成员、任务入口 |
| `/courses/new` 或课程管理抽屉 | 创建课程 | 教师 | `POST /courses` |
| `/courses/{id}/teachers` | 老师组 | 教师、管理员 | 老师组 CRUD |
| `/courses/{id}/students` | 学生管理 | 教师、管理员 | 学生名单、批量加入、移出 |
| 管理员课程列表归档弹窗 | 归档 / 恢复 | 管理员 | archive / restore |

- 标题栏、顶部导航、头像与 M1 共用。
- 学生课程详情：课程信息 + 任务 / 本人成绩；可退出课程。
- 教师课程详情：任务 / 学生 / 老师组 / 统计。
- 管理员课程详情：概览 / 学生 / 老师组；不显示任务、报告、统计。
- 页面视觉：B · 深蓝 + 琥珀；顶部导航；学生用卡片，教师 / 管理员用表格；创建课程用右侧抽屉。

## 5. 跨模块边界

- M1 提供账号、学校、专业、班级、教师专业；M2 只读引用。
- M2 提供课程、课程专业、老师组、学生成员、`end_at`、归档状态。
- M3 读取课程与成员，创建任务；课程 `end_at` 后不能新建任务；归档后只读。

- M5 读取学校；管理员可管理本校题库（与 M5 设计一致），但不进入 M3 / M4 / M6 / M7 评测业务。
- M7 教师评分在 `end_at` 后仍可进行，归档后只读；本组教师可通过直链查看归档课程统计 / 导出。

## 6. 事务、并发与幂等

| 场景 | 事务 / 并发 |
|---|---|
| 注册 | 单事务写 `accounts` + 角色档案；用户名唯一约束 |

| 归档 / 恢复 | 单事务更新状态；不删除关联数据 |
| 登录 / 注册 | Nginx 限流；失败统一提示 |
