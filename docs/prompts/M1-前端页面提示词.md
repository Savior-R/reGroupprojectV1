## 0. 给执行者的话（先读，违反其中任一条都会返工）

1. **技术栈固定**：Vue 3 `<script setup>` + TypeScript + Element Plus + Pinia + Vue Router 4。不要引入 Tailwind、shadcn/ui、Ant Design Vue 或 Naive UI。若目标项目确实是 React 栈，见附录 D 的组件映射表，页面结构与视觉规范不变。
2. **视觉基调固定**：明亮、护眼、有学术气息。不要做成 SaaS 后台那种高饱和蓝白，也不要暗色赛博风，不要大面积纯白 + 纯黑文字。
3. **全局暗色已移除**（2026-11-10）：`src/main.ts` 不再给 `<html>` 加 `dark` 类，`src/style.css` 已是 `color-scheme: light` + 米白背景。**新增页面直接复用 `var(--m1-*)` 变量即可，不要引入第二套主题变量。** 例外见 §4.7：课堂 / 面试 / 复盘三个沉浸式页面保留深色。
4. **只实现第 5 章列出的页面**。不要自行增加"修改密码""账号列表""删除账号""自定义角色"——需求明确不做，见 §1.3。
5. **接口契约不可改**：路径、字段名（snake_case）、错误码照附录 A / B 执行。后端已实现，前端不得假设不存在的接口；第 5.9 节明确标注了需要新增的只读接口。
6. **响应式必须做**：桌面（≥1200px）、平板（768–1199px）、移动（<768px）三档都要能完成全部流程，不是"能打开"。
7. **每个页面交付四态**：加载中、空数据、请求失败、成功。

## 1. 产品背景与模块边界

### 1.1 产品是什么

面向师范生的**课堂试讲训练与评测平台**。学生录制试讲 → AI 评分 → 教师复盘点评。本模块负责三件事：**谁能进来（认证）、进来是谁（身份）、能做什么（授权）**。

使用者是师范生和高校教师，不是互联网 C 端用户。界面气质应接近**高校教务系统 / 学术期刊网站**，而不是电商或 SaaS 控制台。

### 1.2 三种主身份（注册时选定，终身不可变）

| 主身份 | 关键特征 | 注册时必填 |
|---|---|---|
| **学生** | 归属某校、某年级、某专业、某班级 | 学校 → 年级 → 专业 → 班级（四级级联） |
| **教师** | 归属某校，可属一个或多个专业，**不绑年级** | 学校 + 至少一个专业（多选） |
| **管理员** | 与学校**一对一**；注册时无学校，登录后建校 | 仅用户名 + 密码 |

**主身份注册后不可变更**，界面不得出现任何"切换身份"控件。

### 1.3 多角色：主身份 ≠ 全部权限

这是本模块最容易理解错的地方，先讲清：

- **主身份**（`account_type`）决定建立哪种档案，不可变；
- **授权角色**（`roles` 数组）决定这次登录能行使哪些权限，可以叠加。

现实场景：**一位教师同时是教务管理员**。管理员可以在「教师管理」页给本校教师打开「管理员」开关，该教师重新登录后 `roles = ["teacher", "admin"]`，既能用教师功能，也能进管理端。

界面上要体现这一点：

- 顶栏角色徽章显示 `教师 / 管理员`，不是一个词；
- 被授予管理员的教师，导航里同时出现教师侧与管理侧入口；
- 授权页要明确提示"该教师需重新登录后生效"——这是真实限制，不是 bug。

### 1.4 明确不做的功能（不要实现，连按钮都不放）

- 密码找回、修改密码、修改个人资料（本轮账号信息只读）
- 主身份变更
- 管理员管理其他账号（仅"修改本校教师专业范围""授予/撤销管理员角色"两项例外）
- 自定义角色、角色增删改、按接口勾选权限（三类角色固定）
- 账号注销 / 停用 / 封禁
- 手机号 / 短信验证码登录、微信以外的第三方登录
- 管理员的教师身份（反向：管理员变教师，缺教师档案，不在本轮）

## 2. 角色与权限模型（写页面前必须读懂）

### 2.1 数据结构（三层）

```
账号 accounts
  ├─ account_type_id        → 主身份（student / teacher / admin），不可变
  └─ account_roles          → 授权角色集合，可多行
        └─ role_code        → student / teacher / admin

角色 account_types           → 三类固定角色
权限 api_permissions         → 一条路由一条规则（method + path_pattern + 权限码）
角色权限 account_type_permissions → 角色拥有哪些权限码
```

授权判定 = **角色集合的权限并集**。教师兼管理员时，教师权限 + 管理员权限都可用。

### 2.2 前端怎么用

| 场景 | 用什么判断 | 不要用 |
|---|---|---|
| 显示管理端导航 | `roles.includes('admin')` | `account_type === 'admin'` ❌ |
| 显示任务中心 | `roles.includes('student')` | `account_type === 'student'` ❌ |
| 显示"教师"标签 | `roles.includes('teacher')` | `account_type` |
| 判断主身份档案 | `account_type` | `roles` |

JWT 里的字段（解码 payload，**不验签**，签名由后端保证）：

```json
{
  "sub": "账号 UUID",
  "account_type": "teacher",          // 主身份
  "roles": ["teacher", "admin"],      // 授权集合，判断权限只用这个
  "school_id": "学校 UUID 或 null",
  "exp": 1762000000
}
```

`roles` 缺失时（旧 token）回退为 `[account_type]`。

### 2.3 角色与权限总览（页面文案直接可用）

| 能力 | 学生 | 教师 | 管理员 |
|---|---|---|---|
| 注册 / 登录 / 绑定邮箱微信 | ✅ 本人 | ✅ 本人 | ✅ 本人 |
| 查看任务中心 | ✅ | ❌（教师端待开发） | ❌ |
| 建校 / 维护学校·专业·班级 | ❌ | ❌ | ✅ 本校 |
| 修改教师专业范围 | ❌ | ❌ | ✅ 本校 |
| 授予 / 撤销管理员角色 | ❌ | ❌ | ✅ 本校 |
| 跨校数据 | ❌ | ❌ | ❌ |

### 3.2 目录结构

```
src/
├─ api/
│  ├─ auth.ts          # 本模块全部请求（已有 30+ 函数）
│  ├─ jwt.ts           # 解码 claims、rolesOf / hasRole / isAdmin / homeFor
│  └─ client.ts        # M3 共享客户端，不要在本模块页面里用
├─ views/
│  ├─ auth/            # 登录、注册、OAuth 引导注册
│  └─ admin/           # 外壳、建校、组织、教师、账号安全、角色权限

├─ types/api.ts
└─ style.css
```

**约定**：M1 页面只用 `api/auth.ts` 的 `authClient`（自动带 Bearer）；`api/client.ts` 是 M3 的共享客户端，混用会带错身份头。

### 3.3 状态管理

- **服务端状态**不做全局缓存，页面内 `ref` + 请求函数即可（本模块数据量小、变更频繁）。
- **会话状态**只有 token：`localStorage['m1.auth.token']`，通过 `getToken() / setToken()` 读写。
- 不要新建 Pinia store 存用户信息；需要时调 `GET /auth/me`。

### 3.4 命名与代码风格

- 组件 `PascalCase.vue`，文件放 `views/auth/` 或 `views/admin/`。
- 接口类型定义在 `api/auth.ts`，与后端 DTO 字段名一致（snake_case），**不要在组件里再转换命名**。
- 样式用 `<style scoped>`，颜色一律走 CSS 变量（见 §4.2），禁止硬编码十六进制。
- 注释说明"为什么"，不复述代码。

## 4. 视觉规范

### 4.1 设计基调（一句话）

**米白纸感背景 + 墨绿主色 + 衬线标题 + 克制留白**，像一本排版良好的学术论文集，而不是一块仪表盘。

四条落地原则：

1. **降低刺激**：背景不用纯白（`#FFFFFF`），用微暖米白；正文不用纯黑，用墨灰。长时间阅读不刺眼。
2. **提高可读**：正文 15–16px，行高 1.7，段落宽度不超过 72 个汉字。
3. **强调克制**：一屏最多一个主色实心按钮；其余用描边或文字按钮。
4. **层次靠留白与描边**，不靠浓重阴影与大面积色块。

### 4.2 色彩系统（CSS 变量，直接写进 `style.css`）

```css
  --m1-bg-subtle:    #F1EFE9;          /* 表头、次级区域、代码块 */
  --m1-bg-hover:     #EDEAE2;          /* 悬浮态 */
```

**用色纪律**：

- 主色实心按钮：每屏最多 1 个（提交 / 创建 / 保存）。
- 危险操作（撤销管理员、解绑）用 `--m1-danger` 描边按钮，不用实心红。
- 状态标签：文字用语义色，底色用对应 `-soft` 变体（如 `#E7EFEC`），不要用高饱和填充。
- 禁止使用纯红 `#FF0000`、纯蓝 `#1890FF`、纯黑 `#000000`。

**布局节奏**：

- 页面左右内边距：桌面 32px，平板 24px，移动 16px。
- 卡片内边距：桌面 24px，移动 16px。
- 卡片之间垂直间距 24px；表单项之间 20px。
- 内容区最大宽度 `1120px` 居中（管理端表格页可放宽到 `1280px`）。

### 4.5 组件视觉规则

| 组件 | 规则 |
|---|---|
| 按钮 | 高度 36px（`size="default"`），圆角 8px；主按钮实心主色，次按钮描边 `--m1-border-strong`，文字按钮仅主色文字无背景 |
| 输入框 | 高度 40px，圆角 8px，边框 `--m1-border`；聚焦时 1px 主色边框 + 2px `--m1-primary-soft` 外发光，**不要**默认的蓝色发光 |
| 卡片 | 白底 + 1px `--m1-border` + `--m1-shadow-card`；不使用 Element 默认的 `--el-card-border-color` 深灰边框 |
| 表格 | 表头底色 `--m1-bg-subtle`，无竖线，行分隔用 1px `--m1-border`；行悬浮 `--m1-bg-hover` |
| 标签 | 圆角 6px，高度 22px，13px 字号；底色用 `-soft` 变体 |
| 步骤条 | 激活色主色，完成色主色，未激活 `--m1-text-placeholder`；文字用 sans |
| 弹窗 | 圆角 12px，`--m1-shadow-pop`，标题用 serif 18px；遮罩 `rgba(31,42,40,0.35)` |
| 分割线 | 1px `--m1-border`，上下留白 24px |
| 空状态 | 图标 48px、`--m1-text-placeholder`；文案 14px 次要色；不用默认插画 |

### 4.6 动效

- 时长 **150–200ms**，缓动 `cubic-bezier(0.4, 0, 0.2, 1)`。
- 只允许三种：**淡入**（弹窗、提示）、**位移 4px 淡入**（卡片列表）、**颜色过渡**（按钮、链接 hover）。
- 禁止：缩放弹跳、旋转加载以外的动画、大面积位移。
- 必须尊重 `prefers-reduced-motion: reduce`，命中时全部动效降为 0ms。

### 4.7 明暗模式

本轮**只交付明亮主题**，且已完成切换（2026-11-10）：

- `src/main.ts` 中的 `document.documentElement.classList.add('dark')` 与 `dark/css-vars.css` 引入**已移除**；
- `src/style.css` 的 `color-scheme` 已改为 `light`，背景为 `--m1-bg-page: #f7f6f2`；
- Element Plus 的 `--el-*` 变量已映射到本主题，组件库整体跟随。

不提供切换开关——多一套主题会成倍增加验收面，本轮不做。

> 例外：课堂 / 面试 / 复盘三个沉浸式页面仍用 `ImmersiveLayout` 的深色背景（`#0b1220`）。这是录制与直播场景的刻意选择，与全站浅色不冲突，新页面不要模仿。

## 5. 页面清单与详细规格

### 5.0 路由总表

| 路由 | 页面 | 访问条件 | 落地后 |
|---|---|---|---|
| `/login` | 登录 | 公开；已登录用户进入会被弹回首页 | — |
| `/register` | 注册 | 公开 | 学生 → `/student/tasks`；教师 → `/settings/security`；管理员 → `/admin/setup` |
| `/register/oauth` | 微信引导注册 | 公开，需 `?ticket=` | 同上 |
| `/admin/setup` | 创建学校 | 登录 + `admin` 角色 + 未建校 | 建校后 → `/admin/org` |
| `/admin/org` | 学校与组织 | 登录 + `admin` + 已建校 | — |
| `/admin/teachers` | 教师管理 | 登录 + `admin` + 已建校 | — |
| `/admin/roles` | **角色与权限**（新增） | 登录 + `admin` + 已建校 | — |
| `/settings/security` | 账号安全 | 登录 | — |

**守卫规则**（`router.beforeEach`）：

```
未登录 + 需要登录        → /login?redirect=<原路径>
无 admin 角色 + 管理页    → /403
非学生 + 学生端页面       → /403
admin 角色 + 未建校 + 管理页 → /admin/setup
已登录 + 访问 /login|/register → 该角色首页
```

> 首页函数：`admin` → 已建校 `/admin/org`，未建校 `/admin/setup`；`student` → `/student/tasks`；其余 → `/settings/security`。

### 5.1 应用外壳 AppShell（`views/admin/AdminShell.vue`）

**导航生成规则**

| 条件 | 显示项 |
|---|---|
| `roles` 含 `admin` 且有 `school_id` | 学校与组织、教师管理、角色与权限 |
| `roles` 含 `admin` 且无 `school_id` | 创建学校 |

### 5.2 登录页 `/login`

**目标**：三种方式都能进，且失败不泄露账号是否存在。

**布局（桌面 ≥1024px）**：左右分栏，比例 55:45。

```
┌──────────────────────────────┬─────────────────────────┐
│                              │                         │
│   三尺讲台                    │   ┌─────────────────┐   │
│   AI 师范生教学评测            │   │  ┌──┬──┬──┐      │   │
│                              │   │  │密码│邮箱│微信│   │   │
│   ────                       │   │  └──┴──┴──┘      │   │
│                              │   │                 │   │
│   「讲台三分钟，              │   │  用户名          │   │
│    功夫在课外。」              │   │  [__________]   │   │
│                              │   │  密码            │   │
│   左侧为品牌区：              │   │  [__________]👁  │   │
│   - 背景 var(--m1-bg-subtle) │   │                 │   │
│   - 顶部一枚校徽/抽象几何图形  │   │  [   登 录   ]   │   │
│   - 衬线大字 + 细横线 + 引文   │   │                 │   │
│                              │   │  还没有账号？注册 │   │
│                              │   └─────────────────┘   │
└──────────────────────────────┴─────────────────────────┘
```

**移动端（<768px）**：左侧品牌区隐藏（保留一个 48px 高的小品牌头），卡片全宽，内边距 24px。

**卡片**：宽 420px（桌面），白底，圆角 12px，`--m1-shadow-card`，内边距 32px。

**Tab 一：密码登录**

| 字段 | 组件 | 校验 | 说明 |
|---|---|---|---|
| 用户名 | `el-input` | 必填，2–64 字符 | 提示"请输入姓名（与注册时一致）" |
| 密码 | `el-input` type=password，`show-password` | 必填，8–64 字符 | 回车即提交 |

- 提交按钮全宽，主色实心，loading 时禁用并显示"登录中"。
- 失败统一提示 **「用户名或密码错误」**——不要区分"账号不存在"和"密码错误"。
- 成功后：`setToken(token)` → 按附录 A 的 `homeFor` 规则跳转；若 URL 带 `redirect` 参数且是同源站内路径，优先跳它。

**Tab 二：邮箱验证码登录**

| 字段 | 组件 | 校验 |
|---|---|---|
| 邮箱 | `el-input` | 必填，邮箱格式 |
| 验证码 | 6 个独立输入框（或单框 `letter-spacing: 0.3em`）+ 「获取验证码」按钮 | 6 位数字 |

- 「获取验证码」点击后进入 **60 秒倒计时**，按钮文案 `58s 后重发`，倒计时期间禁用。
- 后端限流：同一邮箱 5 次/小时、同一 IP 20 次/小时；命中返回 429，提示「请求过于频繁，请稍后再试」。
- 验证码错误/过期/邮箱未绑定统一提示 **「验证码无效或已过期」**，不暴露邮箱是否注册。
- 图标：验证码输入框左侧放 `Message` 图标（20px，`--m1-text-placeholder`）。

**Tab 三：微信扫码**

```
┌──────────────────────────┐
│      ┌────────────┐      │
│      │            │      │
│      │   二维码    │      │  160×160，白底，1px 描边
│      │            │      │
│      └────────────┘      │
│   请使用微信扫描二维码登录  │  13px 次要色
│   二维码 4:58 后失效  [刷新]│
└──────────────────────────┘
```

- 进入 Tab 时请求二维码（`POST /auth/oauth/wechat/qr`），返回 `state` + `qr_content`。
- **轮询**：每 2 秒 `GET /auth/oauth/wechat/status?state=`，状态机：

| 状态 | 界面表现 | 后续动作 |
|---|---|---|
| `pending` | 二维码正常，提示"等待扫描" | 继续轮询 |
| `scanned` | 二维码上浮一层半透明遮罩 + 打勾图标，文案「已扫描，请在手机上确认」 | 继续轮询 |
| `authorized` | 停止轮询，调 `POST /auth/oauth/wechat/exchange {ticket}` | 换到 token → 登录成功 |
| `needs_registration` | 停止轮询，跳 `/register/oauth?ticket=<ticket>` | 引导注册 |
| `expired` | 二维码置灰 + 「二维码已失效」+ 「刷新」按钮 | 手动刷新 |
| `failed` | 显示错误说明 + 「重试」按钮 | 手动重试 |

- 二维码 5 分钟有效期，界面上显示倒计时；页面切到后台（`visibilitychange`）暂停轮询，回到前台恢复。
- 组件卸载时必须清掉定时器。
- **开发/演示模式**：`M1_WECHAT_MOCK=true` 时，二维码区域下方额外显示两个调试按钮「模拟已绑定扫码」「模拟未绑定扫码」，点击直接推进状态。生产构建下不渲染（用 `import.meta.env.DEV` 判断）。

**页面状态**

| 状态 | 表现 |
|---|---|
| 初始 | 表单为空，主按钮可点 |
| 提交中 | 按钮 loading，输入框禁用 |
| 失败 | 表单上方 `el-alert`（type=error，`--m1-danger` 左侧 3px 竖条），文案来自后端 `message` |
| 成功 | 无需成功提示，直接跳转 |

### 5.3 注册页 `/register`

**目标**：两步向导，先选身份再填资料；身选择直接决定第二步的字段。

**步骤条**（`el-steps`，简洁版，不要图标圆圈里的数字用 serif）：

```
① 选择身份  ──────  ② 填写资料
```

**第一步：选择身份**

三张卡片并排（桌面 3 列，平板 3 列压缩，移动纵向堆叠）：

```
┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│   [GraduationCap] │ │   [Reading]      │ │   [Setting]      │
│              │ │              │ │              │
│   学 生       │ │   教 师       │ │   管理员      │
│              │ │              │ │              │
│ 在校师范生，   │ │ 指导教师，可  │ │ 负责本校组织  │
│ 参与试讲与评测 │ │ 属多个专业    │ │ 与教师管理    │
└──────────────┘ └──────────────┘ └──────────────┘
```

- 卡片尺寸 200×160，白底，1px 描边，圆角 12px。
- 悬浮：边框变 `--m1-primary`，背景 `--m1-primary-soft`（透明度 50%）。
- 选中：边框 2px `--m1-primary`，右上角一枚 `Check` 圆形徽标（18px，主色底、白勾）。
- 图标 28px，`--m1-primary`；标题 17px serif 600；描述 13px 次要色，两行以内。
- 选择后用一行说明文字确认：「你将注册为**教师**，注册后身份不可变更」，其中身份加粗主色。
- 底部「下一步」按钮，未选择时禁用。

**第二步：填写资料**

字段按身份分支：

| 身份 | 字段 |
|---|---|
| 学生 | 用户名、密码、确认密码、学校、年级、专业、班级 |
| 教师 | 用户名、密码、确认密码、学校、专业（多选） |
| 管理员 | 用户名、密码、确认密码 |

公共字段规则：

| 字段 | 组件 | 校验 | 提示 |
|---|---|---|---|
| 用户名 | `el-input` | 必填，2–64 字符，平台唯一 | 「请填写真实姓名，重名时加区分后缀，如"张三2"」 |
| 密码 | password | 必填，8–64 字符 | 「至少 8 位」；强度条可省略，但必须显示规则 |
| 确认密码 | password | 与密码一致 | 不一致时行内红字 |

**四级级联（学生）**：学校 → 年级 → 专业 → 班级

- 四个 `el-select` 竖排，每级依赖上一级。
- 切换上级时清空下级并重新拉取；加载中展示 `loading` 状态。
- **班级自动选中**：若某年级某专业下只有一个启用班级，自动填入并显示一行提示「已自动匹配班级：2024 级 1 班（可修改）」；多个班级时留空要求手动选；**没有班级时阻断提交**，提示「该专业暂无可用班级，请联系学校管理员」。
- 班级下拉展示格式：`2024 级 · 1 班`。

**专业多选（教师）**：

- `el-select multiple`，选项来自所选学校的启用专业。
- 至少选 1 个；选择后以标签形式展示，标签可关闭。
- 提示：「可属多个专业，不绑定年级。管理员后续可调整」。

**提交**

- 「完成注册」主按钮；成功后 `setToken` 并按身份跳转。
- 用户名冲突（409 `USERNAME_TAKEN`）：**在用户名字段下方行内报错**「用户名已被占用，请在姓名后加区分后缀」，不要只弹 toast。
- 其余错误用 `el-alert` 展示后端 `message`。

**返回**：第二步左上角有「← 上一步」，返回不清空已填内容。

```
│ ─────────────────────────      │ │ ─────────────────────────      │
```

- 停用二次确认：「停用后该专业不再出现在新注册与新建课程中，已有数据保留。确认停用？」
- 停用行整行文字降为 `--m1-text-placeholder`，状态标签用 warning 色。

**班级区**

- 顶部筛选：专业下拉（含"全部"）。
- 新增行：专业下拉 + 年级输入（4 位数字，如 2024）+ 班名输入 + 「新增」。
- 列表列：专业、年级、班名、状态、操作。
- 空态：「本校暂无班级，可手动新增或导入」。

**导入（关键交互）**

入口：专业区与班级区各一个「导入 CSV / Excel」按钮 + 「下载模板」。

```
点击「导入」
  → 弹窗（宽 520px）
     ┌──────────────────────────────────────┐
     │  导入专业                              │
     │  支持 .csv / .xlsx，≤ 5MB，单次 ≤ 500 行 │
     │  ┌────────────────────────────────┐  │
     │  │   拖拽文件到此处，或点击选择      │  │  ← 虚线框，高 140px
     │  └────────────────────────────────┘  │
     │  已选：majors.csv（12 KB）            │
     │  [下载 CSV 模板]                      │
     │                    [取消]  [开始导入]  │
     └──────────────────────────────────────┘
```

- 拖拽区：悬浮/拖入时边框变主色、背景 `--m1-primary-soft`。
- 文件类型限制在前端先校验一次；不合法立即提示，不发请求。
- 导入中：显示进度条（不确定进度，用 `el-progress` 的 `indeterminate`）与文案「正在校验 32 行…」。
- **成功后**：弹窗内切换为结果视图——「导入完成：新增 28，更新 4，跳过 0」，列表自动刷新。
- **有错误行时（整批回滚）**：同一弹窗内展示错误表格，**必须逐行列出**：

```
┌──────────────────────────────────────────────┐
│  ⚠ 导入失败，未写入任何数据                     │
│  第 3 行 · name：专业名称不能为空               │
│  第 7 行 · name：专业名称在本批次内重复          │
│                     [下载错误明细] [关闭]       │
└──────────────────────────────────────────────┘
```

错误数据结构 `details.errors[]`，每项 `{ row, column, message }`。错误表格两列：位置（`第 N 行`）、原因。超过 10 条时表格内部滚动（最大高度 240px）。

- 「下载模板」：`GET /admin/imports/templates/{type}`（`type` 为 `major` / `class`），直接触发浏览器下载。

**空态与加载态**

- 加载：卡片内 `el-skeleton` 3 行，不要整页 spinner。
- 空：`el-empty`，描述「还没有专业，先新增一个或导入清单」。

## 6. 全局交互规范

### 6.1 表单校验时机

- **失焦时**校验单字段；**提交时**校验全部；**输入时**清除该字段的错误提示。
- 错误文案紧贴字段下方，12px，`--m1-danger`，前面不加图标（节省视觉噪音）。
- 必填项标签前不加红星堆叠：统一在标签后加一个 4px 的 `--m1-danger` 小圆点。

### 6.2 四态规范

| 状态 | 规范 |
|---|---|
| **加载** | 卡片内 `el-skeleton`（3–5 行）；表格用 `v-loading`；按钮用 `loading` 属性。**禁止整页 spinner 遮罩**，除非是首次进入应用 |
| **空** | `el-empty`，描述文字必须具体（"本校暂无班级，可手动新增或导入"），不要写"暂无数据" |
| **错误** | 页面级用 `el-alert`（可关闭，显示后端 `message` + `code`）；行内用字段下方红字 |
| **成功** | 轻量 `ElMessage.success`（2 秒自动消失）；**不要**用弹窗打断 |

### 6.3 错误提示映射

优先显示后端 `message`（已是中文业务文案）。后端不可达时按状态码兜底：

| 状态码 | 兜底文案 |
|---|---|
| 400 | 提交内容有误，请检查后重试 |
| 401 | 登录已过期，请重新登录（并跳 `/login`） |
| 403 | 你没有权限执行该操作 |
| 404 | 请求的内容不存在 |
| 409 | 该内容已存在，请更换后重试 |
| 429 | 操作过于频繁，请稍后再试 |
| 5xx | 服务暂时不可用，请稍后重试 |

**统一入口**：在 `authClient` 上加响应拦截器，把 `error.response.data.message` 提升到 `error.message`；页面 `catch` 里只读 `error.message`。不要在 8 个页面里各写一份解析。

### 6.4 权限失败的表现

- 前端守卫拦截 → 跳 `/403` 页，页面提供「返回首页」按钮（按角色回到正确首页）。
- 后端返回 403 → `el-alert` 提示「你没有权限执行该操作」，不要清 token、不要跳转。
- **不要把 403 和 401 混同**：401 才清 token 跳登录。

### 6.5 会话

- token 存 `localStorage['m1.auth.token']`。
- 每次进入受保护路由解码一次，检查 `exp`；过期视为未登录。
- 不做自动续期（后端无 refresh token），过期即跳登录，并在登录页提示「登录已过期，请重新登录」。
