# M1 账号管理与身份认证

> 上位文档：[需求规格说明书.md](需求规格说明书.md) 第一点（拆分后的账号与组织部分）
> 版本：V0.3（讨论稿）　状态：待评审　更新日期：2026-11-07
> 需求编号：`FR-M1-xx`
> 关联模块：[M2 课程操作与管理](M2-课程操作与管理.md)（依赖本模块）

## 1. 范围

### 1.1 本轮实现

- 学生、教师、管理员自助注册与登录；注册时选择并确认账号类型，注册后不可变更
- 用户名 + 密码登录、邮箱验证码登录、微信开放平台扫码登录三种方式
- 微信扫码未绑定账号时进入 OAuth 引导注册；已登录账号可绑定 / 解绑微信与邮箱
- JWT / JWS 认证、token 校验与会话
- 账号 ID、用户名、密码、账号类型、学校归属；账号类型注册后不可变更
- 管理员与学校一对一；管理员创建并绑定学校
- 学校、专业、班级的创建 / 导入 / 维护（管理员）
- 学生学校、年级、专业归属与班级匹配、入班
- 教师学校、专业归属（可多专业）
- 管理员修改本校教师的专业范围
- 管理员为本校教师授予 / 撤销管理员角色（多角色：教师兼管理员）
- 接口级角色与学校范围授权

### 1.2 本轮不做

- 课程创建、老师组、选课等课程功能（见 M2）
- 跨校账号、跨校管理员
- 管理员管理其他账号（仅修改本校教师专业范围、授予 / 撤销本校教师管理员角色除外）
- 自定义角色、角色增删、按接口勾选权限（角色固定为学生 / 教师 / 管理员三类）
- 密码找回、账号资料修改
- 账号类型变更（注册时确认，注册后不可变更；授予管理员角色不改主身份）
- 账号审核、封禁
- 教务系统对接
- 微信以外的第三方登录 provider、手机号 / 短信验证码登录、Passkey / TOTP 二次验证
- 按 OAuth 邮箱静默合并账号；OAuth 未绑定账号一律走引导注册或已登录绑定
- 试讲、评测、作业等教学数据（后续模块）

## 2. 角色

| 角色 | 说明 |
|---|---|
| 学生 | 自助注册；归属某校、某年级、某专业、某班级 |
| 教师 | 自助注册；归属某校与一个或多个专业；不绑定年级 |
| 管理员 | 自助注册；创建并绑定一所学校；维护本校学校 / 专业 / 班级数据；可修改本校教师专业范围；课程管理见 M2 |
| 初始化 / 部署 | 无独立平台角色；管理员通过注册产生，首个管理员自行创建学校 |

## 3. 核心概念

### 3.1 数据对象

| 对象 | 关键字段 | 说明 |
|---|---|---|
| 学校 | school_id、名称、admin_account_id | 管理员创建；与管理员一对一 |
| 专业 | major_id、school_id、名称 | 属于学校；管理员维护 |
| 班级 | class_id、school_id、major_id、年级、班名 | 属于学校与专业；管理员维护 |
| 账号 | account_id、用户名、密码、email、email_verified_at、account_type_id、school_id | account_id 系统生成；用户名即真实姓名、平台内唯一；email 可空、平台内唯一（大小写不敏感），验证后才可用于登录；`account_type_id` 是**主身份**，注册时确认、注册后不可变更，决定档案类型；未建校管理员的 school_id 为空 |
| 账号角色 AccountRole | account_id、role_code、granted_by、created_at | **授权角色集合**，一个账号可有多行（教师兼管理员）；主身份角色随账号创建自动写入；`role_code` 取 `account_types.code`；授权判定取各角色权限的并集 |
| 第三方身份 OAuthIdentity | id、account_id、provider、provider_user_id、union_id、email、nickname、avatar_url、created_at、last_login_at | 一个账号可绑定多个 provider；同一 provider 的 provider_user_id 全局唯一；provider 只存稳定 ID，不存 access token / secret |
| 邮箱登录验证码 EmailLoginCode | id、email、code_hash、purpose、expires_at、attempts、consumed_at、request_ip、created_at | 只存哈希；5 分钟有效、单次使用、最多 5 次尝试；不保存明文验证码 |
| 登录审计 AuthLoginEvent | id、account_id（可空）、**event_type**、method、provider、success、ip、user_agent、created_at | `event_type` 区分 `login` / `bind` / `unbind`；`method` 为 `password` / `email` / `wechat`；供安全审计，不含 token / 验证码 |
| 学生档案 | account_id、class_id | 年级、专业由班级带出，不单独冗余存储 |
| 教师档案 | account_id、school_id | 不绑定年级；专业归属见教师专业 |
| 教师专业 | account_id、major_id、状态（有效 / 失效）、生效时间、失效时间 | 教师可归属多个专业；至少一个有效；变更时旧关系标记失效并保留历史 |
| 管理员档案 | account_id、school_id | 与学校一对一；建校后写入 |
| 班级成员 | class_id、student_account_id | 一个学生归属一个班级 |
| 认证 token | account_id、**roles**（数组）、account_type（主身份）、school_id、exp、iat、jti | JWT / JWS，不落库；`roles` 是授权依据，`account_type` 仅表示主身份 |

### 3.2 关系

- 管理员与学校一对一：一个管理员创建并管理一所学校；一所学校只有一个管理员。
- 一所学校包含多个专业与多个班级；一个班级属于一个专业、一个年级。
- 一个学生归属一个班级；年级指入学年级 / 届别（如 2024 级），由班级记录。
- 教师归属一所学校与一个或多个专业；不绑定年级。教师专业关系保留变更历史。
- 学校、专业、班级由管理员维护，其他角色只读。
- M2 的课程与老师组引用本模块的学校、专业、账号与教师专业；班级仅作为拉人时的只读来源，不形成课程-班级关系。

## 4. 已确认的业务规则

1. 学生、教师、管理员均自助注册，注册时选择并确认账号类型，注册后不可变更；不做身份审核。
2. 用户名即真实姓名，平台内唯一；重名时由用户加区分后缀；登录使用用户名与密码。
3. 账号 ID 由系统生成，平台内唯一，个人资料中展示。
4. 管理员与学校一对一：管理员注册后创建一所学校并绑定，之后只能管理本校数据。
5. 管理员创建并维护本校学校信息，导入 / 维护本校专业、班级。
6. 学生注册填写学校、年级、专业，系统匹配班级；匹配到多个班时由学生自选；没有匹配班级则注册无法完成（默认）。
7. 年级指入学年级 / 届别，由后台导入的班级确定；学生从已有选项中选择，不手工输入。
8. 教师注册绑定学校，并选择一个或多个本校专业；不绑定年级。
9. 认证使用 JWT / JWS；token 带 account_id、**roles（授权角色数组）**、account_type（主身份）、school_id；接口按角色集合的权限并集与学校范围授权。
10. 管理员不管理其他账号，但可修改本校教师的专业范围、给本校教师授予 / 撤销管理员角色；学生 / 教师账号自助注册。
11. 学校、专业、班级属于本模块；课程、老师组、选课属于 M2。
12. 登录方式：用户名 + 密码、邮箱验证码、微信开放平台扫码；三种方式签发同一套 JWT claims，不改变角色与学校范围。
13. 邮箱验证码只用于登录已绑定并验证邮箱的账号；未绑定邮箱的账号不可用验证码登录，需先登录后绑定。
14. 微信扫码 P0 **以服务端 Mock provider 验收**（覆盖扫码 → 回调 → ticket → 登录 / 引导注册全链路）；真实微信开放平台 PC 扫码（`snsapi_login`）需企业主体资质与认证费，**不在本轮范围**，接口按 `OAuthProvider` 端口保留以便后续替换。已绑定的微信身份直接登录，未绑定身份进入 OAuth 引导注册，不静默创建账号。
15. OAuth 引导注册必须补齐 M1 注册所需的账号类型、学校、专业 / 班级等信息；账号创建与微信身份绑定在同一事务内完成。
16. 已登录账号可绑定 / 解绑邮箱与微信；绑定前必须重新验证邮箱验证码或当前密码（默认要求当前密码 + 验证码）；一个邮箱 / 一个微信身份只能绑定一个账号。
17. 邮箱验证码与 OAuth state / ticket 均一次性使用；验证码只存哈希，OAuth access token / secret 不落库、不返回前端。
18. 所有登录方式失败统一提示，不泄露账号、邮箱或微信身份是否存在；登录成功 / 失败写入审计事件。
19. 一个账号可拥有多个角色：`account_type_id` 是主身份（注册时确认、不可变更），`account_roles` 是授权角色集合（可叠加）。管理员可给本校教师授予 / 撤销 `admin` 角色，授权判定取并集；角色随 JWT 下发，变更后需重新登录生效。

## 5. 功能需求

### FR-M1-01 注册（P0）

- 学生、教师、管理员共用注册入口，注册时必须选择并确认账号类型；注册成功后账号类型不可变更。
- 不提供账号类型切换接口或管理入口；选错类型需重新注册。
- 用户名即真实姓名，平台内唯一；重名时由用户自行加区分后缀（默认）。密码由用户设定并加密存储。
- 系统生成全局唯一账号 ID，注册成功后展示。
- 学生必填：学校、年级、专业；教师必填：学校、一个或多个专业；管理员注册时不需要学校，登录后创建。
- 异常：账号类型缺失 / 非法、用户名已占用、必填项缺失、密码不符合规则、所选学校不存在、教师所选学校未导入专业时阻止提交并提示；注册后修改账号类型一律拒绝。

### FR-M1-02 登录与会话（P0）

- 支持用户名 + 密码、邮箱验证码、微信扫码三种登录方式，登录后按角色进入对应首页；邮箱 / 微信登录见 FR-M1-09 / FR-M1-10。
- 登录成功签发 JWT / JWS；token 包含 account_id、role、school_id、exp、iat、jti。
- 客户端通过 `Authorization: Bearer <token>` 携带 token；服务端验签、验过期、校验角色。
- 默认使用 HS256 和环境变量密钥；token 有效期 2 小时；本轮不做 refresh token。
- 登出由客户端丢弃 token；本轮不做服务端吊销。
- 管理员未建校时 token 中 school_id 为空，只能访问创建学校相关接口。
- 管理员创建学校成功后，服务端在响应中返回新的 token（school_id 已写入），客户端替换旧 token，不要求重新登录。
- 异常：用户名或密码错误统一提示；token 无效 / 过期返回 401；角色不符或跨校访问返回 403。

### FR-M1-03 管理员创建学校与绑定（P0）

- 未绑定学校的管理员可以创建一所学校，填写学校名称；创建成功后管理员与学校一对一绑定。
- 绑定后管理员不能创建第二所学校，也不能管理其他学校。
- 学校名称平台内唯一（默认）。
- 创建成功后在响应中返回新 token，管理员无需重新登录即可继续维护本校数据。
- 异常：管理员已绑定学校、名称为空或重复时阻止创建。

### FR-M1-04 学校 / 专业 / 班级维护（管理员，P0）

- 管理员可创建、导入、编辑本校的学校信息、专业、班级。
- 导入支持 CSV / Excel；按自然键幂等更新（学校；学校内专业；专业 + 年级 + 班名），整批事务导入，任一行失败则整批回滚。
- 提供重复、缺失、跨校引用校验。
- 专业 / 班级采用停用而非物理删除：停用后不再出现在新注册、新建课程的可选项中，已有学生与课程关系保留。
- 班级已有学生时，专业、年级不可修改；空班级可以修改（默认）。
- 非管理员角色对学校、专业、班级只读，平台不提供增删改入口。

### FR-M1-05 学生归属与班级匹配（P0）

- 学生注册填写学校、年级、专业后，系统查询该校该年级该专业的班级。
- 恰好一个：自动入班；多个：列出班级由学生选择；没有：提示联系学校，注册无法完成（默认）。
- 班级数据只读，学生不能自行改班。

### FR-M1-06 教师归属（P0）

- 教师注册时选择学校，并选择一个或多个本校专业；不绑定年级。
- 教师本人不能修改自己的专业范围；管理员可修改本校教师的专业范围（见 FR-M1-08）。
- 一个教师可参与多个年级、多个专业的课程；其专业范围决定可创建和加入的课程（在 M2 中体现）。

### FR-M1-07 接口授权与学校范围（P0）

- 公开接口：注册、密码 / 邮箱验证码登录、邮箱验证码发送、微信扫码 / 回调 / 状态 / exchange、OAuth 引导注册、注册时使用的学校 / 专业 / 年级选项查询。
- 学生：访问本人档案、班级信息与选课所需基础数据。
- 教师：访问本人档案与本校基础数据。
- 管理员：维护本校学校 / 专业 / 班级；修改本校教师专业范围；未建校时仅可访问创建学校相关接口。
- 所有受保护接口需要有效 token；跨校访问一律拒绝。
- 课程级权限（老师组、选课）在 M2 中定义。

### FR-M1-08 管理员修改教师专业范围（P0）

- 管理员可修改本校教师的专业范围；教师本人不能修改自己的专业范围。
- 专业范围至少保留一个有效专业，且必须是本校启用状态的专业。
- 修改时旧的专业关系标记为失效并保留历史，新关系生效；不物理删除历史记录。
- 管理员的学校范围限制同样适用：只能修改本校教师，跨校操作拒绝。
- 教师专业范围变更后，已有的课程老师组成员关系保留；新建课程、加入老师组按修改后的专业范围校验。
- 异常：教师不属于本校、没有有效专业、专业已停用、跨校操作时拒绝。

### FR-M1-09 邮箱验证码登录（P0）

- 账号可在登录后绑定邮箱；绑定前必须通过邮箱验证码验证，邮箱平台内唯一（大小写不敏感）。
- 登录页提供“邮箱验证码登录”：输入邮箱 → 发送验证码 → 输入验证码 → 登录。
- 验证码 6 位数字，5 分钟有效，单次使用；服务端只存 HMAC / 哈希，不存明文。
- 重发间隔 60 秒；同一邮箱 5 次 / 小时、同一 IP 20 次 / 小时（默认）；超过限流返回 429。
- 同一验证码最多尝试 5 次；发送新码后旧码失效。
- 仅已绑定并验证邮箱的账号可登录；未绑定、邮箱不存在、验证码错误统一返回 `UNAUTHORIZED`，不泄露账号是否存在。
- 登录成功签发与密码登录相同的 JWT；账号被停用 / 不存在 / 邮箱未验证均拒绝。
- 绑定 / 换绑邮箱：登录用户发送验证码 → 校验 → 写入 `email` + `email_verified_at`；换绑需当前密码（默认）并再次验证；解绑需当前密码，解绑后不能再用邮箱登录。
- 异常：邮箱格式非法、邮箱已绑定其他账号（409，统一文案）、验证码过期 / 错误 / 尝试超限、邮件服务不可用（503，不改变账号状态）。

### FR-M1-10 微信开放平台扫码登录（P0）

- 登录页提供“微信扫码登录”；P0 只支持微信开放平台 PC 扫码 `snsapi_login`，不接公众号 / 小程序。
- 前端请求生成一次性 `state` 与服务端授权 URL / 二维码内容；`state` 5 分钟有效、单次使用。
- 用户在微信扫码确认后，微信回调服务端；服务端校验 `state`，用授权码换取 `openid` / `unionid` 与用户信息；access token 不落库、不返回前端。
- 已绑定微信身份 → 服务端生成一次性 `login_ticket`（5 分钟），前端用 ticket 换取 JWT。
- 未绑定微信身份 → 生成一次性 `registration_ticket`，进入 FR-M1-11 的 OAuth 引导注册；不静默创建账号。
- 微信昵称 / 头像只作为展示资料，不作为登录唯一标识；登录标识为 `provider + provider_user_id`（优先使用 unionid 关联同一开放平台账号）。
- 前端轮询扫码状态，支持 `pending / scanned / authorized / needs_registration / expired / failed`；二维码过期可刷新。
- 异常：state 过期 / 重放、微信回调失败、provider 不可用、ticket 过期 → 统一失败，不创建账号、不签发 JWT；网络 / 微信服务不可用返回 503。

### FR-M1-11 OAuth 引导注册与账号绑定（P0）

- OAuth 未绑定用户进入引导注册页，必须选择账号类型（学生 / 教师 / 管理员），并补齐对应注册必填项：
  - 学生：学校、年级、专业、班级匹配；
  - 教师：学校、一个或多个本校专业；
  - 管理员：注册时不需要学校，登录后进入建校流程。
- 引导注册必须设置用户名（真实姓名）、密码与可选邮箱；用户名、邮箱唯一性按 FR-M1-01 / FR-M1-09 校验。密码用于密码登录、绑定 / 解绑校验。
- 账号创建与 `oauth_identities` 绑定在同一事务内；任一步失败则整个注册回滚，ticket 不消耗（或标记失败）。
- 已登录账号可在账号设置中绑定 / 解绑微信与邮箱；绑定前必须重新验证（当前密码 + 邮箱验证码 / 微信扫码），解绑需当前密码。
- 一个 `provider_user_id` 只能绑定一个账号；一个账号同一 provider 只保留一个有效绑定；重复绑定返回 409，不泄露其他账号信息。
- 绑定 / 解绑写审计事件（依赖 `auth_login_events` 增加 `event_type` 列以区分 `login` / `bind` / `unbind`，见 `design/12` §3.1 与 V15）。
- 解绑最后一个登录方式：本轮账号必有密码（注册即设置、不支持清空），该场景**不可达**；若后续支持清空密码，须补「至少保留一种可用登录方式（密码 / 邮箱 / 微信）」校验，否则拒绝。
- 异常：ticket 过期 / 已使用、账号类型缺失、学校 / 专业 / 班级无效、用户名或邮箱冲突、微信身份已绑定其他账号；解绑唯一登录方式在「密码必有」模型下不可达。

### FR-M1-12 多角色：教师叠加管理员权限（P0）

- 一个账号可拥有多个角色。`account_type` 是**主身份**（注册时确认、不可变更，决定建立哪种档案），`account_roles` 是**授权角色集合**，接口授权取各角色权限的并集。
- 管理员可在「教师管理」中为本校教师**授予 / 撤销管理员角色**。授予后该教师同时保有教师功能（课程、任务、评测）与管理端功能；撤销后恢复为纯教师。
- 只能操作本校教师；不能给学生授予管理员角色；不能修改自己的角色（防自助提权与自锁）。
- 本接口**不改变主身份**：教师被授予管理员后仍只有教师档案，不新建 `school_admins` 记录；其学校归属沿用 `accounts.school_id`。
- 角色随 JWT 的 `roles` claim 下发，因此被授予 / 撤销的账号**需重新登录**才生效；未重新登录期间旧 token 权限不变（与「无 refresh token、token 即权限快照」一致）。
- 管理员账号要获得教师身份不在本轮范围：缺少教师档案与专业归属，需另立需求。
- 异常：目标非本校教师 → 403 `CROSS_SCHOOL_ACCESS`；目标非教师或操作自己 → 400 `VALIDATION_ERROR`；无 `admin:roles` 权限 → 403 `FORBIDDEN`。

## 6. 主要流程

### 6.1 管理员初始化

1. 管理员自助注册，填写用户名、密码。
2. 登录，创建学校并绑定；服务端返回新 token，客户端替换。
3. 导入 / 维护本校专业、班级。
4. 按需修改本校教师的专业范围。

### 6.2 学生注册

1. 选择学生身份注册，填写用户名、密码、学校、年级、专业。
2. 系统匹配班级；匹配到多个时由学生选择。
3. 系统生成账号 ID，注册完成。

### 6.3 教师注册

1. 选择教师身份注册，填写用户名、密码、学校，选择一个或多个本校专业。
2. 系统生成账号 ID，注册完成。

### 6.4 登录认证

1. 用户使用用户名 + 密码登录。
2. 服务端签发 JWT / JWS。
3. 客户端每次请求携带 Bearer token。
4. 服务端验签、验过期，按角色与学校范围放行。

### 6.5 邮箱验证码登录

1. 用户输入邮箱，请求发送验证码；服务端统一返回 202，不提示邮箱是否存在。
2. 服务端生成 6 位验证码，保存哈希与过期时间，异步发送邮件。
3. 用户输入验证码；服务端按邮箱查找已绑定并验证的账号，校验验证码。
4. 校验通过后签发 JWT；失败统一提示，不区分邮箱 / 验证码错误。

### 6.6 微信扫码登录

1. 登录页请求生成 `state` 与微信授权 URL / 二维码，展示二维码并开始轮询。
2. 用户微信扫码确认；微信回调服务端，服务端校验 state 并换取 openid / unionid。
3. 已绑定：生成 `login_ticket`，前端用 ticket 换取 JWT。
4. 未绑定：生成 `registration_ticket`，跳转 OAuth 引导注册（6.7）。
5. 二维码过期 / 取消 / 失败：停止轮询，允许刷新重试。

### 6.7 OAuth 引导注册

1. 未绑定微信用户进入引导注册页，选择账号类型并补齐学校 / 专业 / 班级 / 用户名等信息。
2. 服务端校验注册信息与 ticket，创建账号并绑定微信身份（同一事务）。
3. 注册成功自动登录并签发 JWT；管理员未建校时进入建校流程。
4. ticket 已使用 / 过期 / 信息非法时阻止提交，要求重新扫码。

## 7. 权限矩阵

| 操作 | 学生 | 教师 | 管理员 |
|---|---|---|---|
| 注册 / 登录 | 可 | 可 | 可 |
| 邮箱验证码登录 | 可（已绑定邮箱） | 可（已绑定邮箱） | 可（已绑定邮箱） |
| 微信扫码登录 / OAuth 引导注册 | 可 | 可 | 可 |
| 绑定 / 解绑邮箱 / 微信 | 可（本人） | 可（本人） | 可（本人） |
| 创建学校（未绑定） | — | — | 可 |
| 维护本校学校 / 专业 / 班级 | — | — | 可 |
| 查看本校基础数据 | 可（注册 / 本人） | 可 | 可 |
| 学生班级匹配 | 可（本人） | — | — |
| 管理其他账号（专业范围除外） | — | — | 不可 |
| 修改本校教师专业范围 | — | 不可（本人） | 可 |

## 8. 异常与边界

- 用户名重复：阻止注册，提示在用户名后加区分后缀（用户名即真实姓名）。
- 密码不符合规则、必填项缺失：阻止注册。
- 学校不存在：学生 / 教师注册时阻止提交。
- 教师所选学校未导入专业：阻止注册并提示联系管理员。
- 管理员已绑定学校再创建学校：拒绝。
- 管理员未建校访问其他管理接口：拒绝，仅允许创建学校。
- 无匹配班级：提示联系学校，注册无法完成（默认）。
- 多个匹配班级：学生必须选择其一后才能完成注册。
- 专业 / 班级停用：不再出现在新注册、新建课程的可选项中，已有学生 / 课程关系保留。
- 班级已有学生时修改专业 / 年级：阻止。
- 管理员修改教师专业范围：教师不属于本校、专业为空或已停用、跨校操作时拒绝。
- 学校名称重复：拒绝创建（默认）。
- token 无效 / 过期：401；角色不符或跨校访问：403。
- 邮箱验证码：邮箱未绑定 / 不存在、验证码错误 / 过期 / 超限统一 `UNAUTHORIZED`；发送过频 429；邮件服务不可用 503。
- 邮箱重复绑定：返回 409 统一文案，不透露已绑定账号；换绑 / 解绑缺少当前密码或验证码时拒绝。
- 微信扫码：state / ticket 过期、重放、已使用、provider 失败统一登录失败；未绑定身份不自动创建账号。
- OAuth 引导注册：账号类型缺失、学校 / 专业 / 班级无效、用户名或邮箱冲突、微信身份已绑定其他账号时整笔回滚。
- 解绑最后一个登录方式：本轮账号必有密码（注册即设置、不支持清空），解绑邮箱 / 微信后仍保留密码登录；若后续支持清空密码，须拒绝并提示先设置密码 / 绑定其他方式。
- 所有登录失败响应不区分账号 / 邮箱 / 微信身份是否存在；审计记录保留内部原因。
- 角色授予：目标非本校教师 403；目标非教师（学生 / 管理员）或操作自己 400；无 `admin:roles` 权限 403。撤销后旧 token 在过期前仍保留原权限（最长 2 小时），重新登录即失效。

## 9. 验收要点

1. 管理员自助注册 → 登录 → 创建学校 → 导入专业 / 班级，绑定后只能管理本校。
2. 学生使用管理员导入的学校 / 年级 / 专业注册，并匹配到班级。
3. 教师注册时选择学校和一个或多个专业，不绑定年级。
4. 登录成功签发 JWT / JWS，受保护接口校验 token、角色与学校范围。
5. 一个管理员只能有一所学校，不能管理其他学校。
6. 非管理员无法修改学校 / 专业 / 班级。
7. 专业 / 班级停用后不再出现在新注册、新建课程选项中，已有关系保留；已有学生的班级不能改专业 / 年级。
8. 管理员可修改本校教师专业范围；教师本人不能修改；旧专业关系失效但保留历史；已有老师组关系保留。
9. 注册时必须选择并确认账号类型，注册后不可变更；平台不提供类型切换入口，选错类型需重新注册。
10. 绑定邮箱后可只用邮箱验证码登录；验证码 5 分钟有效、单次使用、重发 / 尝试限流，错误不泄露邮箱是否存在。
11. 微信扫码已绑定账号可直接登录；未绑定账号进入引导注册，补齐账号类型与学校 / 专业 / 班级后创建账号并绑定。（本轮以 Mock provider 验收，真实开放平台不接）
12. 同一微信身份不能绑定多个账号；绑定 / 解绑需重新验证；解绑最后一个登录方式在「密码必有」模型下不可达（保留该校验的语义约束）。
13. 三种登录方式签发的 JWT claims、有效期、角色 / 学校范围一致；所有登录失败不泄露账号存在性。
14. 管理员可给本校教师授予管理员角色：该教师重新登录后既能用教师功能，也能进管理端；撤销后重新登录即失去管理端访问；不能授予学生、不能跨校、不能修改自己的角色。
