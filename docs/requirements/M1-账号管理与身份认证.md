## 1. 范围

### 1.1 本轮实现

- 学生、教师、管理员自助注册与登录；注册时选择并确认账号类型，注册后不可变更
- JWT / JWS 认证、token 校验与会话
- 账号 ID、用户名、密码、账号类型、学校归属；账号类型注册后不可变更
- 管理员与学校一对一；管理员创建并绑定学校
- 学校、专业、班级的创建 / 导入 / 维护（管理员）
- 学生学校、年级、专业归属与班级匹配、入班
- 教师学校、专业归属（可多专业）
- 管理员修改本校教师的专业范围
- 接口级角色与学校范围授权

### 1.2 本轮不做

- 课程创建、老师组、选课等课程功能（见 M2）
- 跨校账号、跨校管理员
- 管理员管理其他账号（仅修改本校教师专业范围除外）
- 密码找回、账号资料修改
- 账号类型变更（注册时确认，注册后不可变更）
- 账号审核、封禁
- 教务系统对接
- 试讲、评测、作业等教学数据（后续模块）

## 2. 角色

| 角色 | 说明 |
|---|---|
| 学生 | 自助注册；归属某校、某年级、某专业、某班级 |
| 教师 | 自助注册；归属某校与一个或多个专业；不绑定年级 |
| 管理员 | 自助注册；创建并绑定一所学校；维护本校学校 / 专业 / 班级数据；可修改本校教师专业范围；课程管理见 M2 |
| 初始化 / 部署 | 无独立平台角色；管理员通过注册产生，首个管理员自行创建学校 |

## 3. 核心概念

### 3.1 数据对象

| 对象 | 关键字段 | 说明 |
|---|---|---|
| 学校 | school_id、名称、admin_account_id | 管理员创建；与管理员一对一 |
| 专业 | major_id、school_id、名称 | 属于学校；管理员维护 |
| 班级 | class_id、school_id、major_id、年级、班名 | 属于学校与专业；管理员维护 |
| 账号 | account_id、用户名、密码、account_type_id、school_id | account_id 系统生成；用户名即真实姓名、平台内唯一；账号类型注册时确认，注册后不可变更；未建校管理员的 school_id 为空 |
| 学生档案 | account_id、class_id | 年级、专业由班级带出，不单独冗余存储 |
| 教师档案 | account_id、school_id | 不绑定年级；专业归属见教师专业 |
| 教师专业 | account_id、major_id、状态（有效 / 失效）、生效时间、失效时间 | 教师可归属多个专业；至少一个有效；变更时旧关系标记失效并保留历史 |
| 管理员档案 | account_id、school_id | 与学校一对一；建校后写入 |
| 班级成员 | class_id、student_account_id | 一个学生归属一个班级 |
| 认证 token | account_id、role、school_id、exp、iat、jti | JWT / JWS，不落库 |

### 3.2 关系

- 管理员与学校一对一：一个管理员创建并管理一所学校；一所学校只有一个管理员。
- 一所学校包含多个专业与多个班级；一个班级属于一个专业、一个年级。
- 一个学生归属一个班级；年级指入学年级 / 届别（如 2024 级），由班级记录。
- 教师归属一所学校与一个或多个专业；不绑定年级。教师专业关系保留变更历史。
- 学校、专业、班级由管理员维护，其他角色只读。
- M2 的课程与老师组引用本模块的学校、专业、账号与教师专业；班级仅作为拉人时的只读来源，不形成课程-班级关系。

## 4. 已确认的业务规则

1. 学生、教师、管理员均自助注册，注册时选择并确认账号类型，注册后不可变更；不做身份审核。
2. 用户名即真实姓名，平台内唯一；重名时由用户加区分后缀；登录使用用户名与密码。
3. 账号 ID 由系统生成，平台内唯一，个人资料中展示。
4. 管理员与学校一对一：管理员注册后创建一所学校并绑定，之后只能管理本校数据。
5. 管理员创建并维护本校学校信息，导入 / 维护本校专业、班级。
6. 学生注册填写学校、年级、专业，系统匹配班级；匹配到多个班时由学生自选；没有匹配班级则注册无法完成（默认）。
7. 年级指入学年级 / 届别，由后台导入的班级确定；学生从已有选项中选择，不手工输入。
8. 教师注册绑定学校，并选择一个或多个本校专业；不绑定年级。
9. 认证使用 JWT / JWS；token 带 account_id、account_type、school_id；接口按账号类型和学校范围授权。
10. 管理员不管理其他账号，但可修改本校教师的专业范围；学生 / 教师账号自助注册。
11. 学校、专业、班级属于本模块；课程、老师组、选课属于 M2。

## 5. 功能需求

### FR-M1-01 注册（P0）

- 学生、教师、管理员共用注册入口，注册时必须选择并确认账号类型；注册成功后账号类型不可变更。
- 不提供账号类型切换接口或管理入口；选错类型需重新注册。
- 用户名即真实姓名，平台内唯一；重名时由用户自行加区分后缀（默认）。密码由用户设定并加密存储。
- 系统生成全局唯一账号 ID，注册成功后展示。
- 学生必填：学校、年级、专业；教师必填：学校、一个或多个专业；管理员注册时不需要学校，登录后创建。
- 异常：账号类型缺失 / 非法、用户名已占用、必填项缺失、密码不符合规则、所选学校不存在、教师所选学校未导入专业时阻止提交并提示；注册后修改账号类型一律拒绝。

### FR-M1-02 登录与会话（P0）

- 使用用户名 + 密码登录，登录后按角色进入对应首页。
- 登录成功签发 JWT / JWS；token 包含 account_id、role、school_id、exp、iat、jti。
- 客户端通过 `Authorization: Bearer <token>` 携带 token；服务端验签、验过期、校验角色。
- 默认使用 HS256 和环境变量密钥；token 有效期 2 小时；本轮不做 refresh token。
- 登出由客户端丢弃 token；本轮不做服务端吊销。
- 管理员未建校时 token 中 school_id 为空，只能访问创建学校相关接口。
- 管理员创建学校成功后，服务端在响应中返回新的 token（school_id 已写入），客户端替换旧 token，不要求重新登录。
- 异常：用户名或密码错误统一提示；token 无效 / 过期返回 401；角色不符或跨校访问返回 403。

### FR-M1-03 管理员创建学校与绑定（P0）

- 未绑定学校的管理员可以创建一所学校，填写学校名称；创建成功后管理员与学校一对一绑定。
- 绑定后管理员不能创建第二所学校，也不能管理其他学校。
- 学校名称平台内唯一（默认）。
- 创建成功后在响应中返回新 token，管理员无需重新登录即可继续维护本校数据。
- 异常：管理员已绑定学校、名称为空或重复时阻止创建。

### FR-M1-04 学校 / 专业 / 班级维护（管理员，P0）

- 管理员可创建、导入、编辑本校的学校信息、专业、班级。
- 导入支持 CSV / Excel；按自然键幂等更新（学校；学校内专业；专业 + 年级 + 班名），整批事务导入，任一行失败则整批回滚。
- 提供重复、缺失、跨校引用校验。
- 专业 / 班级采用停用而非物理删除：停用后不再出现在新注册、新建课程的可选项中，已有学生与课程关系保留。
- 班级已有学生时，专业、年级不可修改；空班级可以修改（默认）。
- 非管理员角色对学校、专业、班级只读，平台不提供增删改入口。

### FR-M1-05 学生归属与班级匹配（P0）

- 学生注册填写学校、年级、专业后，系统查询该校该年级该专业的班级。
- 恰好一个：自动入班；多个：列出班级由学生选择；没有：提示联系学校，注册无法完成（默认）。
- 班级数据只读，学生不能自行改班。

### FR-M1-06 教师归属（P0）

- 教师注册时选择学校，并选择一个或多个本校专业；不绑定年级。
- 教师本人不能修改自己的专业范围；管理员可修改本校教师的专业范围（见 FR-M1-08）。
- 一个教师可参与多个年级、多个专业的课程；其专业范围决定可创建和加入的课程（在 M2 中体现）。

### FR-M1-07 接口授权与学校范围（P0）

- 公开接口：注册、登录、注册时使用的学校 / 专业 / 年级选项查询。
- 学生：访问本人档案、班级信息与选课所需基础数据。
- 教师：访问本人档案与本校基础数据。
- 管理员：维护本校学校 / 专业 / 班级；修改本校教师专业范围；未建校时仅可访问创建学校相关接口。
- 所有受保护接口需要有效 token；跨校访问一律拒绝。
- 课程级权限（老师组、选课）在 M2 中定义。

### FR-M1-08 管理员修改教师专业范围（P0）

- 管理员可修改本校教师的专业范围；教师本人不能修改自己的专业范围。
- 专业范围至少保留一个有效专业，且必须是本校启用状态的专业。
- 修改时旧的专业关系标记为失效并保留历史，新关系生效；不物理删除历史记录。
- 管理员的学校范围限制同样适用：只能修改本校教师，跨校操作拒绝。
- 教师专业范围变更后，已有的课程老师组成员关系保留；新建课程、加入老师组按修改后的专业范围校验。
- 异常：教师不属于本校、没有有效专业、专业已停用、跨校操作时拒绝。

## 6. 主要流程

### 6.1 管理员初始化

1. 管理员自助注册，填写用户名、密码。
2. 登录，创建学校并绑定；服务端返回新 token，客户端替换。
3. 导入 / 维护本校专业、班级。
4. 按需修改本校教师的专业范围。

### 6.2 学生注册

1. 选择学生身份注册，填写用户名、密码、学校、年级、专业。
2. 系统匹配班级；匹配到多个时由学生选择。
3. 系统生成账号 ID，注册完成。

### 6.3 教师注册

1. 选择教师身份注册，填写用户名、密码、学校，选择一个或多个本校专业。
2. 系统生成账号 ID，注册完成。

### 6.4 登录认证

1. 用户使用用户名 + 密码登录。
2. 服务端签发 JWT / JWS。
3. 客户端每次请求携带 Bearer token。
4. 服务端验签、验过期，按角色与学校范围放行。

## 7. 权限矩阵

| 操作 | 学生 | 教师 | 管理员 |
|---|---|---|---|
| 注册 / 登录 | 可 | 可 | 可 |
| 创建学校（未绑定） | — | — | 可 |
| 维护本校学校 / 专业 / 班级 | — | — | 可 |
| 查看本校基础数据 | 可（注册 / 本人） | 可 | 可 |
| 学生班级匹配 | 可（本人） | — | — |
| 管理其他账号（专业范围除外） | — | — | 不可 |
| 修改本校教师专业范围 | — | 不可（本人） | 可 |
| 跨校数据 | 不可 | 不可 | 不可 |

## 8. 异常与边界

- 用户名重复：阻止注册，提示在用户名后加区分后缀（用户名即真实姓名）。
- 密码不符合规则、必填项缺失：阻止注册。
- 学校不存在：学生 / 教师注册时阻止提交。
- 教师所选学校未导入专业：阻止注册并提示联系管理员。
- 管理员已绑定学校再创建学校：拒绝。
- 管理员未建校访问其他管理接口：拒绝，仅允许创建学校。
- 无匹配班级：提示联系学校，注册无法完成（默认）。
- 多个匹配班级：学生必须选择其一后才能完成注册。
- 专业 / 班级停用：不再出现在新注册、新建课程的可选项中，已有学生 / 课程关系保留。
- 班级已有学生时修改专业 / 年级：阻止。
- 管理员修改教师专业范围：教师不属于本校、专业为空或已停用、跨校操作时拒绝。
- 学校名称重复：拒绝创建（默认）。
- token 无效 / 过期：401；角色不符或跨校访问：403。

## 9. 验收要点

1. 管理员自助注册 → 登录 → 创建学校 → 导入专业 / 班级，绑定后只能管理本校。
2. 学生使用管理员导入的学校 / 年级 / 专业注册，并匹配到班级。
3. 教师注册时选择学校和一个或多个专业，不绑定年级。
4. 登录成功签发 JWT / JWS，受保护接口校验 token、角色与学校范围。
5. 一个管理员只能有一所学校，不能管理其他学校。
6. 非管理员无法修改学校 / 专业 / 班级。
7. 专业 / 班级停用后不再出现在新注册、新建课程选项中，已有关系保留；已有学生的班级不能改专业 / 年级。
8. 管理员可修改本校教师专业范围；教师本人不能修改；旧专业关系失效但保留历史；已有老师组关系保留。
9. 注册时必须选择并确认账号类型，注册后不可变更；平台不提供类型切换入口，选错类型需重新注册。
