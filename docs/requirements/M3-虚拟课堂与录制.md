## 1. 范围

### 1.1 本轮实现

- 教师创建试讲任务，按发布时的在课学生快照分配
- 自由试讲、情景模拟两种虚拟课堂模式
- 结构化面试模式：本校题库手动选题、考官文字提问、考生语音回答
- 虚拟学生配置：最多 30 人，默认 3 人；每人独立参数 + 个性文本
- 虚拟学生文字问答、多轮对话、正确性标记
- 教师提问语音识别：高置信自动进入问答，低置信只提示，手动按钮始终可用
- 课堂纪律状态模型：注意力衰减、概率触发、教师管理动作
- 共享外部窗口（PPT / PDF / 白板）+ 录屏 + OCR + 实时转写
- 录制人像、麦克风、共享窗口；云端存档、回放
- 多次试讲、选一次提交、只保留提交件
- WebSocket 实时事件、状态机、时间 tick
- 控制 WebSocket 断线 30 秒 grace 与重连快照（页面仍存活且录制状态正常时）
- 任务配置快照与 M3→M4 数据契约

### 1.2 本轮不做

- 教姿教态与普通话评测（M4 也不做）
- 说名字点名、虚拟学生自主举手、自动点名 / 自动回答、自动评价、自动结束对话、教师追问驱动的多轮问答（后续 A 阶段，见 §6）
- 按时间点硬触发的剧本事件（C）
- 页面刷新 / 浏览器崩溃 / Java 重启后的会话恢复；录制断点续传
- 直播、教师在线观摩、实时指导
- 本地保存录像
- 任务按班级 / 个人定向（对象为发布时课程在课学生快照）
- 任务关闭后重开
- 平台内置 PPT / PDF 渲染器或白板编辑器
- 课程外自由开试讲
- 示范片段、TTS 语音示范

## 2. 角色与依赖

| 角色 | 说明 |
|---|---|
| 学生 | 课程在课学生；接收任务、试讲、回看、提交；只能看自己的录像与报告 |
| 教师 | 课程老师组；创建任务、配置虚拟学生与权重、关闭任务、查看提交录像与报告 |
| 管理员 | 不参与 M3；学校、专业、班级、课程维护在 M1 / M2 |
| 系统 | 任务调度、状态机、WebSocket 推送、录制与事件落库 |

- M1 提供账号、角色、学校、专业、班级、教师专业。
- M2 提供课程、课程老师组、学生有效关系、课程专业范围。
- M5 提供本校结构化面试题库；M3 只读题库，教师手动选题，发布时把题干与答案要点写入配置快照。
- M6 训练模式复用本模块课堂、录制与事件；训练 session 不属于课程任务，权限按 M6。
- M7 读取本模块的任务、任务分配快照、提交件与配置快照，用于教师评分与统计；M3 不依赖 M7。
- M3 产出 session、录像、转写、OCR 帧、事件日志，供 M4 消费。
- 实时通信使用 WebSocket；任务、提交、回放查询使用 REST。

## 3. 核心概念

### 3.1 数据对象

| 对象 | 关键字段 | 说明 |
|---|---|---|
| 试讲任务 Task | task_id、course_id、mode、topic、textbook_version、reference_material、scenario_config、virtual_student_config、duration_recommended、duration_max、rubric_weights、question_config、config_snapshot、config_version、status、created_by、published_at、closed_at | 课程老师组创建；发布时锁定配置并生成快照 |
| 任务分配 TaskAssignment | task_id、student_account_id、assigned_at、status | 发布时按课程在课学生快照生成；后加入学生不自动纳入 |
| 虚拟学生配置 VirtualStudent | virtual_student_id、task_id、name、avatar、personality_text、activity、question_rate、ability、attention_baseline、discipline_probability | 参数 0—1；默认全部 0.5 |
| 试讲会话 Session | session_id、session_type（task / training）、task_id（训练可空）、course_id、student_account_id、mode、status、attempt_no、started_at、ended_at、duration、stream_offsets | 任务与训练共用；训练 session 由 M6 定义终态 |
| 提交 Submission | submission_id、task_id、student_account_id、session_id、class_id_snapshot、submitted_at、status | 每个学生每任务最多一条提交；提交时记录学生当时班级，供 M7 统计 |
| 录制 Recording | recording_id、session_id、camera_url、screen_url、audio_url、duration、status、offset_ms | 课堂模式三路；结构化面试只有人像 + 麦克风 |
| 课堂文本 SessionText | text_id、session_id、speaker_type（teacher / student / examiner / candidate）、source（asr / llm / manual）、kind、text、start_ms、end_ms、at_ms、confidence、model_version、prompt_version | 统一文本流：教师 ASR、学生 LLM、结构化面试考官 / 考生；时间使用 session 相对毫秒 |
| OCR 帧 Frame | frame_id、session_id、timestamp、text、bounding_boxes、confidence、change_score、frame_type、object_key | frame_type：normal / slide_change / final / low_confidence / chart |
| 课堂事件 Event | event_id、session_id、type、timestamp、actor、target、payload | 全部事件落库，供 M4 |
| 结构化面试题 | question_id、category、text、answer_points | 来自 M5 本校题库；任务发布时选定并写入配置快照 |

### 3.2 关系

- 一个任务对应发布时的在课学生快照（TaskAssignment）；每个学生可有多次试讲 session。
- 每个学生每任务最多一条提交；提交绑定一个 session，只保留该 session 的录像。
- 一个 session 对应一组录制、统一文本流、OCR 帧和事件。
- 任务发布时生成不可变配置快照（config_version），供 M4 复现。
- M3 依赖 M1 / M2；M4 依赖 M3，M3 不依赖 M4。

## 4. 业务规则

1. 虚拟课堂只能由教师发布的试讲任务触发；学生不能自由开课。
2. 任务对象为发布时课程在课学生快照；发布后新加入的学生不会自动获得任务。
3. 每个学生可多次试讲；每次生成临时录像；学生选一次提交，只保留提交件并送 M4，其余丢弃。
4. 提交后任务对该学生完成；教师可关闭任务，停止开始新的试讲。关闭时已在进行的会话允许完成并提交；关闭后不可重开，如需再练由教师新建任务。
5. 到达最高时长自动停止录制；学生可回看并决定提交或重做。
6. 虚拟学生最多 30 人，默认 3 人；每人五个 0—1 参数 + 个性文本；教师可单独调；试讲学生只看到姓名、头像、状态。
7. 自由试讲、情景模拟使用虚拟课堂；结构化面试使用考官界面，不用虚拟学生和板书。
8. 提问触发在 MVP 只走 B：教师点「让学生提问」/「向全班提问」，或语音高置信识别到教师提问 → 系统选 1—3 人举手（保底至少 1 人），问题预生成 → 教师点名一个，其他手放下；每个学生每次举手后降低其举手积极性并进入冷却；30 秒未点名全部放下，回讲解状态并记录事件；低置信语音只提示，不自动进入问答。
9. 学生回答：教师点「向全班提问」→ 学生举手 → 教师点名；或教师直接点学生头像点名。学生文字回答，教师点「对 / 错 / 不完整」；问答结束由教师显式点「结束问答 / 结束对话」并记录 `classroom.qa_ended`。
10. 对话可多轮：学生自己判断是否继续追问，最多 3 轮；教师可随时结束。
11. 纪律：每个学生有注意力值，随时间衰减；教师提问、点名、提醒会拉回；低注意力时按概率出现走神、小声说话、吵闹；教师点学生提醒，记录课堂管理动作。课堂状态层根据学生走神 / 小声事件统计课堂纪律等级 0—3；等级变化写 `classroom.discipline_level_changed`，仅记录 / 供 UI / 供 M4 控场维度使用，不反向驱动虚拟学生概率。
12. 情景模式只给学生设定角色 / 情境；MVP 中仍由教师按钮触发提问，角色影响问题内容和行为文本，不赋予自主触发权；A 阶段再开放自主举手。
13. 共享窗口只共享外部 PPT / PDF / 白板窗口，不共享整个桌面；平台不内置渲染器或白板编辑器；录屏只录该窗口。翻页 / 板书变化靠 OCR 和画面变化检测推断，不依赖结构化翻页事件。
14. 录音只录教师麦克风；虚拟学生用文字，不使用 TTS。
15. 结构化面试：教师从本校 M5 题库按类别筛选、手动选择 1—10 道题，可调整顺序，设置总时长 1—60 分钟（默认 2 题 / 5 分钟）；同一任务所有学生同题；发布时快照题干与答案要点；考官文字提问，考生语音回答；每题带答案要点，供 M4 内容评测。
16. 录像可见：录制学生本人 + 课程老师组；管理员不可见。
17. 所有课堂事件、时间 tick、状态变化写入 session 日志，供 M4 消费。
18. 控制 WebSocket 断线进入 30 秒 grace：session 保持 `in_progress`，`SessionActor` 与运行时状态保留；30 秒内可重新申请 ticket 并发送 `session.resume {last_seq, recording_state}` 重连，服务端补发 `last_seq` 之后的事件。`recording_state=active` 才允许恢复；页面刷新 / 浏览器崩溃 / MediaRecorder 丢失 / 30 秒超时 / Java 重启不恢复，session 标记 `failed`，学生可在任务未关闭时重做。感知 WebSocket 断线不进入 grace，只影响 ASR / OCR，录制继续，M4 标记 partial。
19. 课堂模式必须同时具备摄像头、麦克风和共享窗口三路流；任一路缺失或中断则本次不可提交，学生重做。结构化面试必须具备摄像头和麦克风。实时 ASR / OCR / LLM 故障不终止录制，但写入事件，M4 将受影响维度标为 partial。
20. 参考材料：自由试讲 / 情景模拟必须由教师导入教材原文或教案；结构化面试不需要，使用题目答案要点。参考材料供教师组和系统使用，试讲学生不可见。
21. 任务发布时生成不可变配置快照，包含参考材料解析文本、权重、结构化面试所选题目及答案要点、时长、虚拟学生配置和情景配置；M4 用快照复现。
22. 课程结束日期到达后，课程内不再允许开始新的试讲任务；已提交录像、报告与 M7 教师评分 / 最终分保留至课程结束 + 1 年（默认）。课程归档后，任务、会话、录像、报告转为只读；不能新建或开始任务；已提交的录像与报告仍可由录制学生和课程老师组查看。
23. 学生提交时写入当时班级 `class_id_snapshot`；M7 教师评分与统计优先使用该快照，学生之后转班不影响历史统计。

## 5. 功能需求

### FR-M3-01 任务创建与发布（教师，P0）

- 课程老师组任一教师可创建任务。
- 必填：课程、模式、课题 / 教材版本、推荐时长、最高时长、评分权重。
- 自由试讲 / 情景模拟：必须导入教材原文或教案，并配置虚拟学生；情景模拟可填写 `scenario_config`（角色 / 情境，可选）。
- 结构化面试：从本校 M5 题库按类别筛选、手动选择 1—10 道题、调整顺序、设置总时长 1—60 分钟（默认 2 题 / 5 分钟）；不需要教材参考。
- 权重按模式校验：自由 / 情景为五维，结构化面试为三维；各模式权重和必须为 100%。
- 发布时按课程当前在课学生生成 TaskAssignment 快照，并生成配置快照（含所选题干、答案要点、顺序、数量与时长）；发布后锁定。
- 可保存草稿；草稿不向学生可见。
- 异常：非课程老师组、课程无在课学生、权重和不为 100%、自由 / 情景参考材料缺失或解析失败、结构化面试所选题为空 / 不足 / 已停用 / 无答案要点时阻止发布。

### FR-M3-02 虚拟学生配置（教师，P0）

- 最多 30 人，默认 3 人；教师可添加、删除。
- 每个学生五个参数（0—1，UI 显示百分比）：活跃度、提问频率、能力、注意力基线、纪律概率。
- 每个学生一段个性文本，供 LLM 生成提问、回答和行为。
- 默认全部 0.5；教师可逐个调整；可预览、重新生成姓名 / 头像。
- 发布后锁定；试讲学生只看到姓名、头像和状态，看不到参数与个性文本。
- 异常：超过 30 人、参数越界、个性文本超长时阻止保存。

### FR-M3-03 学生任务列表（P0）

- 按「待开始 / 进行中 / 已提交」分组；「进行中」包含 preparing、in_progress、ended、reviewing 的未提交 session。
- 卡片展示模式、课程、老师组、推荐时长 / 最高时长、状态和入口。
- 操作：开始试讲、查看临时录像 / 重做、查看提交回放 / 评测报告。
- 已提交任务不再允许试讲；关闭任务不再允许开始新试讲。

### FR-M3-04 开始试讲与共享窗口（P0）

- 学生从任务进入，选择外部共享窗口（PPT / PDF / 白板），授权摄像头、麦克风、屏幕共享后开始录制。
- 只共享选定窗口；录屏只录该窗口，不录整个桌面。
- 课堂模式必须同时具备摄像头、麦克风、共享窗口三路流；结构化面试必须具备摄像头和麦克风。
- 任一路在开始前不可用或进行中中断，本次 session 标记 `failed`，不可提交，允许重做。
- 实时 ASR / OCR / LLM 故障不终止录制；写入事件，M4 标记受影响维度 partial。

### FR-M3-05 自由试讲 / 情景模拟课堂（P0）

- 布局 A：共享窗口主画面 + 右侧虚拟学生网格 / 名单 + 摄像头小窗 + 底部控制条。
- 实时转写教师语音，按窗口变化采样 OCR。
- 虚拟学生以文字提问和回答，显示在右侧对话面板。
- 控制条：让学生提问、向全班提问、点名、提醒、结束对话、结束试讲。
- 情景模式使用 `scenario_config` 设定角色 / 情境；MVP 仍由教师按钮触发提问，角色影响生成内容，不赋予自主触发权。

### FR-M3-06 学生提问触发（B，P0）

- 教师点「让学生提问」后，系统按注意力、活跃度、举手积极性、冷却时间选 1—3 名学生举手，保底至少 1 人；举手时预生成问题。
- 教师语音提问：ASR final 段经 Python 分类，置信度 ≥ 0.8 且冷却 > 10 秒自动进入问答；低置信只提示，手动按钮始终可用。
- 每个学生每次举手写 `student.hand_raised` 事件，并降低其举手积极性、进入 45 秒冷却。
- 教师点名一个学生 → 该学生问题以文字出现，其余举手放下。
- 教师 30 秒未点名 → 全部举手放下，写 `classroom.hand_window_timeout`，回讲解状态。
- 问题生成上下文：近期转写、OCR 文字、课题 / 教材、学生个性文本与参数。
- 自动监测（A）后续实现；定时硬触发（C）不做；情景模式 MVP 也不自主触发。

### FR-M3-07 学生回答与多轮对话（P0）

- 教师点「向全班提问」→ 学生可举手；教师点名一个；或教师直接点学生头像点名。
- 学生按能力参数生成文字回答；回答可正确、不完整或错误。
- 教师在界面上点「对 / 错 / 不完整」，标记绑定该条回答。
- 教师语音回应进入对话上下文；学生自己判断是否继续追问，最多 3 轮；教师可点「结束对话」或说「请坐」结束。
- 异常：点名未举手学生、重复点名、对话轮次超限、学生在其他对话中。

### FR-M3-08 纪律与课堂管理（P0）

- 每个学生有注意力值（0—1），随时间 tick 衰减。
- 教师提问、点名、提醒会拉回注意力。
- 注意力低于阈值时，按纪律概率触发走神、小声说话、吵闹等行为。
- 教师点学生头像提醒，状态回升，并记录一次课堂管理动作。
- 学生状态：专注、走神、小声说话、举手、被点名、回答、对话。
- 课堂纪律聚合：按人数 + noisy_ratio 统计 0—3 级，取较大等级；等级变化写 `classroom.discipline_level_changed`。
- 聚合事件只记录 / 供 UI / 供 M4 控场维度使用，不反向驱动虚拟学生概率；邻近学生的局部传染仍由虚拟学生层处理。
- 异常：连续提醒、学生已在对话中、已到最高时长。

### FR-M3-09 结构化面试（P0）

- 教师创建任务时从本校 M5 题库按类别筛选，手动选择 1—10 道题，可调整顺序；设置总时长 1—60 分钟（默认 2 题 / 5 分钟）；可预览题干与答案要点；发布后锁定。
- 只能选择启用、答案要点非空的题目；同一任务所有学生同题；发布时把 question_id、题干、答案要点、顺序写入配置快照。
- M5 中题目后续编辑或停用不影响已发布任务；新任务只显示启用题目；M5 不可用时不能新建结构化面试任务。
- 学生进入：考官文字提问、人像与麦克风录制、总计时、回答转写；学生只看到题干，不显示答案要点。
- 操作：下一题、结束面试；到最高时长自动停止。
- 不使用虚拟学生、板书或共享窗口；本轮不做 LLM 追问。
- 事件需记录 `interview.question_shown`、`interview.answer_started`、`interview.answer_ended`、`interview.next_question`、`interview.ended`，并带 question_id / answer_id，供 M4 时间线使用。
- 回放：人像主画面 + 题目 / 回答时间线。

### FR-M3-10 录制、回放与提交（P0）

- 课堂模式录制三路：人像、麦克风、共享窗口；结构化面试录制人像 + 麦克风。
- 云端存档；回放布局 A：录屏主画面 + 人像小窗 + 右侧事件流；事件可点击跳转；支持倍速、音量、全屏。
- 学生可回看临时录像；选一次提交；提交后只保留该录像，其他临时录像删除。
- 提交时写入学生当时班级 `class_id_snapshot`，供 M7 教师评分与统计使用；学生之后转班不改变历史统计。
- 未提交 session 的临时录像保留 `max(ended_at + 24h, task_closed_at + 24h)`，不得因任务关闭提前删除仍在提交窗口内的录像；同时最多保留 5 个未提交 attempt，超出按最旧丢弃。
- 到最高时长自动停止录制；学生可提交或重做。
- 可见性：录制学生本人 + 课程老师组；管理员不可见。
- 学生退课后，已提交的录像和报告保留只读访问；未提交的 session 取消。

### FR-M3-11 事件、状态机与 WebSocket（P0）

- session 状态：`preparing → in_progress → ended → reviewing → submitted`；`cancelled`（重做 / 放弃 / 超时）、`failed`（录制或技术失败）。
- 到最高时长：`in_progress → ended`；学生打开回看后进入 `reviewing`；提交后 `submitted`。
- 学生状态：`focused / distracted / whispering / hand_raised / called_on / answering / dialogue`。
- 事件写入 session 日志，供 M4 使用；时间戳统一使用 session 相对毫秒。
- WebSocket 推送实时状态与事件；REST 提供任务、提交、回放查询。
- 时间 tick 只驱动注意力衰减、纪律概率和计时，不触发提问。
- 控制 WebSocket 断线 30 秒 grace + 重连快照：30 秒内 `session.resume` 可恢复并补发事件；页面刷新 / 录制器丢失 / 超时 / Java 重启 → `failed`。感知 WebSocket 断线不终止录制。
- 训练 session（M6）复用本状态机，但终态为 `selected / evaluated`，不进入 `submitted`。

### FR-M3-12 任务关闭与课程归档（P0）

- 教师可关闭已发布任务；关闭后不允许开始新的试讲。
- 关闭时处于 `in_progress` 的 session 允许完成；处于 `ended / reviewing` 的允许在 24 小时内提交。
- 关闭后不可重开；如需继续训练，教师新建任务。
- 课程结束日期到达后，课程内不再允许开始新的试讲任务；已提交录像与报告按保留期处理。
- 课程归档后，任务、会话、录像、报告转只读；不能新建或开始任务；已提交的录像与报告仍可由录制学生和课程老师组查看。

## 6. M3 → M4 数据契约

M3 提供原始数据与事件，M4 负责派生信号与评测。

| 数据 | 提供方 | 内容 |
|---|---|---|
| 录像 | M3 | camera_url、screen_url（课堂模式）、audio_url；每路 `offset_ms` |
| 统一文本流 | M3 | text_ids；speaker_type / source / kind；教师 ASR、学生 LLM、结构化面试考官 / 考生；时间使用 session 相对毫秒 |
| OCR 帧 | M3 | frame_id、timestamp、text、bounding_boxes、confidence、change_score、frame_type、object_key |
| 事件 | M3 | event_id、type、timestamp、actor、target、payload |
| 任务配置 | M3 | 发布时的 config_snapshot 与 config_version（参考材料解析文本、权重、结构化面试所选题目题干与答案要点、时长、虚拟学生配置） |
| 音频特征 | M4 | 从 audio_url 计算音量、停顿、语速等 |
| 关键帧选择 | M4 | 基于 frame_type、change_score、OCR 置信度选择关键帧送视觉 LLM |
| 评测结果 | M4 | 维度分、总分、问题、建议；引用 session_id、submission_id、task_config_version |

**M7 读取**：`submission.class_id_snapshot` 用于教师评分与班级统计；M3 不依赖 M7。

**时间基准**：所有事件、文本、OCR 帧使用 session 相对毫秒；三路录制尽量同时开始，记录每路 `offset_ms`。MVP 允许 ±1 秒误差；回放 seek 使用 session 相对时间。

**必需事件类型**：
- `session.started`、`session.time_tick`、`session.ended`
- `classroom.state_changed`、`classroom.question_asked`、`classroom.question_suggested`、`classroom.hand_window_timeout`、`classroom.qa_ended`、`classroom.discipline_level_changed`
- `student.state_changed`
- `student.hand_raised`、`student.hand_lowered`
- `teacher.called_on`、`teacher.marked`、`teacher.management_action`
- `student.question`、`student.answer`、`student.follow_up`
- `dialogue.started`、`dialogue.ended`
- `discipline.event`
- `interview.question_shown`、`interview.answer_started`、`interview.answer_ended`、`interview.next_question`、`interview.ended`
- `submission.created`

**关键 payload**：`student_account_id`、`question_id`、`answer_id`、`correctness`（correct / partial / wrong）、`hand_raise_id`、`dialogue_id`、`discipline_event_id`、`management_action_id`。

## 7. 主要流程

### 7.1 教师建任务

1. 教师登录（M1），进入课程（M2）。
2. 创建任务：课程、模式、课题 / 教材、参考材料、时长、权重。
3. 自由 / 情景：配置虚拟学生，填写情景设定；结构化面试：从本校 M5 题库选题、调整顺序、设置数量与时长。
4. 预览并发布：生成在课学生快照与配置快照；配置锁定。

### 7.2 学生试讲

1. 任务列表 → 开始试讲。
2. 选择共享窗口，授权摄像头、麦克风、屏幕共享。
3. 课堂进行：转写、OCR、虚拟学生、提问、回答、纪律、计时。
4. 到最高时长或主动结束 → 停止录制 → 回看。
5. 选一次提交；其他临时录像删除；M4 生成评测。

### 7.3 教师查看与关闭

1. 任务提交列表：已提交、进行中、未开始。
2. 已提交 → 回放 A / 评测报告。
3. 关闭任务：停止新试讲；进行中的允许完成，已录完的允许 24 小时内提交。

## 9. 异常与边界

- 任务无在课学生、非课程老师组、权重和不为 100%：阻止发布。
- 自由 / 情景任务缺少参考材料或解析失败：阻止发布；结构化面试不需要参考材料。
- 虚拟学生超过 30 人、参数越界、个性文本超长：阻止保存。
- 共享窗口拒绝、关闭或中断：本次 `failed`，不可提交，可重做。
- 摄像头 / 麦克风 / 共享窗口任一路缺失或中断：本次 `failed`，不可提交。
- 实时 ASR / OCR / LLM 故障：录制继续，写事件，M4 标记受影响维度 partial。
- 控制 WebSocket 断线：30 秒内可重连并补发事件；超时 / 页面刷新 / 录制器丢失 / Java 重启 → `failed`，可重做。感知 WebSocket 断线只影响 ASR / OCR，录制继续。
- 到最高时长：自动停止，进入回看。
- 未提交临时录像超过 `max(ended_at + 24h, task_closed_at + 24h)`：自动清理；超过 5 个未提交 attempt：最旧的丢弃。
- 提交后不可再试讲；关闭任务不可重开。
- 结构化面试题库为空、题目不足、题目已停用或答案要点缺失：阻止发布。
- M5 不可用：不能新建结构化面试任务；已发布任务按快照继续。
- 学生退课：未提交 session 取消；已提交录像和报告保留只读。
- 课程归档：任务、会话、录像、报告只读；不能新建或开始任务。
- 管理员访问录像 / 报告 / 参考材料：拒绝。

## 10. 验收要点

1. 教师可创建自由试讲、情景模拟、结构化面试任务；发布时生成在课学生快照与配置快照，发布后配置锁定。
2. 学生能看到任务，开始试讲，共享选定外部窗口并采集摄像头、麦克风。
3. 虚拟学生按配置生成；教师点「让学生提问」/「向全班提问」出现 1—3 人举手（保底至少 1 人），点名后出现文字问题；30 秒未点名全部放下、回讲解并记录；每次举手降低该生积极性和进入冷却。
4. 学生文字回答；教师可标记对 / 错 / 不完整；多轮对话最多 3 轮，教师可结束。
5. 纪律状态随时间与互动变化；教师提醒会拉回注意力并记录管理动作。
6. 到最高时长自动停止；学生可多次试讲，选一次提交，只保留提交件。
7. 回放 A 可用：录屏主画面 + 人像小窗 + 右侧事件流；学生本人与课程老师组可见，管理员不可见。
8. 结构化面试：教师从本校题库手动选题、调整顺序、设置 1—10 道题与 1—60 分钟；发布快照锁定题干与答案要点；文字考官、语音作答、计时、人像回放；题目 / 回答事件可供 M4 使用。
9. 三路流缺一不可提交；实时分析故障不阻断录制，但 M4 标记 partial。
10. 关闭任务停止新试讲，进行中的可完成；关闭后不可重开；课程归档后只读。
11. 事件、状态机、WebSocket 日志完整，时间统一为 session 相对毫秒，可供 M4 消费。
12. 课程结束日期到达后不再开始新试讲；提交件按「课程结束 + 1 年」保留。
13. 控制 WebSocket 断线 30 秒内重连成功，session 保持进行中并补发缺失事件；超时 / 页面刷新 / 录制器丢失 → failed；感知 WebSocket 断线不影响录制。

## 12. 后续 A 阶段需求（未实现，仅记录）

> 本节记录 2026-11-07 讨论确定的后续需求，不改变 §4 / §5 的 P0 行为；实现前必须先更新 05A 状态机与事件契约，并由 M3 Owner、架构 / 契约 owner 确认。当前 P0 已具备“教师点名后学生自动生成回答”；本节 FR-M3-13 指的是**自动点名 + 自动回答**，不是现有点名后的回答。

### FR-M3-13 自动点名与自动回答（A 阶段，后续）

- 教师语音或手动提问进入 `qa.waiting_hands` 后，系统在可配置延迟（默认 2 秒）自动选择一个举手学生并触发回答，无需教师点击“点名”。
- 选择规则可配置：第一个举手 / 举手评分最高 / 上次回答学生优先；必须遵守“保底至少 1 人”和 45 秒冷却规则。
- 自动点名与手动点名共用同一条 `teacher.call_on → student.answer` 路径；不得产生重复回答或重复 `teacher.called_on`。
- 教师可随时关闭自动模式或手动点名覆盖；自动模式关闭时保持现有 P0 行为。
- 无可用举手学生时不自动点名，保持 30 秒举手窗口；窗口超时按现有规则回到讲解。
- 异常：已在他人的对话中、session 非 in_progress、没有举手学生、自动点名与手动点名并发时，只允许一个生效。
- 验收：语音提问后无需点击即可在 1—3 秒内看到学生回答；手动点名仍可用；重复命令只产生一条 `student.answer`。

### FR-M3-14 自动评价（A 阶段，后续）

- 学生回答或追问生成后，系统自动给出正确性 / 质量评价（correct / partial / wrong 或等价分档），并带置信度；可配置是否启用。
- 评价结果绑定 `answer_id`，写入事件与文本流，供对话面板和 M4 / M7 使用；教师仍可手动覆盖。
- 低置信度或上下文不足时输出 `unrated` / 建议状态，不强行标记；评价失败不得影响回答展示和课堂继续。
- 评价调用与内容生成解耦，可异步执行；不得阻塞 `student.answer` 推送。
- 验收：每次 `student.answer` 最多一条自动评价；教师覆盖后以教师标记为准；低置信度不产生错误标记。

### FR-M3-15 自动结束对话（A 阶段，后续）

- 对话可在满足以下任一条件时自动结束，无需教师点击“结束对话”：
  - 达到最大轮次（默认 3 轮）；
  - 学生判断不再追问（`no_follow_up`）；
  - 教师 / 学生静默超过配置时长；
  - 自动评价认为本轮问答已完成（可配置）。
- 自动结束必须产生 `dialogue.ended`，reason 使用 `auto_timeout` / `max_rounds` / `no_follow_up` / `auto_completed` 等明确值，并按现有顺序回到 `waiting_hands`。
- 教师手动结束优先于自动结束；自动结束不得在 ASR partial / 教师正在说话时触发。
- 验收：三种自动结束路径各产生且仅产生一次 `dialogue.ended`；状态回到 `waiting_hands`；无重复事件。

### FR-M3-16 教师追问驱动的多轮问答（A 阶段，后续）

- 教师在 `qa.dialogue` 中通过语音 ASR final 或文本输入继续追问时，系统生成**学生对教师追问的回答**（`student.answer`），而不是当前 P0 的学生 `student.follow_up`。
- 每轮教师追问产生新的 `answer_id`，绑定当前 `dialogue_id` 与轮次；最多可配置轮次（默认 3 轮）。
- 回答生成上下文必须包含教师本轮追问文本、最近对话、学生个性与参数；自动评价按 FR-M3-14 执行。
- 事件顺序、`dialogue.started` / `dialogue.ended`、`student.answer` / `student.follow_up` 的取舍由 05A 更新后确定；不得同时产生学生追问和学生回答。
- 教师可随时结束对话或结束问答；达到轮次上限自动结束对话。
- 验收：教师连续追问 2—3 轮，每轮都有新的学生 `student.answer`；对话面板按“教师追问—学生回答”顺序显示；不再出现未请求的 `student.follow_up`。
