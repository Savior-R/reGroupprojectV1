# 模块需求一致性与可行性分析

> 覆盖范围：M1、M2、M3、M4、M5、M6、M7；M5 本轮只做结构化面试题库，M8 暂缓
> 版本：V0.3（讨论稿）　状态：待评审　更新日期：2026-11-02
> 用途：检查模块之间的依赖、冲突与缺口，评估优化空间和实施可行性，作为概要设计与排期依据

## 1. 结论摘要

- M1 → M2 / M5 → M3 → M4 → M7 的主链路边界清晰，未发现会导致返工的硬冲突；M6 作为独立训练层复用 M3 / M4，M8 暂缓。
- 本次新增 M7 后，原第 8 点的教师评分、统计、排行榜、导出有了明确归属；管理员只保留 M1 / M2 的元数据管理，不再承担评测业务。
- 主要风险集中在三处：M4 `partial / failed` 的最终分缺失、首次评分后配置锁定的调整流程、M7 与 M3 / M4 数据契约的稳定性；并发编辑与班级归属已通过乐观锁和提交时班级快照收敛。
- M7 和 M5 都适合独立演示：M7 只读 M3 / M4 的结果数据；M5 为 M3 提供题库，但本身不依赖课堂链路，可用种子数据启动。
- 建议实施顺序：M1 → M2 / M5 → M3 → M4 → M7 → M6；M8 在 M7 稳定后启动。

## 2. 模块依赖与边界

| 模块 | 依赖 | 被谁消费 | 边界要点 |
|---|---|---|---|
| M1 账号管理与身份认证 | — | M2、M3、M4、M6、M7、M8 | 账号、角色、学校、专业、班级；管理员与学校一对一；不做教学数据 |
| M2 课程操作与管理 | M1 | M3、M4、M6、M7 | 课程、老师组、学生关系、归档与 `end_at`；不做评分与统计 |
| M3 虚拟课堂与录制 | M1、M2、M5 | M4、M6、M7 | 任务、分配快照、提交件、录制、事件、配置快照；结构化面试从 M5 选题；不做 AI 评分与教师评分 |
| M4 AI 评测与反馈 | M1、M2、M3 | M6、M7、M8 | AI 评测、维度分、报告；不做教师人工评分、统计、导出 |
| M5 结构化面试题库 | M1 | M3 | 每校题库、类别 / 题目、种子复制；不做教材等其他资源 |
| M6 训练模式 | M1—M4 | 学生本人、M8（后续） | 学生独立训练；教师不可见；训练不进入 M7 |
| M7 教师评测与数据统计 | M1—M4 | M8 | 教师评分、最终分、统计、排行榜、导出；只读 M3 / M4，不写回 |
| M8 达标与认证 | M4、M6、M7 | — | 证书、薄弱项训练推送、进步曲线；暂缓，不纳入当前范围 |

> 依赖原则：上游只提供数据，下游只读消费；M7 不修改 M3 / M4，M8 不复制 M4 / M7 的评测结果。

## 3. 发现的问题、冲突与处理

| 编号 | 严重度 | 涉及模块 | 问题 | 影响 | 建议 / 当前处理 |
|---|---|---|---|---|---|
| C1 | 高 | M4、M7 | M4 的 `partial / failed` 是终态，且本轮不提供手动重跑；`ai_weight > 0` 时 M7 的最终分需要 AI 分 | 这类提交件永远无法得到最终分，教师评分保留但不进入统计 | 已确认方案 A：本轮不计算最终分、不进统计；P1 再评估受控重跑，暂不做教师单独最终分 |
| C2 | 高 | M2、M7 | 课程老师组平权，同一提交件的教师评分由多人共享；若只按最后写入生效，没有逐次修订历史 | 并发编辑可能覆盖；成绩争议时无法追溯 | M7 已增加 `version` 乐观锁，冲突返回 409；P1 再增加修订历史或指定主评教师 |

## 4. 优化空间

### 4.1 M7 教师评测与数据统计

- 评分效率：支持“一键采用 AI 分”、批量填充、评语模板、键盘连续录入、只显示待评分学生。
- 进度可见：任务卡片显示已评分 / 待评分 / 待 AI 数量，教师可快速定位未完成项。
- 薄弱项下钻：从维度平均分跳到该维度低分学生，再跳到 M4 的具体问题与时间戳。
- 权重管理：常用权重预设（70 / 30、50 / 50、100 / 0），配置变更二次确认与变更记录。
- 成绩口径：在页面固定展示“AI 分 / 教师分 / 最终分”三者关系，避免误解。
- 导出：按班级 / 任务 / 状态保存导出模板；后续支持异步导出与 Excel。
- 审计：P1 增加评分修订历史、配置变更历史、导出日志。
- 演示：种子数据 + 只读适配层 + 一键重置；不依赖 M3 / M4 实时运行。

### 4.2 M3 / M4

- M3 提交件已增加 `class_id_snapshot`，从源头解决班级统计漂移。
- 任务列表展示 AI 评测状态，教师无需进入 M7 才知道谁待评测。
- M4 增加受控的手动重跑或“评估不完整”处理策略，避免 M7 永久缺分。
- 明确 M4 `partial` 的展示口径：哪些维度可用、哪些不计分，M7 直接复用。

### 4.3 M1 / M2

- 班级成员历史可作为后续增强；本轮已在 M3 提交时写快照。
- 明确课程 `end_at` 与归档的区别：`end_at` 是教学结束，归档是管理动作；评分窗口按归档控制。

### 4.4 M5 / M8

- M5：每校结构化面试题库、类别 / 题目维护、种子复制；M3 手动选题并快照。教材、教案、板书模板、优秀范例后续扩展。
- M8：暂缓，不纳入当前范围；后续再定义证书阈值、薄弱项推送规则与进步曲线。

## 5. 可行性评估

| 模块 | 技术复杂度 | 主要风险 | 可行性结论 |
|---|---|---|---|
| M1 | 中 | 学校 / 专业 / 班级导入、管理员一校一人、token 范围 | 可行；依赖清晰的导入格式与示例数据 |
| M2 | 中 | 多专业课程、老师组平权、软删除与历史 | 可行；规则已较完整 |
| M3 | 高 | WebSocket、三路录制、窗口共享、ASR / OCR、断线失败 | 可行但风险最高；建议先做单机 MVP，实时分析故障降级为 partial |
| M4 | 高 | LLM / OCR / 视觉调用、异步重试、部分成功、成本 | 可行；需控制调用量、设置超时与重试上限 |
| M6 | 中 | 复用 M3 / M4、训练隐私、模板快照、保留期 | 可行；依赖 M3 / M4 稳定 |
| M7 | 低—中 | 只读数据契约、并发评分、班级快照、AI 不完整 | 可行；无 AI 调用，主要是 CRUD、聚合与 CSV |
| M5 | 低 | 每校题库 CRUD、种子复制、M3 选题读取 | 可行；无文件存储与 AI 调用，可独立开发与演示 |
| M8 | — | — | 暂缓，不纳入当前范围 |

### 5.1 M7 的技术可行性

- 数据来源：M3 的 task、task_assignment、submission、config_snapshot；M4 的 evaluation、dimension_score、status。MVP 建议同库只读视图，后续可替换为 REST 适配层。
- 计算：最终分与维度分是四则运算，无模型调用；可在查询时计算，或落一张可重算的 `FinalScore` 缓存表。
- 性能：按 `task_id`、`course_id`、`student_account_id`、`submission_id` 建索引；单课程 / 单任务数据量可控；统计按需聚合。
- 安全：JWT + 角色 + 学校范围 + 课程老师组校验；管理员、训练记录、跨校访问统一 403。
- 演示：种子数据覆盖学校、教师、学生、课程、任务、提交件、AI 评测；M7 可独立启动，不依赖录制与评测 worker。
- 主要工作量：数据适配、评分表格、最终分计算、统计聚合、CSV 导出；属于低—中复杂度。

### 5.2 M5 的技术可行性

- 每校题库、类别 / 题目 CRUD、搜索分页、种子复制均为常规 CRUD；无文件存储与 AI 调用。
- 与 M3 的接口是只读列表 / 详情；M3 发布时快照题干与答案要点；与 M4 无直接依赖。
- 建校时复制种子题库可用事务 + 幂等键；已有学校首次访问可懒初始化。
- 演示时用种子题库即可，不需要真实课程或试讲数据。

### 5.3 实施顺序建议

1. M1：账号、学校、专业、班级。
2. M2、M5：课程 / 老师组与结构化面试题库；M5 只依赖 M1，可先做或并行。
3. M3、M4：课堂、录制、AI 评测；M3 的结构化面试依赖 M5 题库。
4. M7：在 M3 / M4 数据契约稳定后接入；可提前用种子数据并行开发。
5. M6：复用 M3 / M4，排在 M7 前后均可。
6. M8：暂缓，不纳入当前排期。
