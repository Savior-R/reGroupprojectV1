## 1. 定位

### 1.1 面向"试讲",不是"演讲"

| | 演讲 / 说课 | **试讲(模拟教学)** |
|---|---|---|
| 对象 | 听众、评委,被动 | **学生,要互动** |
| 目标 | 他们"听懂了" | 他们"**学会了**" |
| 结构 | 起承转合 | 导入 → 新授 → 练习 → 小结 → 作业 |
| 核心技能 | 表达、感染力、逻辑 | **教学**:提问、引导、反馈、控场 |
| 时间 | 大致均匀 | 各环节**有配比要求** |

本模块面向**右列**。

### 1.2 虚拟学生是"测量仪器",不是场景装饰

如果只做演讲训练,虚拟学生就是背景动画,做成 gif 都行。

但试讲里最值钱的评测维度**全部依赖虚拟学生才能算出来**:

| 评测维度 | 需要虚拟学生做什么 |
|---|---|
| 提问设计 | 学生答错 → 看教师会不会追问 |
| 引导能力 | 学生答得不完整 → 看教师会不会搭台阶 |
| 反馈评价 | 学生答完后 → 看教师有没有回应 |
| 控场能力 | 学生走神、吵闹 → 看教师怎么处理 |
| 互动覆盖 | 学生举手 → 看教师有没有叫到人 |

**去掉虚拟学生,这五项全部归零。**

由此推出本模块最重要的设计约束:

> 虚拟学生的行为必须**可复现、可解释、可单测**,并且必须**落库**。
> 它不能"自由发挥" —— 一旦自由发挥,评测就没有基准真值。

### 1.3 结构化面试不在本文件范围

需求里的「结构化面试」模式,在物理形态上是另一个产品:

| | 教学型(本文件) | 面试型(后续) |
|---|---|---|
| 场景 | 教室 + 座位 + 学生 + 黑板 | 考场 + 考官席 + 题目卡 |
| 交互 | 举手、答问、纪律 | 无学生行为 |
| 评测 | 教学能力 | 表达与应答 |

本文件只覆盖**教学型**:自由试讲、情景模拟。

## 2. 核心原则

### 2.1 课堂状态的权威在服务端

前端**不持有**任何课堂状态,只做渲染。

理由:录制结束后的评测需要"举手时刻"这类基准真值。如果前端自己随机,回放和评测对不上。

### 2.2 统一时钟

前后端各跑一个定时器 = 必然漂移,10 分钟能差出几秒,评测的"响应率"直接失效。

设计:

- 服务端以单调时钟的 `started_at` 作为**唯一时间源**
- 所有事件的时间戳都是相对 `started_at` 的毫秒数(`at_ms`)
- 前端只用 `at_ms` 做插值渲染,不用本地计时器做判断
- 定期做时钟校准(客户端报本地经过时长,服务端回权威值,前端算偏移量)

### 2.3 LLM 只驱动「内容」,不驱动「行为」

这是本模块最重要的一条分工:

```
LLM 负责「说什么」          ── 语义任务,低频,可容忍秒级延迟
概率模型负责「什么时候做」    ── 时序任务,高频,需毫秒级确定性
```

理由(按重要性排序):

1. **评测的立论基础** —— 见 1.2。行为若由 LLM 自由决定,"学生答错"就可能是随机的,而不是因为教师提问含糊,因果链断裂
2. **频率** —— 40 名学生高频判定 = 一节课数万次调用,不可行
3. **延迟** —— LLM 单次 1~5 秒,举手延迟 3 秒会毁掉互动节奏
4. **可复现** —— 同一份试讲必须得到同样的学生反应
5. **统计合理性** —— LLM 倾向于给出"戏剧化"的答案(总是那几个学生有戏),真实课堂的行为分布是分散、低频的

**LLM 在本模块的职责范围:**

| 环节 | 驱动者 | 频率 |
|---|---|---|
| 什么时候举手 / 走神 / 说话 | 概率模型 | 每秒 |
| 纪律事件升级、降级 | 状态机规则 | 事件驱动 |
| 回答的**质量档** | 公式(**不是 LLM**) | 每次回答 |
| 学生提问的**内容** | LLM,课前批量 | 8~10 条/课 |
| 学生回答的**内容** | LLM,按档位生成 | 5~8 次/课 |
| 判断教师提问是否清晰 | LLM | 批量 |
| 情景模拟的事件内容 | LLM | 3~5 次/课 |

### 2.4 确定与概率的分界

> **承载评测因果链的行为 → 必须确定**
> **只提供背景真实感的行为 → 可以概率**

| 必须确定 | 可以概率 |
|---|---|
| 纪律事件升级 / 降级 | 谁走神、走神多久 |
| 情景模拟的突发事件 | 谁小声说话、和谁 |
| 回答质量档 | 非提问时的自发举手 |
| 提问与学生的匹配 | 行为的具体时刻分布 |

## 3. 虚拟学生

### 3.1 学生规模与人设

每个学生由一组参数刻画 —— **参数化而非逐个手写**,这样数十人的班级才可配置、可复用:

| 参数 | 含义 | 作用 |
|---|---|---|
| 姓名、座位 | 身份标识 | 教师点名叫答、座位图渲染 |
| 专注倾向 | 0~1 | 走神概率 |
| 学业水平 | 0~1 | 举手概率、回答质量档 |
| 积极度 | 0~1 | 举手概率、反应延迟、举手的耐心时长 |
| 说话倾向 | 0~1 | 小声说话概率 |
| 外观标识 | 可选 | 立绘变体或颜色,用于区分个体 |

**学生规模与人设均由用户自定义。**

**规模** —— 可选档位或自定义人数。座位布局按人数自动排布(优先 6~8 列,行数按需增加),纵深感按实际行数动态计算,不写死排数。

**人设** —— 三种创建方式,逐层降低门槛:

1. **开箱即用的预设班级** —— 零配置即可直接开始试讲
2. **预设模板** —— 如"标准班 / 活跃班 / 沉闷班 / 小班",一键套用
3. **逐个编辑** —— 表格化编辑姓名与四个参数,支持批量操作(全部设为中等、随机化选中项)

**人设不是每次试讲都重配。** 一套人设可保存为**可复用的虚拟班级**,后续试讲直接选用 —— 否则每次都要重配数十个学生,没有人会用。

**角色结构**:沿用"少数活跃角色 + 多数背景角色"的结构,活跃角色占比约 25%~30%(比例可按规模自动计算,也可由用户指定具体哪些学生是活跃角色)。

- **活跃角色** —— 有名字、有特点、会被叫到、会提问
- **背景角色** —— 只有参数,参与集体行为(举手、走神、纪律)

理由:真实课堂也是少数人主导互动。这个结构既真实,又省去给每个人写人设的成本。

**规模对评测的影响(需注意)**:班级规模会影响行为密度的绝对量 —— 人数多则举手总人数多、纪律更易升级。这**符合真实课堂规律,因此不做归一化**;但报告需标明班级规模,跨规模比较时应谨慎解读。

### 3.2 行为的三种类型

驱动逻辑完全不同,必须分开设计。

| 类型 | 行为 | 特征 | 驱动方式 |
|---|---|---|---|
| **持续状态** | 专注、走神、小声说话、记笔记 | 持续一段时间后自然切换 | 概率 + 上下文调制 |
| **瞬时动作** | 举手 | 有明确时刻与持续时长 | 受教师行为触发 |
| **交互回合** | 提问、回答、纪律失控 | 需要教师参与的完整回合 | 编排 + LLM 生成内容 |

### 3.3 概率模型

**模型性质:非齐次半马尔可夫过程。**

| 成分 | 含义 |
|---|---|
| 马尔可夫 | 学生状态只依赖"当前状态 + 当前上下文",不回溯历史 |
| 半 | 每个状态有**停留时间**,不是每 tick 重新掷骰子 |
| 非齐次 | 转移概率随时间变化 —— 受当前环节和教师行为调制 |

**关键设计点:状态必须有"停留时间"。**

若每个 tick 重新判定,学生会每秒闪烁(专注→走神→专注→走神),一眼就假。正确做法是进入行为时即决定持续多久。

各行为的停留时长区间(初始值,可调):

| 行为 | 停留时长 |
|---|---|
| 专注 | 30~180 秒 |
| 走神 | 10~40 秒 |
| 小声说话 | 5~20 秒 |
| 举手 | 15~45 秒(无人叫答则放下) |

**所有参数集中在一张权重表中**,可由师范专业教师参与调参。这是模型可讨论、可验证的前提。

### 3.4 三个调制因子

```
行为概率 = 基础权重 × 学生性格 × 当前环节 × 教师行为
```

**因子 1 · 学生性格**(静态)—— 见 3.1 的参数表。

**因子 2 · 当前环节**(半静态)—— 不同环节的行为分布完全不同:

| 环节 | 走神 | 说话 | 举手 | 主动提问 |
|---|---|---|---|---|
| 导入 | 低 | 低 | 低 | 低 |
| 新授 | 中 | 低 | 中 | **高**(听不懂) |
| 练习 | 中 | **高** | **高** | 中 |
| 小结 | **高** | 中 | 低 | 低 |

**因子 3 · 教师行为**(实时)—— 见第 5 节的 `TeacherBehaviorSummary`。

### 3.5 双层驱动

```
┌────────────────────────────────────────────────┐
│  反应层(主驱动,承担约 90% 的行为)              │
│  教师行为 → 学生反应                             │
└────────────────────────────────────────────────┘
                     +
┌────────────────────────────────────────────────┐
│  保底层(防课堂死机)                             │
│  长时间无任何教师行为 → 少量自然的走神、小声说话   │
│  作用:1) 课堂不静止  2) 给长时间照本宣科的教师压力│
└────────────────────────────────────────────────┘
```

**保底层的时间表不是主驱动。** 它只在教师不动作时发力;教师互动越频繁,它越沉默。

### 3.6 反应矩阵

本模块的核心映射表:**教师行为 → 学生反应。**

| 教师行为 | 检测方式 | 学生反应 | 影响方式 |
|---|---|---|---|
| 提问 | 教师按键 / 语音识别 | 举手 | 举手概率随提问清晰度变化 |
| 点名回答 | 点击学生 / 识别姓名 | 该生回答 + 质量档 | 确定触发 |
| 长时间无互动 | 计时 | 走神概率上升 | 随时间累积 |
| 语速过快 | 规则计算 | 主动提问概率上升 | 跟不上 |
| 提问含糊 | LLM 判断 | 举手率下降、答对率下降 | 同时影响两个公式 |
| 表扬某学生 | LLM 判断 | 该生积极度上升,邻近学生举手率上升 | 短期增益 |
| 管理纪律 | LLM 判断 | 吵闹降级 | 状态机 |
| 进入练习环节 | 环节切换 | 说话上升、举手上升 | 环节因子 |
| 长时间不叫答 | 计时 | 举手放下 | 耐心耗尽 |
| 播放视频 / 演示 | 屏幕变化 | 走神加速 | 注意力衰减 |

### 3.7 行为传染与纪律升级

**传染**:邻近学生处于"小声说话"时,该学生的说话概率显著上升。这形成了自然的行为聚集,比独立随机真实得多。

**纪律事件分级:**

| 级别 | 条件 | 表现 |
|---|---|---|
| 0 | 安静 | — |
| 1 | 1~2 人小声说话 | 对话气泡 |
| 2 | 3 人以上同时说话 | 气泡 + 头顶视觉提示 |
| 3 | 持续 20 秒未平息 | 前排学生回头 + 明显噪声 |

**升级由系统自动推进,降级必须由教师触发。** 这是"控场能力"可量化的关键 —— 教师处理后降级,不处理则继续升级。

### 3.8 举手的展开过程

教师提问后,学生**不是同时举手**,而是有一个自然展开:

| 参数 | 含义 | 说明 |
|---|---|---|
| 举手概率 | 该生本次是否参与 | 与积极度、水平、提问清晰度相关 |
| **反应延迟** | 从提问到举手的间隔 | 与积极度负相关(越积极越快),叠加随机扰动 |
| 等待窗口 | 超过则不再有人举 | 约 3~5 秒 |

**反应延迟是举手看起来真实的关键。** 全班在同一帧举手会立刻暴露是程序。

**举手后未被叫答** → 触发"耐心"计时,超时后放下。越积极的学生耐心越久。

**"举了手没人理"是评测信号,不是装饰** —— 它直接产出"互动覆盖不足"和"冷落了最积极的学生"两条结论。

## 4. 内容生成(LLM 的职责)

### 4.1 接缝问题与解法

**核心矛盾**:概率模型是同步的(微秒级),LLM 是异步的(1~3 秒)。当概率模型决定"某学生要提问了",内容还没生成出来。

**解法:用互动本身的节奏掩盖 LLM 延迟。**

```
举手(t=0)        ← 概率模型即时决定,不需要内容
   ↓
教师叫答(t=3~8s)  ← LLM 的生成窗口
   ↓
学生说话(t=6~10s) ← 内容已就绪
```

**举手不需要内容,说话才需要。** 这中间 3~8 秒的间隔在真实课堂里本来就存在。

### 4.2 生产者-消费者

概率模型**永远不等待** LLM:

- 概率引擎只负责"谁、何时、做什么行为",行为即时发生
- 内容从**内容池**取:池中有则直接取;池中无则异步生成并占位;超时或失败则取兜底模板
- LLM 在后台运行,结果写入池子

### 4.3 各类内容的时间预算

| 内容 | 生成时机 | 可用延迟 |
|---|---|---|
| 学生提问的问题库 | **课前批量**(一次出 8~10 条) | 无限制 |
| 本轮提问选哪一条 | 运行时,从池中取 | 0 |
| 学生回答的内容 | **教师提问时批量生成** | 3~8 秒 |
| 教师行为的判断 | 实时,批量 | 1~3 秒 |
| 情景模拟的事件内容 | 课前 + 实时 | 可变 |

### 4.4 提问内容

**课前批量生成**,每条问题携带三个元数据:

| 元数据 | 作用 |
|---|---|
| 目标知识点 | 保证问题落在**教学重难点**上,而不是"老师你几岁了" |
| 问题类型 | 基础困惑 / 边界条件困惑 / 挑战质疑 |
| 适配水平 | 匹配学生学业水平,低水平问基础困惑,高水平问质疑 |

生成约束:

- 口语化 —— 真实学生会说出口的困惑,不是教案语言
- 关于教学内容本身,不是关于教师个人
- 学段越高质疑越深,不得出现超出学段的问题

分配时按"当前环节 + 学生水平"挑选,保证对应关系。

### 4.5 回答内容与质量档

**质量档由公式决定,不由 LLM 决定:**

```
质量档 = f(学生学业水平, 教师提问清晰度, 问题难度)
```

| 学生水平 | 提问清晰度 | 问题难度 | → 质量档 |
|---|---|---|---|
| 高 | 高 | 低 | 正确 |
| 中 | 高 | 中 | 部分正确 |
| 低 | 中 | 中 | 错误 |
| 任意 | **低(含糊)** | 任意 | **错误概率显著上升** |

**最后一行是整个评测体系的因果基础:**

> 教师提问越含糊 → 学生答对概率越低。

**内容生成按档位批量进行,不按学生逐个进行:**

在教师提问的瞬间,一次性生成"正确 / 部分正确 / 错误"三档各若干变体。叫到谁,就按该生的质量档从对应变体中取一条。

理由:同一问题的正确答案内容大同小异,差异主要在口吻。这样把生成量从"按学生数"降到"按档位数",调用量降一个数量级,且零延迟。

**内容必须是学生口吻,绝不能生成标准答案** —— 否则试讲人听到的就是正确答案,反而学不到东西。

### 4.6 降级链

```
内容请求
  ├─ 池中有     → 直接取
  ├─ 池中无     → 异步生成 + 占位;超时则取兜底模板
  └─ 调用失败   → 取兜底模板
```

兜底模板必须预设且**像真的**(例如"老师,这里我没太听明白")。

> 底线原则:**学生绝不能哑巴。** 一个举了手却不说话的学生,比说一句平淡的话糟糕得多。

## 5. 教师行为提取

### 5.1 三层原则

> **能埋点的绝不识别,能算的绝不问 LLM,必须问 LLM 的降频批量。**

| 层 | 内容 | 成本 | 延迟 | 准确率 |
|---|---|---|---|---|
| 埋点 | 提问、叫答、环节切换、翻页 | 0 | 0 | 100% |
| 算法 | 语速、停顿、口头禅、注视、手势、走动 | 0 LLM | ~1 秒 | 高 |
| LLM | 是不是真提问、表扬/批评/管理、提问清晰度 | 较高 | ~3 秒 | 高 |

**把能塞进埋点层的东西全部塞进去。** 埋点比任何 AI 都准、都快、都便宜。

### 5.2 埋点层

| 教师行为 | 上报方式 | 为何不用识别 |
|---|---|---|
| 提问 | 教师按快捷键 / 点击按钮 | 语音判疑问句会误判,手动 100% 准 |
| 点名回答 | 点击学生 | 提取姓名需 ASR + LLM,点击零成本 |
| 环节切换 | 点击环节按钮 | 让模型猜环节边界不可靠 |
| 屏幕内容切换 | 屏幕采样检测(见第 6 节) | — |
| 开始 / 结束 | 按钮 | — |

**第一期的提问与叫答采用人工操作,这不是临时方案** —— 微格教学本身是规范动作训练,有意识地"按下提问",帮助师范生建立"提问是一个明确教学动作"的意识。自动识别上线后,人工操作保留为兜底(自动识别永远会有误判)。

### 5.3 算法层

**音频**(纯计算,零 LLM):

| 指标 | 来源 |
|---|---|
| 语速 | 转写字数 / 有效说话时长,按环节分别统计 |
| 停顿 | 相邻转写段之间的间隔 |
| 口头禅 | 词表匹配(嗯 / 那个 / 就是 / 然后 / 呃) |
| 音量 | 分段音频包络 |
| 卡壳 | 超长停顿且无语音 |

**视觉**(抽帧 + 关键点检测,详见第 7.4 节):

| 指标 | 说明 |
|---|---|
| 注视镜头时长占比 | 近似"看学生"的时长 |
| 头部朝向分散度 | 是否扫视全班,而非只对一个方向讲 |
| 手势频次与幅度 | 幅度需按肩宽归一化 |
| 躯干偏离垂直的时长 | 站姿 |
| 走动轨迹 | 幅度与频次,双向评价(过少死板 / 过多晃悠) |
| 表情变化 | 微笑占比、表情丰富度 |
| 出画时长 | 是否走出摄像头范围 |

**派生量**(纯计数):距上次互动的时长、连续讲授时长。这两个值**直接驱动学生模型**(讲太久 → 走神概率上升)。

### 5.4 LLM 层:降频 + 批量

**按话语单元触发,不按固定定时器:**

触发条件(任一满足):一段有意义的话语结束 / 命中疑问词 / 环节刚切换 / 距上次判断超过 30 秒。

**批量判断**:攒 5~10 句一次送,而不是一句一调 —— 成本与延迟都差一个数量级。

**规则预过滤**:送 LLM 之前先用疑问词表过滤,可滤掉大部分非提问。

LLM 返回每句话的类型标签,可能的类别包括:真实提问、**伪提问**、点名、表扬、批评、管理纪律、讲解。

**伪提问**值得单独说明:指"对不对呀?""是不是?"这类教师口头习惯,并不需要学生回答。教育学上称为"齐答式提问",是新手教师的典型问题之一。**判断伪提问率几乎不增加成本**(反正已经要分类),但在报告中非常有说服力。

### 5.5 TeacherBehaviorSummary

**关键抽象**:三种来源的教师行为归一成**一个结构**,学生模型只读它,不关心数据来源。

| 字段组 | 更新频率 | 来源 |
|---|---|---|
| 埋点与派生:是否处于提问窗口、上次叫答时刻、当前环节、连续讲授时长、距上次互动时长 | 事件驱动 | 埋点 |
| 音视频数值:是否在说话、语速、静音时长、口头禅频率、注视占比、手势活跃、是否走动 | 约 1 秒 | 算法 |
| 语义:话语类型列表、提问清晰度、是否伪提问 | 20~30 秒 | LLM |

**这个抽象带来的关键收益**:从"人工操作"升级到"自动识别"时,只改这个结构的**填充方式**,学生模型的代码一行不改。

### 5.6 双路径消费

同一份数据,两种时效要求,分开跑:

| 路径 | 用途 | 频率 | 深度 |
|---|---|---|---|
| 实时 | 调制学生行为 | 每 20~30 秒 | 浅 —— 只做粗分类 |
| 离线 | 生成评测报告 | 课程结束后一次性 | 深 —— 全量转写与完整分析 |

这个分离本身是一个重要的效率优化:合并两者就得在实时性与分析深度之间二选一。

## 6. 交互流程

### 6.1 提问 → 举手 → 叫答

```
教师触发提问
   ↓
服务端进入提问窗口,为每名学生计算举手概率
   ↓
对通过判定的学生,各自安排一个反应延迟
   ↓
批量下发(一条消息携带所有候举手与其延迟),前端本地定时展开
   ↓
学生陆续举手
   ↓
窗口关闭,未举手者本次不再参与
   ↓
教师叫答(点击 / 语音点名)
   ↓
被叫学生进入回答状态,其余举手者开始陆续放下
   ↓
生成回答内容(按质量档),语音朗读
   ↓
回答结束,回到常态
```

### 6.2 等待时间

提问到叫答之间的间隔本身是评测指标。教育学中"等待时间"是一个经典研究点:优秀教师提问后通常等待 3 秒以上,新手常不足 1 秒就自己接话或改问。

| 指标 | 定义 |
|---|---|
| 等待时间 I | 提问 → 叫答的间隔 |
| 等待时间 II | 学生答完 → 教师反馈的间隔 |

**这两个值由埋点直接产出,零额外成本。**

### 6.3 无人举手

真实场景,且是新手教师最易慌乱的情况,值得专门处理:

- 窗口关闭后无任何举手 → 界面提示"无人举手",并落库
- 评测含义:问题太难 / 太宽泛 / 未给思考时间
- **教师在沉默后的应对**是关键区分点:是降级重新引导,还是直接给出答案

### 6.4 提问未收尾

提问后学生举手了,教师却没叫任何人 —— **问了不问,等于没问**。这是高频教学缺陷,必须如实记录,不做自动补齐。

### 6.5 可产出的互动指标

| 指标 | 算法 | 反映 |
|---|---|---|
| 提问响应率 | 有举手的提问数 / 总提问数 | 提问是否有效 |
| **提问收尾率** | 有叫答的提问数 / 总提问数 | 问了不问等于没问 |
| 参与广度 | 去重举手学生数 / 总学生数 | 是否只激活少数人 |
| **互动覆盖度** | 被叫答学生中"新面孔"的占比 | 总叫同几个人 = 高频缺陷 |
| 冷落度 | 举手未被叫答的次数 | 积极学生被忽视 |
| 等待时间 | 见 6.2 | 是否给思考时间 |
| 回答质量分布 | 各质量档的分布 | 提问清晰度的量化反馈 |
| 伪提问率 | 伪提问数 / 总提问数 | 用"对不对"代替真问题 |

## 7. 课堂环境呈现

### 7.1 布局

三栏工作台:

```
┌────────────────┬──────────────────────────┬─────────────────┐
│ 左栏            │ 中栏                      │ 右栏             │
│ 本环节教案要点   │ 虚拟教室(讲台视角)        │ 座位图 + 学生状态 │
│ 重难点提示       │ 屏幕共享窗口(黑板/PPT)    │ 举手提醒(置顶)   │
│ 环节进度         │ 学生座位阵列              │ 事件日志         │
│ 计时 / 环节打点   │                           │ 实时提示         │
└────────────────┴──────────────────────────┴─────────────────┘
```

### 7.2 用屏幕共享替代自研黑板 / PPT / 板书

**教师用自己的 PPT 与书写工具,系统只显示其屏幕画面。**

理由:

| | 自研渲染 | 屏幕共享 |
|---|---|---|
| 实现工作量 | 上传链路 + 格式转换 + 翻页系统 + 笔迹引擎 + 分区 + 质感 | 嵌入一个视频元素 |
| PPT 保真度 | 图片轮播,无动画 | **真 PowerPoint,完全保真** |
| 板书手感 | 自行实现压力与延迟 | 系统级,可用数位板 |
| 工具广度 | 仅支持已实现的 | **任意软件**:几何画板、仿真、视频 |
| 教师学习成本 | 需学习本系统工具 | 零 |

**"工具广度"是关键。** 数学的动态几何、物理的仿真、化学的实验视频 —— 自研渲染永远做不到,而屏幕共享天然全覆盖。

**取舍(明确接受):**

- 失去精确的 PPT 页码,只能得到"内容切换时刻"
- 失去板书矢量数据,板书分析只能基于截图
- 失去"板书随视频逐笔重现"的效果
- 换来的是工作量下降一个量级

**屏幕内容与录制的关系**:录制本来就需要屏幕流,同一份流既作为虚拟教室的"黑板"又作为录制输入,一份输入两处使用。

### 7.3 屏幕内容的分析

**变化检测:基准哈希 + 累积漂移**

屏幕有两种变化模式,需要一套逻辑同时捕获:

| 变化类型 | 特征 |
|---|---|
| 离散切换(翻页) | 一步到位 |
| 连续累积(板书) | 逐步增加,单次变化很小 |

做法:以"最近一次确认稳定的画面"为基准,持续比较当前画面与基准的差异累积量,超过阈值时记录一次变化并更新基准。

- 翻页:差异一次达标,立即触发
- 板书:写几笔后累积达标,触发一次
- 光标移动、局部微调:差异过小,不触发

**采用感知哈希而非逐像素比较**,正是为了对光标、抗锯齿、动画这类局部小变化不敏感,只对版式结构变化敏感。

**截图时机:仅在各环节结束时各截一张。**

- 数量少,成本可控
- 时间点有意义 —— 是该环节板书/PPT 的最终状态
- 直接对应"本环节重难点是否上板"

截图与环节的对应关系交由多模态模型一次性判断(内容类型是板书还是幻灯片、结构是否清晰、是否体现重难点),**一次调用同时完成分类、评分与评语**。

**健康检查:**

- 画面接近纯色 → 屏幕共享可能已失效,提示教师
- 长时间无任何变化 → 记录静止时长

**与视觉指标的交叉判断(零额外成本):**

| 屏幕 | 手势 | 含义 |
|---|---|---|
| 静止 | 活跃 | **正在板书** —— 正常 |
| 静止 | 不动 | **干讲** —— 学生缺乏视觉锚点 |
| 频繁变化 | 不动 | 被幻灯片牵着走 / 在操作电脑 |
| 频繁变化 | 活跃 | 演示与手势配合 —— 最佳 |

这个交叉推断还顺带解决了"怎么知道教师在板书"的问题,无需额外埋点。

**隐私**:屏幕共享会录到教师电脑上的全部内容。进入课堂前需做共享预览确认,并在界面明确提示关闭其他窗口。

### 7.4 学生阵列与摄像头视觉

**渲染方案:DOM + CSS。不引入 3D 引擎。**

理由:讲台视角是**固定视角**(走动是身体动作,录在摄像头画面里,不需要视角跟随),视角不动就没有 3D 的必要。座位阵列的节点数量远未到浏览器性能瓶颈。

**纵深感**由行间缩放 + 后排压暗与轻微模糊共同实现。仅缩放会造成"大小不同的贴纸"感,压暗与模糊才是"远"的感知来源。

**学生形象**采用矢量立绘,按状态切换(专注 / 走神 / 举手 / 说话 / 应答)。同一形象复用、以颜色区分个体,避免数十份独立资源。

**让场景"活起来"的关键不是姿势本身,而是过渡与持续的小动作:**

- 举手后有轻微起伏,避免静止成贴纸
- 说话时有对话气泡
- 走神时头部偏转,可与邻近学生形成互动
- 所有状态切换加入短过渡

**场景整体缩放**:以固定设计尺寸绘制,外层整体缩放适配,而非逐元素响应式。

**摄像头视觉指标的提取**(供第 5.3 节使用):

- 关键点检测在**浏览器端**执行,仅上报聚合后的统计数值
- 抽帧频率分离:姿态检测频率高于表情检测(手势是快动作,表情是慢变量)
- 输入分辨率需下调后再送入检测模型,以控制 CPU 占用
- **所有距离类指标必须按肩宽归一化**,否则人走近走远时数值失真
- 视觉原始数据**不进入 LLM**,仅用于规则计算

**选择浏览器端而非服务端推理的关键理由**:只有浏览器端能做到**实时反馈**(例如"已连续 40 秒未注视镜头")。服务端方案要等录制上传分析完成,那时课已经讲完了。实时提示才是这一功能的产品价值所在。

**风险与降级**:笔记本内置摄像头在弱光下检测易失败。当检测失败率过高时,该维度应标记为"数据不足"而**不给分**。

> 宁愿说"数据不足",也不要基于劣质数据给出分数。

## 8. 课堂数据形态

**概念性描述,非最终表结构。**

### 8.1 虚拟班级与学生档案

**虚拟班级** —— 可复用的人设模板。用户自定义一次,后续试讲可直接选用。

| 字段 | 含义 |
|---|---|
| 名称 | 如"标准班 30 人" |
| 规模 | 学生人数 |
| 创建者、创建时间 | 归属与排序 |

**学生档案** —— 虚拟班级中的每名学生。

| 字段 | 含义 |
|---|---|
| 班级标识 | 归属哪个虚拟班级 |
| 姓名、座位 | 身份与位置 |
| 专注倾向、学业水平、积极度、说话倾向 | 驱动行为与质量的四个参数 |
| 外观标识 | 立绘变体或颜色 |
| 是否活跃角色 | 参与互动回合,还是仅参与集体行为 |

**一次试讲开始时会快照一份学生档案。** 评测要引用学生属性(例如"对低水平学生你讲了 3 分钟没换说法"),而人设可能在试讲后被人为修改 —— 快照保证历史报告的解读不会因后续编辑而失真。

### 8.2 课堂事件

课堂行为的流水记录,是**虚拟课堂与评测之间唯一的桥梁**。

| 字段 | 含义 |
|---|---|
| 试讲标识 | 归属 |
| 序号 | 同一试讲内的顺序 |
| 时刻 | 相对开始时间的毫秒数 |
| 类型 | 见下表 |
| 学生标识 | 涉及的学生(可空) |
| 负载 | 类型相关的结构化内容 |

**事件类型与负载:**

| 类型 | 负载内容 |
|---|---|
| 教师提问开始 | 问题标识、问题文本 |
| 学生举手 | 关联的问题标识、反应延迟 |
| 学生放下手 | 原因(未被叫答 / 主动放弃) |
| 教师叫答 | 学生标识、来源(点击 / 语音) |
| 学生回答 | 质量档、回答文本、关联问题 |
| 教师提问未被收尾 | 问题标识 |
| 无人举手 | 问题标识 |
| 状态变化 | 行为类型、持续时长 |
| 纪律事件 | 级别、涉及学生、持续时长 |
| 教师反馈 | 类型(表扬 / 追问 / 评价)、目标学生 |

**评测所需的一切都可以从这张表推出**,不需要回看录像。

### 8.3 课堂脚本

情景模拟与保底层使用的预编排事件序列,在创建试讲时生成并落库。

| 字段 | 含义 |
|---|---|
| 时刻 | 相对开始的毫秒数 |
| 类型 | 行为 / 提问 / 纪律 / 情景事件 |
| 学生标识 | 涉及学生 |
| 负载 | 具体内容 |

**落库而非前端随机生成** —— 使回放时虚拟学生行为可精确复现,并为评测提供基准真值。

### 8.4 问题池

课前批量生成的学生提问,绑定教学重难点。

| 字段 | 含义 |
|---|---|
| 试讲标识 | 归属 |
| 问题文本 | 学生口中的话 |
| 目标知识点 | 对应哪个重难点 |
| 问题类型 | 基础困惑 / 边界困惑 / 挑战质疑 |
| 适配水平 | 适合哪个水平的学生 |
| 是否已使用 | 避免重复提问 |

### 8.5 教师行为摘要

**运行时的中间结构,不一定落库**,但需明确其形态(见 5.5)。它是学生模型的唯一输入接口。

## 9. 三种模式

三种模式**不是三套代码**,而是同一引擎更换驱动策略。

| 模式 | 驱动策略 |
|---|---|
| 自由试讲 | 概率模型 + 教师行为调制;保底层兜底 |
| 情景模拟 | 脚本 + 强制注入突发事件(学生质疑、纪律失控、设备故障) |
| 结构化面试 | **不在本文件范围**(见 1.3) |

驱动策略需统一为同一接口,使渲染层完全复用。

**自由试讲的可复现性来源**:运行时行为由"教师行为 + 学生参数 + 随机数"共同决定;实际发生的行为**全部落库**,回放与评测一律读库,**绝不重算**。因此:

- 同一次试讲的回放完全一致
- 不同次试讲结果不同(因为教师讲得不同)—— 这是期望的性质
- 单元测试用固定输入得到确定输出

> 学生模型是"把教师行为映射成概率分布的响应函数",不是"时间表放映"。
