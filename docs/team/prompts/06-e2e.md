## 5. 目标与范围

### 5.1 P0 目标

- Playwright 配置：Chromium、baseURL、trace / video / screenshot on failure、4 vCPU / 8 GB demo 环境可运行。
- 测试账号 / fixture：M1 管理员 / 教师 / 学生；M2 课程 / 老师组 / 学生；M3 任务 / 录像 / 回放；M4 评测；M6 训练；M7 评分 / 统计。
- 6 组场景：E2E-01 课程任务闭环、E2E-02 结构化面试、E2E-03 训练、E2E-04 管理员组织、E2E-05 归档与保留、E2E-06 跨校隔离。
- 录制 / 回放仅在 Chromium；fake camera / mic / screen（48k WAV / Playwright flags）用于本地自动化；真实设备手工 smoke 另记。
- 失败输出：场景编号、步骤、trace / 录屏、所属模块 / Owner；不修改业务代码绕过。

### 5.2 不做

- 实现或修复 M1—M7 业务功能（交对应 Owner）。
- 用单元 / mock 代替 E2E 验收；用跳过 / 删除失败场景让流水线变绿。
- 压测 / 性能 NFR 的完整执行（可搭骨架，具体由 QA 后续）。
- 修改 `docs/team/01`、owner 表、模块边界。

### 5.3 必须遵守的契约

- E2E 场景编号 / 步骤以 `docs/design/10` §7 为准；新增场景先改测试设计文档。
- 测试数据必须可重复：固定账号 / 课程 / 任务 / seed；不依赖手工脏数据。
- 录制 / 回放场景需 fake media 或真实设备说明；不得伪造 trace。
- 跨模块失败先归属模块，再交 Owner；不直接改业务代码。
- 模块测试后置不影响 E2E 骨架搭建，但 E2E 通过仍需完整链路可用。

## 6. 执行顺序（可并行）

1. 读文档、列 6 组场景与依赖矩阵。
2. 搭 Playwright 配置 / 页面对象 / fixture / seed 数据。
3. 先接入 M3 已完成的免费课堂 / 面试 / 回放场景。
4. 随 M1 / M2 / M4 / M6 / M7 可用，逐步启用 E2E-01—06。
5. NFR 骨架（性能 / 安全 / 迁移）与 CI 命令。
6. 输出报告 / trace / 缺陷清单；更新 E2E 行与证据。

## 7. 测试门禁

- E2E：`npx playwright test`（Chromium；首次安装浏览器）。
- 失败保留 trace / video / screenshot；报告场景编号与 Owner。
- 不要求单元 / 集成测试全绿才搭 E2E；但 E2E 通过必须基于真实模块链路。
- 不得跳过 / 删除失败场景；已知阻塞写 `test.skip` 时必须注明 issue / Owner / 解除条件。

## 8. 交付物与汇报格式

1. 分支、commit、变更文件；
2. E2E 场景清单与当前通过 / 阻塞状态；
3. 测试数据 / fixture 说明；
4. Playwright 命令与报告 / trace 路径；
5. 缺陷清单（场景、模块、Owner、证据）；
6. 未完成 / 阻塞 / 风险；
7. 是否合并 / 推送（默认等用户选择）。

## 9. 反模式

- 不得改业务代码让 E2E 通过。
- 不得伪造通过 / trace / 报告。
- 不得让 E2E 依赖手工脏数据或不可重复的外部账号。
- 不得把 E2E 做成模块单元测试的重复。
