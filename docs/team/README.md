## 使用顺序

1. **开工前**：读 `01`，确认自己负责的模块和路径；不属于自己的模块，不改。
2. **写代码 / 文档前**：查 `01` 第 3 节的路径表；跨模块先按第 4.2 节提变更请求。
3. **每次提交后**：更新 `02` 中自己模块的 gate 和证据；不修改他人模块的行。
4. **写测试前**：读 `10` 第 2 节的分层与模块最低测试组合；E2E 场景见 `10` 第 7.7 节。
5. **Agent 协作**：Agent 修改非当前使用者模块的文件前，必须提醒并询问是否执行；见 `01` 第 5 节和仓库根 `CLAUDE.md`。

## 维护

- `01` / `02` 是团队契约；Owner 表、模块边界、Gate 权重的变更需全体 owner 确认。
- 只改自己模块的进度行；跨模块修改获批后，由目标 owner 更新。
- 文档中的相对链接必须可访问；提交前跑链接检查。
